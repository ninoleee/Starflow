## 后续约定

- 用户行为变化：更新 README 中对应概述及所属专题，不在“当前状态”重复追加一遍完整说明。
- 实现变化：更新架构或网络契约；测试入口放代码地图，执行结果放主机记录，真实设备结果与主机结果分开。
- 只有独立复现、设计取舍或审查证据值得长期追溯时才新增带日期报告，并放入 `reviews/`；普通修改不用再建一份任务总结。
- 合并或移动文件时同步检查相对链接和标题锚点；不要保留只有重定向说明的空文档来掩盖未更新的仓库引用。
- 不手工整理 `.fvm/`、`.dart_tool/`、`build/`、Pods 或依赖下载缓存中的 Markdown；文档整理不运行发布预设或品牌生成脚本。
