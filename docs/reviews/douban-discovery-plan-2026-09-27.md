# 搜索页豆瓣选片：实施方案与开发计划

日期：2026-09-27。状态：基础功能已实施，设备与外部接口验收未完成。本文保留开发前的阶段计划和拟议契约；当前行为以 [README](../../README.md)、[架构说明](../architecture.md) 和 [开发网络](../development-network.md) 为准。

实施记录（2026-09-27）：已接入 `/search` 双标签、电影／剧集组合筛选与四种排序、显式分页、详情联动、本机偏好、内存缓存及页面活动隔离，并以定向主机测试验证。实际页面使用紧凑换行菜单（手机亦然），未实现独立筛选草稿面板、TV 焦点恢复到指定海报、独立 application controller、专门的选片结构化日志或 Web 端转发；这些仍为以下计划目标，不得据本文宣称已经交付。未运行发布预设，未递增版本。

## 1. 目标与结论

在现有搜索一级入口内增加「豆瓣选片」，完成「按条件找作品 -> 查看详情 -> 匹配或搜索资源 -> 播放／保存」的闭环。保留资源搜索、独立收藏和详情搜索的既有行为，不新增一级导航分支。

推荐方案：Flutter 客户端通过既有 HTTP 客户端访问豆瓣在线推荐列表，服务端完成筛选和排序；客户端负责呈现、分页、状态恢复和有界缓存。第一版不自建数据库、不新增后端、不接入第三方公共豆瓣镜像。

正式实施以 [架构说明](../architecture.md)、[开发网络](../development-network.md)、[代码地图](../code-map.md) 和 [TV 焦点清单](../tv-focus.md) 为现有契约。本文的拟议行为在实际合入时迁入对应现行文档，不提前写成已支持能力。

## 3. 第一版范围

| 范围 | 第一版决策 |
| --- | --- |
| 入口 | 搜索一级页增加「资源搜索／豆瓣选片」双标签；首次默认资源搜索 |
| 类别 | 电影、剧集；动画、纪录片作为类型，不另造第三种媒体 ID |
| 年份 | 全部＋具体四位年份；当前年动态生成，常用年份优先，菜单支持选择更早年份 |
| 国家／地区 | 单选，优先使用接口候选词及经过验证的内置回退词表 |
| 类型 | 单选，候选按电影／剧集区分；维度间为组合条件 |
| 评分 | 不限、6 分以上、7 分以上、8 分以上、9 分以上；内部统一为数值区间 |
| 排序 | 综合、近期热度、首映／首播时间、高分优先；首次默认高分优先 |
| 展示 | 海报网格、片名、年份、豆瓣评分；人数有值时显示，缺失不造值 |
| 翻页 | 各端统一显式上一页／下一页，默认每页 20；不做无限累积海报流 |
| 联动 | 点击海报进入既有详情，保留搜索资源及匹配链路 |
| 记忆 | 本机保存最后手动选择的标签及电影／剧集各自条件；页码、焦点和滚动仅会话保存 |

不在第一版：自定义年份区间、年代语义、多选／排除标签、最低评分人数、按人数排序、演员导演过滤、豆瓣写入想看／看过、批量收藏、榜单全量导出、全库离线、后台定时同步、列表逐项资源预匹配。需要这些能力时单独验证接口或另立数据方案，不能用当前页局部过滤冒充完整筛选。

年份选择器建议支持 1888 至运行时当前年，具体下界在 P0 核对；这是 UI 输入范围，不承诺每年一定有结果。首版不开放未来年份。评分边界若实测不支持包含等于阈值，则上线前调整文案与参数，不让「以上」与结果语义冲突。

## 4. 页面与导航契约

### 4.1 搜索入口隔离

拟增加 SearchHubPage，仅挂载 /search。资源标签内部复用 SearchPage，不将豆瓣筛选逻辑塞入现有大页面。

- /favorites 继续使用 SearchPage(favoritesOnly: true)，不展示双标签，不改变收藏数据格式。
- /detail-search 继续使用带返回按钮的 SearchPage，不展示选片标签。
- /search?q=有效关键词 强制显示资源搜索，并保留原有自动查询及来源恢复顺序；显式 query 优先于本机标签记忆。该路由强制跳转不覆盖用户最后手动选择的标签。
- 切换标签保留各自查询、结果和位置；隐藏页禁止新增请求、验链排队和焦点争抢。用懒创建的保留子树配合 TickerMode、ExcludeFocus 和活动状态，不让 IndexedStack 中两个页面同时认为自己可见。
- 详情覆盖选片页后保留稳定结果，返回时不自动重新请求。App 后台与路由隐藏都停止新增工作，已发请求通过代次隔离，不承诺网络传输即时取消。
- 两个子页不重复绘制整页工具栏／页面标题；如需 SearchPage 增加嵌入布局参数，默认值保持两个旧入口不变，并补旧入口回归。

### 4.2 页面结构

```text
搜索                            [资源搜索 | 豆瓣选片]
[电影 | 剧集]    排序菜单                 刷新图标
年份菜单    地区菜单    类型菜单    评分菜单    重置图标
当前条件摘要                    第 N 页／本页 N 部
海报网格：图片、评分角标、片名、年份及可选人数
上一页图标                  下一页图标
```

- 小屏将条件收进筛选面板：草稿独立于已应用条件，点击「应用」只发一次请求；取消和返回丢弃草稿。
- 桌面和 TV 使用紧凑分组筛选行，选项过多进入菜单／弹窗，不铺满几十个年份和地区。确定选择后提交，焦点移动不请求。
- 宽屏条件连续变化合并约 250ms；应用按钮直接提交最终草稿。选择相同条件不请求。
- 重置仅恢复当前类别的条件与默认排序并回到第一页，不重置资源搜索、豆瓣设置或收藏；重置是明确的用户提交。
- 复用当前主题、六档字号、按钮及 MediaPosterTile。图标提供 tooltip 和语义标签；不新增功能说明段落、营销区或多层卡片。
- 网格按可用宽度和文字缩放决定列数，不随视口宽度缩放字号；海报固定比例，标题保留两行空间并允许省略，辅助行无数据时保持布局稳定。

### 4.3 TV 和分页

- 遥控器顺序为标签、类别、筛选／排序、海报、分页，沿用默认方向寻焦和公共遥控输入，不重建全局焦点坐标算法。
- 弹窗关闭恢复触发按钮；详情返回优先恢复「条件键＋页码＋豆瓣 ID」，目标不再存在时恢复首个可见结果，再回退筛选栏。
- 切换条件后焦点保留在筛选控件，不因响应到达跳到海报。显式翻页成功后滚到网格起点并聚焦首个结果；失败时保留原页和分页按钮焦点。
- 顶部和底部可各有分页入口；忙碌期间可保焦但不可重复执行。左右键不能被擅自改成翻页，返回键沿用壳层语义；筛选弹窗先关闭。
- 懒构建网格，不把不断增长的 shrinkWrap 网格嵌入滚动页。第一版一页至多 20 张海报；豆瓣图片现有跳过缩采样策略保持不动，实际内存风险在真机验收。

## 5. 豆瓣启用与账号

沿用 DoubanAccountConfig.enabled 作为本功能启用门槛，与「启用豆瓣模块」的用户意图保持一致，不增加配置 schema 字段。

- 未启用时仍可看见选片标签，但不请求接口、不加载海报；显示简洁的关闭状态及进入豆瓣设置的命令。
- 启用后，公共选片固定匿名读取；不要求 User ID 或 Cookie，不自动附带现有账号 Cookie。个性化推荐、兴趣和现有详情请求的认证方式保持原状。
- 触发登录／验证要求时提示访问受限并停止，不尝试破解验证码、轮换身份或向公共代理发送 Cookie。
- 关闭功能时使请求代次失效，清除选片内存数据，停止图片子树加载；过滤偏好可以保留。重新启用并且页面活动时才重新加载。
- 因匿名模式固定，公共结果缓存不按账号共享私人数据；日后若加入登录模式，必须引入独立认证作用域及退出清理规则。

## 7. 请求与响应契约

### 7.1 请求模型

DoubanBrowseQuery：mediaType、year 可空、region 可空、genre 可空、minRating、maxRating、sort。规范化后可比较、可序列化，拒绝未知媒体类型／排序、非法年份及反向评分区间。所有查询值使用 Uri 的 queryParameters 编码，不拼接未转义 JSON。

固定端点仅允许 m.douban.com 的 /rexxar/api/v2/movie/recommend 或 /tv/recommend，不接受用户输入任意接口 URL。

| 参数 | 构造约定 |
| --- | --- |
| refresh | 0；手动刷新绕过本地缓存，不随意改变未验证参数 |
| start / count | 首版 count=20；start 为上游原始偏移，不是有效海报数 |
| selected_categories | JSON 对象，以已选类型、地区构造；「全部」不作为标签值发送 |
| tags | 已选类型、地区、具体年份，去空、去重、固定顺序 |
| uncollect | false，匿名模式不开放「未看过」 |
| score_range | 数值区间，如 0,10 或 8,10 |
| sort | T/U/R/S；P0 确认 T 显式传值与省略是否一致，兼容策略固定后测试 |

Referer 分别对应豆瓣选电影／选剧集，UA 复用既有客户端，不随机更换身份。公共选片不发送 Cookie，不向图片主机传播 API 请求头或认证信息。

### 7.2 响应模型

DoubanBrowsePage 至少保存 items、rawItemCount、requestStart、nextStart、total 可空、capabilities、fetchedAt。items 仅接受可识别的电影／剧集和非空 ID、标题；未知卡片忽略并计数，保留上游顺序。

- `rating.value` 保存有效 0～10 数值，0／缺失按未评分展示；`rating.count` 保存非负人数，缺失不以 0 人评价误导。
- 列表海报使用 pic.normal 优先，pic.large 为候选回退，缺图占位但仍可进详情。
- recommend_categories 与 sorts 可以提供候选，不盲从其 checked 状态覆盖用户已提交条件。本次 S 请求中 checked 仍指向 T，选中态必须由本机 Query 决定。
- HTTP 200 但为 HTML、错误对象或缺少合法 items 数组属于协议失败；合法空 items 才是无结果。单条坏数据不能拖垮整页，全页原始条目均坏则显示异常而非无结果。
- 返回 total 只视为上游报告值，不承诺豆瓣全库总数。第一版主界面展示页码和本页数量，不据 total 提供跳到任意末页。

### 7.3 分页一致性

- 优先采用 P0 验证的响应游标；无明确游标时使用 requestStart + rawItemCount，不以过滤／去重后的数量推进。
- 在上游原始空页、已验证的结束标记或可信 total 边界停止；不能仅凭本页可展示数量不足 20 就判断结束。
- 稳定 ID 为 mediaType＋doubanId；当前查询会话内保留已访问页 ID 归属，去重只影响展示，不影响上游偏移。上一页缓存原样恢复。
- 全页重复或非作品卡片时不自动连续抓取后续页；保留已有结果，显示可手动继续或刷新状态。连续两页无新增作品则终止当前翻页链，提示上游分页异常。
- 每个查询会话最多访问 50 页、保存最多 1000 个轻量 ID 归属。到达本地上限明确提示缩小筛选，不写成「豆瓣没有更多」。该上限是产品保护值，不是豆瓣官方限制。
- 手动刷新使当前查询的旧分页快照及 ID 归属失效，从第一页重新开始，避免新首屏与旧后续页混合。豆瓣榜单本身可能变动，不承诺跨时刻的快照一致性。

## 8. 状态、并发和异常

控制器区分 requestedQuery 与 displayedQuery。待获取的条件／页码不能冒充当前显示结果的归属。

| 状态／事件 | 行为 |
| --- | --- |
| disabled | 无网络；设置入口可操作 |
| 首次进入 | 先读本机条件，再且仅当活动时加载一页 |
| 切换条件 | generation 递增，目标回第一页；无同条件缓存则显示加载态，不把旧结果挂在新条件下 |
| 翻页中 | 保留原页并标记正在翻页；成功原子替换，失败不更改当前页码 |
| 同条件刷新 | 保留已有列表，显示忙碌；失败保留列表和非阻断错误 |
| 空结果 | 独立空态及重置入口，不循环补页 |
| 页面失活／后台 | 失效等待任务与迟到提交；稳定列表保留，回前台不自动刷新稳定结果 |
| 首次加载被打断 | 回到活动页后允许补一次尚未完成的初始加载；失败不形成自动重试循环 |

选片模块最多一个实际在途请求，另存一个「最新意图」；快速连续选择替换待发意图，旧请求结束后只发送最终条件。与首页共用 guard，但不关闭共享 http.Client 来取消单页任务。缓存写入、页面提交及 finally 清理都核对请求身份和清理 epoch。

继续使用已有 6 秒豆瓣请求超时、连续 3 次临时故障后熔断 2 分钟，以及明确用户重试时的一次半开探测。解析层错误不能假设已有 HTTP guard 会计入熔断：HTML 验证页／登录要求设选片会话级阻断，直到用户明确重试或重新进入；不为此擅自改所有豆瓣请求的 guard 行为。

错误区分离线／超时、HTTP 限流、访问受限、熔断中、协议变化和合法无结果。429 的合法 Retry-After 限制重试时机，不启定时自动请求；按钮到期后由下一次用户交互重新判断。403／验证不自动切接口、切 IP 或用账号再试。异常正文只用于内存判断，不原样写入日志／UI。

## 9. 缓存与持久化

第一版仅对列表使用内存缓存，图片继续由公共图片缓存管理；不新增落盘影片库。以下为拟定保护值，不是性能实测结论。

| 项目 | 决策 |
| --- | --- |
| 键 | 协议版本＋规范化 Query＋start＋count；匿名作用域固定 |
| 新鲜期 | 10 分钟；相同请求合并为一个 future |
| 容量 | 全模块最多 12 页且精简数据估算不超过 2 MiB，先到上限即 LRU 淘汰；不缓存评论、用户信息和 alg_json |
| 过期结果 | 活动会话已有页保留；再次选中同条件时可先展示缓存并发起一次刷新，失败标记缓存状态，无后台轮询 |
| 手动刷新 | 跳过缓存并从第一页重建当前条件分页 |
| 释放 | 功能关闭、清理搜索偏好／缓存、低内存及模块销毁时清理可回收缓存；旧请求不得回填已清空代次 |
| 持久化 | search.browseMode、search.doubanBrowseFilters.v1；只存模式和电影／剧集各自条件，不存结果、Cookie 或焦点节点 |

本机偏好使用既有 PreferencesStore，与收藏同步文档和 AppSettings 导出分离，不触发 WebDAV 收藏同步。损坏／未知版本条件回退默认，写失败不阻止浏览但提供轻量提示及脱敏诊断；串行写入避免早一次操作覆盖后一次。

新增偏好纳入现有搜索偏好统计和专用清理路径，更新该项描述。接线前核对现有 clear() 会处理收藏的历史语义：本功能的「重置条件」及「清理浏览记忆」不得调用会清除收藏的总 clear()，不得顺带修正历史清理行为。

## 10. 平台、性能与隐私

- Android 手机、Android TV、iOS 和 macOS 使用既有原生 HTTP 路径，无需新增服务端。桌面其他平台至少验证共享 Dart 行为，未运行的平台明确列为未验证。
- Web 复用现有网络转发机制；原生成功不证明浏览器 CORS 可用。P0 记录配置依赖；若生产 Web 没有获准转发路径，保留清晰的不可用状态，不临时接入公共代理或宣称 Web 全支持。
- 列表阶段不请求每项详情、WMDB、TMDB 或网盘匹配；网络预算为一次条件提交至多一次列表请求，图片请求另计。焦点移动、页面重建、返回详情不触发列表重抓。
- 不预取下一页，不在 App 启动或隐藏标签初始化时请求豆瓣。海报复用既有 TV 并发门，分页组件销毁不清空全局 ImageCache。
- 新增 douban.browse 结构化日志：事件类型、媒体类型、页偏移、耗时、HTTP 状态、错误分类、缓存命中、原始／有效／去重条目数量和代次。不得记录完整 URL、筛选 tags、标题、Cookie、评论、原始响应或用户信息。
- 性能目标：一次视图内最多 20 张海报；持续分页后缓存保持有界；缓存命中无 HTTP；返回详情结果和焦点稳定。首屏网络耗时及内存数值必须测量后记录，不提前给出保证。
