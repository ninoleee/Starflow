# 直播电视

实现核对：2026-09-20，按当前工作区 `lib/features/live_tv/` 与 Android `LiveTvView.kt` 读取核实。本文说明已实现边界，不代表真实直播源或设备已验收。[协作契约](live-tv-contract.md) 顶部记录本次修复接口；其后保留的早期草稿不作为现行功能或测试通过清单。

## 使用入口

- 新配置主菜单包含直播；已有配置保留原菜单，可在“设置 -> 界面 -> 菜单栏按钮”勾选直播。设置的“内容与来源”也提供直播电视与直播订阅入口。
- 添加订阅填写名称、HTTP/HTTPS M3U/TXT 地址和可选 XMLTV/XMLTV.gz 地址；或导入不超过 8 MiB 的本地文件。手机、电脑端使用文件选择器；TV 点击“手机导入 M3U / TXT 文件”显示与配置传输/日志导出一致的二维码地址组件，手机在同一可信局域网扫码后上传 `.m3u / .m3u8 / .txt` 文件。收到后回到电视编辑页显示文件名、清空订阅 URL，点击“保存”才写入当前来源，不覆盖应用配置或其他来源。M3U 的 `x-tvg-url / url-tvg` 可补充空 EPG 地址。
- 启用开关决定来源频道是否可见；更新间隔在直播页激活时检查，默认 24 小时，可选 6/12/24/48/168 小时，不是后台轮询。同一来源同版本刷新合并，自动检查有五分钟尝试冷却，手动更新可重试失败来源。保存远程来源后显式刷新，失败仍保留配置；停用不删除频道/收藏，仓库也跳过已停用来源的刷新。
- 频道支持搜索、分组、收藏、上次成功播放频道，以及整理模式里的隐藏、上下移动、名称/分组/台标/EPG ID 映射。频道身份不包含临时 URL；源内唯一的显式 `tvg-id` 使用 v2 身份，不因名称/分组改变而丢失偏好。重复 `tvg-id` 保留名称/分组消歧，不按重名跨来源合并。旧库只有一对一匹配时才迁移 ID、偏好和上次播放标记；无明确身份的 TXT 或共享 EPG ID 歧义频道仍不能保证更名后自动关联。
- 单份频道表最多 10000 个频道、单频道 64 条线路、全表 50000 条线路；超限拒绝，不截断替换旧缓存。已有手动排序后，新发现频道追加到后面。
- 仅提供文件导入，没有独立粘贴整份频道文本或订阅请求头编辑器。扫码会话单次接收，关闭弹窗、进入后台或十分钟到期会关闭服务；无效文件可在同一会话重试。上传只进入编辑草稿，取消/返回不入库。来源名称和地址编辑复用设置输入组件；TV 不再调用系统文件选择器，跨设备扫码与系统输入法仍需设备验证。

## 独立存储

- IO 平台在应用支持目录 `starflow-db/live_tv.db` 保存 Sembast 数据库；Web 使用名为 `starflow-live-tv` 的浏览器数据库，受当前站点与浏览器数据生命周期约束。
- `sources / channels / preferences / epg / meta` 分别保存订阅、频道、多线路与媒体 headers、收藏/隐藏/排序/映射/偏好线路、节目单、上次播放频道及直播内核选择。直播内核默认 MPV，不跟随点播默认内核；菜单可见性仍属于 `AppSettings`。
- 直播数据库不包含在应用配置 JSON、文件/Web/TV 配置传输、WebDAV 手动配置备份或影视收藏自动同步中。专属入口为“直播订阅 -> 直播备份与恢复”，JSON `format=starflow-live-tv, version=1`，上限 32 MiB。包含来源和频道原 ID、媒体 headers、全部整理偏好、历史频道归属、节目单/台标缓存、上次播放标记和内核偏好；不含运行中会话、点播或应用配置。文件未加密，订阅/媒体地址和请求头可能含凭据。
- 恢复先验证版本、关联关系、地址和数据，再二次确认并单事务提交。合并只添加新 sourceId，保留同 ID 现有来源的完整数据和全局偏好，跨来源记录 ID 冲突拒绝；替换删除并恢复全部直播 store。导入使已开始的刷新代次失效，迟到响应不能覆盖恢复结果。失败不部分导入，未知版本拒绝。普通播放列表导入仍是草稿流程，不等于完整恢复。
- IO 平台支持输入完整 JSON 文件路径，默认导出到应用文档目录 `exports/live-tv/`，已有同名文件拒绝覆盖；非 TV 可选本地备份文件，Web 可选文件恢复并下载 JSON。TV 备份路径需为应用有权限访问的路径，跨设备备份搬运/Android 分区存储与 iOS 沙盒仍需设备验收。既有扫码入口仍仅传 M3U/TXT，不增加配置或备份上传/下载端点。
- 停用来源保留本地数据。上游频道消失后保留整理偏好，`channelOwners` 记录所属来源；删除来源会清除其当前/已登记历史频道偏好、所属记录、节目单、`epgLogos` 缓存和相关上次播放标记，不等于全库压缩。数据库内可能含带凭据的地址和媒体 headers，未配置数据库加密，应按敏感应用数据保管。

## 播放行为

- 原生平台默认 MPV，Android 可选择 Exo，并可在播放器切换内核。直播 Exo 为独立 TextureView/Media3 容器，Flutter 负责频道叠层和遥控器，不跳点播 Activity。
- 播放画布持有主焦点时，上下/频道键在全部可见频道中循环换台，确认键打开频道列表，左键打开分组/频道，右键打开节目单，菜单键进入控制按钮。叠层内方向键移动焦点，确认频道才换台；分组筛选仅限制叠层列表，不改变画布上下换台范围。返回先关节目详情等弹窗、再离开频道/节目单叠层或工具栏模式并恢复画布，随后退出。详细焦点边界见 [TV 焦点清单](tv-focus.md#直播焦点边界2026-09-20)。
- MPV/Exo 共用换台代次、180ms 连续输入合并、15s 开流等待计时和 18s 无进展检测。生产适配器实现 `CancellableLiveEngine.cancelOpen`：超时、换台、后台与退出可在 open 队列外请求卸载，但后续 stop/dispose/open 必须等待卸载确认，不以普通 `Future.timeout` 授权并发打开。MPV 使用可中断的单条原生 loadfile 与非同步锁 stop；Exo 按 generation 释放播放器后应答。保留无取消能力的测试/外部适配器时仍等待 open 自行结束。18s 只由 progress/frame 续期，ready/buffering 不续期；这些都不是像素首帧或整场会话总上限。自动重连最多三次，按 2/4/6s 退避并轮换备用线路；全部失败提供显式重试。短暂就绪/播放不会续增预算；手动选台、选线路或重试重置预算，后台恢复保留原预算，切换内核建立新控制器。
- 原生卸载/初始化本身不响应时不能把超时当作资源已释放。当前代码保证确认前不重开，并未提供强杀进程式的卸载期限；因此 L01 的全引擎故障硬上限仍需进一步工程化和设备验证，不能把可取消 fake 的主机测试当作驱动/原生死锁也可在固定期限内清理的证明。
- Exo 上报 `paused:<playWhenReadyChangeReason>`、`suppressed:<suppressionReason>` 和 `resumed`。耳机断开/永久焦点丢失暂停或临时焦点抑制期间停止看门狗和重连；无进度不再被当成断流。焦点允许恢复时重启检测，明确暂停提供“继续播放”，暂停意图不会被一次后台/前台切换覆盖。
- 静音由页面会话保存，新 controller 在开流前配置静音：Exo open 参数携带初始音量，MPV 在 loadfile 前写音量。音轨弹窗查询/提交检查 controller generation；原生音轨 ID 同时带 native session token，重连后旧弹窗不能误选新会话同序号音轨。
- 只保留一个活动播放器，不预开第二频道。进入后台停止，回前台重新打开当前频道；退出会话释放解码和网络资源。没有时移暂停/快进、节目回看或录制，不写入影视观看历史。
- 记忆频道和线路以当前代次首次 `progress` 或 `frame` 为准，单独 `ready` 不写入；这是内核信号意义上的成功，不保证同时已有可见画面和声音。

### MPV 与 Exo 差异

| 边界 | MPV / media_kit | Android 直播 Exo |
| --- | --- | --- |
| 承载 | 独立 `Player + VideoController`，Web 实际为浏览器后端 | `AndroidView -> LiveTvView`，非焦点 `TextureView`；不是点播 Activity |
| 缓冲 | 原生 MPV 32 MiB 前向、零回看、12s 缓存目标，network-timeout 10s | Media3 3-12s、起播 1s/重缓冲 2s、32 MiB 目标，直播目标偏移 3s |
| 代理 | 构造直播 engine 时读取应用代理快照并在开流设置 | 独立 `LiveTvHttpDataSource / LiveTvHttpTransport`，连接/读取各 10s，不自动继承 Dart 代理 |
| 就绪证据 | `ready` 来自非 buffering，`progress` 来自播放位置前进；无专用像素首帧回调 | `ready`、`onRenderedFirstFrame` 的 `frame`、约每秒位置前进的 `progress` |
| 音轨/画面 | 可选当前 engine 音轨、静音；默认视频适配 | 可选 Media3 当前音轨、静音；TextureView 按视频宽高比适配，处理音频焦点及耳机断开 |
| 点播能力隔离 | 不接入点播字幕准备、续播、跳过、选集或高级 MPV 设置流程 | 标准 Media3 renderer/source factory，不装配点播自定义 FFmpeg renderer、TS/LPCM/PGS 扩展、双字幕和音频输出策略 |

这些缓冲值不是进程内存硬上限，3s 目标偏移不保证实际直播延迟，也不能保证相同首帧速度。标准 HTTP/HTTPS HLS、HTTP-TS 是目标场景，实际编码支持取决于依赖、设备与源；不能用点播音频回归证明直播 Exo 的格式支持。

音轨、静音、线路和 Android 内核切换可通过控制层操作。当前没有播放器内收藏按钮（在频道页操作）、画面比例选择、音轨偏好持久化、暂停/时移/seek、节目回看、录制、字幕选择/外挂字幕、PiP 或系统播放器/AVPlayer 专属直播入口。原生通道保留 `pause / play` 分支不等于 Flutter 提供暂停或时移功能。DRM、UDP 组播以及 Emby/飞牛直播库对接均未接入。

## 节目单与缓存

- `epgUrl` 仅保存用户覆盖，`discoveredEpgUrl` 保存最近一次播放列表声明，`effectiveEpgUrl` 按用户覆盖优先选择。订阅声明 A -> B 或撤销声明会更新发现值。历史库的 `epgUrl` 没有来源标记，保守保留为覆盖，用户清空编辑框后恢复自动发现。仅远端 playlist URL 参与频道 TTL，仅有效远端 EPG URL 参与 EPG TTL；本地导入时间不拖累刚刷新的节目单。

- 支持 XMLTV 时区偏移并转换到本机时间，缺少时区按 XMLTV UTC 语义处理；无效时间/结束早于开始的节目忽略。节目保留过去一天至未来七天，当前区间左闭右开。
- EPG ID 默认取 M3U `tvg-id`、`tvg-name`、显示名称；TXT 默认取频道名。手动映射可修正不一致。台标优先频道表，其次 XMLTV channel icon，可手动覆盖 URL；不把媒体 headers 发送给图片/EPG。
- 频道页批量读取 now/next，但行内目前只显示当前节目；活动页每分钟使本地查询失效，不下载新节目单。播放页每分钟刷新显示时间，展示当前/接下来及可滚动多日节目，单频道查询最多 1000 条；确认节目只打开简介，不换台或回看。无节目单不影响播放。
- 频道和节目单分别事务更新。频道成功、节目单失败时保留新频道、旧节目单与已缓存 EPG 台标，UI 提示更新未完成。刷新按来源 generation 合并，删除/禁用/同 ID 重建后旧回复失效，不覆盖新配置；偏好持有来源归属，删除来源可清理其历史频道偏好。
- XMLTV 下载 8 MiB、解压 32 MiB、保留节目最多 100000 条；拒绝 DTD/实体声明，Gzip 检查 CRC 和长度。解析及保留窗口过滤在后台 isolate（Web 除外）；不是定时磁盘清扫，过期记录在下一次成功替换该来源 EPG 时清除，查询另排除过旧条目。
- 台标采用手动覆盖、频道表、XMLTV 补缺顺序，独立四路下载池、每张 15s/2 MiB，失败显示占位图；不是影视图片磁盘缓存，也不继承媒体请求头。订阅、节目单、图片和媒体请求的完整边界见 [开发网络](development-network.md#直播订阅与媒体流2026-09-20)。
