## 使用入口

- 首页标题栏仅保留标题及设置入口所需的返回按钮；检测、直播订阅、整理依次紧随“收藏”右侧，窄屏时随收藏整体换行。保留订阅按钮 TV 首焦点、检测开始／停止和整理切换行为，Web 不显示检测按钮。
- MPV 直播网络参数由 `application/live_mpv_options.dart` 定义：默认 `Starflow` User-Agent，大小写不敏感地保留订阅显式值；原生 `user-agent` 与媒体 headers 同步。HLS 使用 FFmpeg 6 支持的 `seg_max_retry=1 / http_persistent=0`，协议仅 `http,https,tcp,tls,crypto`，不设置 `allowed_extensions=ALL` 或新版才有的 `extension_picky`。FFmpeg 6 本已允许 HTTP 分片使用非媒体后缀；此前外部新版 FFmpeg 的扩展名拒绝不是已确认的应用根因。Exo 原有默认标识及跨源剥离请求头规则不变。
- 播放故障诊断：`live.playback` 记录播放页请求、每次内核打开和失败后的重试决策，包含频道 ID、线路索引/数量、内核、次数及固定原因类别，不输出媒体地址、请求头或原始异常内容。最终失败页区分启动异常、打开超时、进度超时、内核错误、流结束。Android Exo 通过 `LiveTvPlaybackError` 从有界异常链提取 `errorCategory / nativeErrorCode / httpStatus`，经当前 generation 的通道事件或开流异常传到控制器；失败提示进一步区分 HTTP、DNS、超时、TLS、连接、容器、解码、音频等。Flutter 再次白名单过滤，清理原生实例后保留本次摘要，重新选台/重试清空；旧代次不覆盖新频道。MPV 和旧版原生事件缺少详情时仍显示通用类别，不猜测 HTTP 状态。
- 2026-09-20 用户日志为修复前证据：16:06 导出没有播放阶段记录；17:31 导出中 5 个频道合计 12 次 Exo `engineError`，均无底层详情，另有两个订阅刷新失败。其他频道有首帧记录，只能确认部分频道失败，无法从该日志判定死链、网络或解码根因，也不能把约 3 秒报错直接认定为超时。新增诊断不等于故障频道已恢复，需要故障地址或更新后真机日志复核。
- 订阅刷新失败在 `live.refresh` 中保留 `stage=playlist/epg`、固定原因类别和可用的 HTTP 状态，HTTP 提示标明失败阶段。下载超时、正文超限、格式错误不再全部丢成无原因记录；不输出 URL、响应正文或原始异常。节目单失败不否定本轮已保存的频道列表。

- 当前主菜单包含直播，并可在“设置 -> 界面 -> 菜单栏按钮”调整可见项。设置的“内容与来源”也提供直播电视与直播订阅入口。

- 添加订阅填写名称、HTTP/HTTPS M3U/TXT 地址和可选 XMLTV/XMLTV.gz 地址；或导入不超过 8 MiB 的本地文件。手机、电脑端使用文件选择器；TV 点击“手机导入 M3U / TXT 文件”显示与配置传输/日志导出一致的二维码地址组件，手机在同一可信局域网扫码后上传 `.m3u / .m3u8 / .txt` 文件。收到后回到电视编辑页显示文件名、清空订阅 URL，点击“保存”才写入当前来源，不覆盖应用配置或其他来源。M3U 的 `x-tvg-url / url-tvg` 可补充空 EPG 地址。
- 启用开关直接位于订阅列表每项名称旁，切换即保存并决定来源频道是否可见，支持点击及 TV 遥控器确认；保存期间防止重复切换，失败提示重试且不改变已保存状态。添加／编辑页不再提供开关，新订阅默认启用，编辑保留原状态。停用不删除频道、收藏或节目单，列表禁用该来源的手动更新按钮；重新启用立即恢复缓存频道，开关本身不发起网络更新。更新间隔在直播页激活时检查，默认 24 小时，可选 6/12/24/48/168 小时，不是后台轮询。同一来源同版本刷新合并，自动检查有五分钟尝试冷却，手动更新可重试失败来源。保存远程来源后显式刷新，失败仍保留配置；仓库跳过已停用来源的刷新。

- 检测由首页持有，最多两路并发。新增／线路变化频道连续可见 200ms 后才准入，TV 当前焦点优先排队，不抢占在途请求；短暂划过不发请求。离屏、离页、后台、停止和销毁立即取消。成功缓存 5 分钟，连续失败按 45／90／180／300 秒退避并封顶，成功、线路或网络变化重置失败计数。仅一个定时器处理可见项准入和最近到期，停留同屏自动刷新，离页／停止取消定时器；离屏结果只缓存，不安排刷新。刷新保留旧结果和时间并显示刷新图标，提示／无障碍标签标记“刷新中”。收藏／名称／台标／排序保留匹配线路，URL／headers／首选线路变化仅替换对应任务；隐藏、删除和停用取消对应工作。
- 每线路请求期限仍为 6 秒；Range 只提示 1 KiB，首个非空块后取消读取并关闭独立客户端，不缓存或解码正文，实际流量可超过 1 KiB。旧请求清理完成前仍占并发名额，迟到结果不回填；离页／后台／销毁／手动停止结束会话，开播前等待客户端关闭和响应流清理。清理阶段单独计时，1 秒未完成写 `live.probe` 本地告警，完成／失败记录耗时与取消标记，不记录 URL、headers 或原始异常；不通过超时伪造释放，底层清理永久挂起时不能承诺开播等待有硬上限。结果和进度继续局部刷新。
- `connectivity_plus` 在首页存活期间保留被动系统连接类型订阅，不主动探测互联网；离页后仅使缓存失效，不发检测请求。事件或代理变化清缓存、取消旧代请求，在线时对可见项等待 200ms，离线不准入；不重启手动暂停。正常路由返回复用有效缓存，后台恢复或监听异常后返回保守失效缓存。页面销毁解除系统、代理和生命周期监听。Wi-Fi／蜂窝／以太网／VPN 类型通知不等于互联网可达性，也不能保证同类型 Wi-Fi 热切换一定产生事件。
- 这只是 HTTP 首包连通性：毫秒值含连接、TLS、重定向和首包等待，不是下载速度、播放器首帧或可播证明。HLS 只测入口，不验证变体、分片、密钥、编码或 DRM；不将收到响应标成“可播放”。无效 HTTP 地址、TLS 降级或过多跳转拒绝，HTML／JSON 类型响应不当作媒体。沿用应用 Dart 代理与线路媒体 headers，可能与 Exo 实际网络路径不同；Web 因 CORS／浏览器传输边界不提供检测。网络和凭据细节见 [开发网络](development-network.md#直播订阅与媒体流2026-09-20)。
- TV 的名称、M3U / TXT 订阅地址及 XMLTV 节目单地址统一使用文本输入弹窗，二维码入口位于弹出的输入框右侧。手机连接同一可信局域网，扫码后粘贴文本并发送，只回填弹窗；弹窗“保存”后才更新来源草稿，取消保留原值。确认非空订阅 URL 会清除文件导入草稿，保留名称及 EPG；来源页“保存”才持久化并更新订阅，沿用 HTTP/HTTPS 与 userInfo 校验。文本最多 64 KiB，不读取手机剪贴板、不在手机端请求订阅内容。
- 不提供独立粘贴整份频道文本或订阅请求头编辑器。文件与地址扫码会话均单次接收，关闭弹窗、进入后台或十分钟到期会关闭服务；无效输入可在同一会话重试。上传只进入编辑草稿，取消/返回不入库。来源名称和地址编辑复用设置输入组件；TV 不再调用系统文件选择器，跨设备扫码与系统输入法仍需设备验证。

## 独立存储

- IO 平台在应用支持目录 `starflow-db/live_tv.v2.db` 保存 Sembast 数据库；Web 使用名为 `starflow-live-tv-v2` 的浏览器数据库，受当前站点与浏览器数据生命周期约束。
- `sources / channels / preferences / epg / meta` 分别保存订阅、频道、多线路与媒体 headers、收藏/隐藏/排序/映射/偏好线路、节目单、上次播放频道及直播内核选择。直播内核默认 MPV，不跟随点播默认内核；菜单可见性仍属于 `AppSettings`。
- 直播数据库不包含在应用配置 JSON、文件/Web/TV 配置传输、WebDAV 手动配置备份或影视收藏自动同步中。专属入口为“直播订阅 -> 直播备份与恢复”，JSON `format=starflow-live-tv, version=1`，上限 32 MiB。包含来源和频道原 ID、媒体 headers、全部整理偏好、历史频道归属、节目单/台标缓存、上次播放标记和内核偏好；不含运行中会话、点播或应用配置。文件未加密，订阅/媒体地址和请求头可能含凭据。
- 恢复先验证版本、关联关系、地址和数据，再二次确认并单事务提交。合并只添加新 sourceId，保留同 ID 现有来源的完整数据和全局偏好，跨来源记录 ID 冲突拒绝；替换删除并恢复全部直播 store。导入使已开始的刷新代次失效，迟到响应不能覆盖恢复结果。失败不部分导入，未知版本拒绝。普通播放列表导入仍是草稿流程，不等于完整恢复。
- TV 不再要求输入备份路径或调用系统文件选择器：“手机备份”用共享二维码提供单次 JSON 下载，“手机恢复”接收手机上传的直播备份 JSON（上限 32 MiB）。手机与电视需在同一可信局域网；上传先校验格式与版本，电视再次确认所选合并/替换方式才写库，取消不改变现有数据。关闭、后台或十分钟过期关闭端口；文件未加密，下载发送完成后仍需在手机确认文件已保存。
- 非 TV 的 IO 平台支持输入完整 JSON 文件路径，默认导出到应用文档目录 `exports/live-tv/`，已有同名文件拒绝覆盖，也可选本地备份恢复；Web 可选文件恢复并下载 JSON。扫码服务分别隔离频道文件、订阅地址、备份上传和备份下载模式，不接收普通应用配置，不增加云端同步。跨设备下载/上传与手机文件管理仍需设备验收。
- 停用来源保留本地数据。上游频道消失后保留整理偏好，`channelOwners` 记录所属来源；删除来源会清除其当前/已登记历史频道偏好、所属记录、节目单、`epgLogos` 缓存和相关上次播放标记，不等于全库压缩。数据库内可能含带凭据的地址和媒体 headers，未配置数据库加密，应按敏感应用数据保管。

### MPV 与 Exo 差异

| 边界 | MPV / media_kit | Android 直播 Exo |
| --- | --- | --- |
| 承载 | 独立 `Player + VideoController`，Web 实际为浏览器后端 | `AndroidView -> LiveTvView`，非焦点 `TextureView`；不是点播 Activity |
| 缓冲 | 原生 MPV 32 MiB 前向、零回看、12s 缓存目标，network-timeout 10s | Media3 3-12s、起播 1s/重缓冲 2s、32 MiB 目标，直播偏移采用 Media3／清单默认值 |
| 代理 | 构造直播 engine 时读取应用代理快照并在开流设置 | 独立 `LiveTvHttpDataSource / LiveTvHttpTransport`，连接/读取各 10s，不自动继承 Dart 代理 |
| 就绪证据 | `ready` 来自非 buffering，`progress` 来自播放位置前进；无专用像素首帧回调 | `ready`、`onRenderedFirstFrame` 的 `frame`、约每秒位置前进的 `progress` |
| 音轨/画面 | 可选当前 engine 音轨；默认视频适配 | 可选 Media3 当前音轨；TextureView 按视频宽高比适配，处理音频焦点及耳机断开 |
| 点播能力隔离 | 不接入点播字幕准备、续播、跳过、选集或高级 MPV 设置流程 | 标准 Media3 renderer/source factory，启用 FFmpeg 音频扩展和 decoder fallback，不装配点播 TS/LPCM/PGS 扩展、双字幕和自定义音频输出策略 |

这些缓冲值不是进程内存硬上限，默认偏移不保证实际直播延迟，也不能保证相同首帧速度。标准 HTTP/HTTPS HLS、HTTP-TS 是目标场景，实际编码支持取决于依赖、设备与源；不能用点播音频回归证明直播 Exo 的格式支持。

音轨、线路和 Android 内核切换可通过控制层操作。当前没有播放器内收藏按钮（在频道页操作）、画面比例选择、音轨偏好持久化、暂停/时移/seek、节目回看、录制、字幕选择/外挂字幕、PiP 或系统播放器/AVPlayer 专属直播入口。原生通道保留 `pause / play` 分支不等于 Flutter 提供暂停或时移功能。DRM、UDP 组播以及 Emby/飞牛直播库对接均未接入。

## 节目单与缓存

- `epgUrl` 仅保存用户覆盖，`discoveredEpgUrl` 保存最近一次播放列表声明，`effectiveEpgUrl` 按用户覆盖优先选择。订阅声明 A -> B 或撤销声明会更新发现值。历史库的 `epgUrl` 没有来源标记，保守保留为覆盖，用户清空编辑框后恢复自动发现。仅远端 playlist URL 参与频道 TTL，仅有效远端 EPG URL 参与 EPG TTL；本地导入时间不拖累刚刷新的节目单。

- 支持 XMLTV 时区偏移并转换到本机时间，缺少时区按 XMLTV UTC 语义处理；无效时间/结束早于开始的节目忽略。节目保留过去一天至未来七天，当前区间左闭右开。
- EPG ID 默认取 M3U `tvg-id`、`tvg-name`、显示名称；TXT 默认取频道名。手动映射可修正不一致。台标优先频道表，其次 XMLTV channel icon，可手动覆盖 URL；不把媒体 headers 发送给图片/EPG。
- 选台首页与播放器频道列表复用 `liveNowNextProvider` 批量读取本地 now/next，按来源 ID + `snapshot.epgId(channel)` 匹配，支持手动映射且不混用同 ID 的其他来源节目。首页显示“正在播出”和保留原有“接下来”行，播放器列表在频道名下方仅显示当前标题；缺失、节目间隙或已过期时显示“暂无节目信息”，不把下一档当成当前节目。首次读取失败无缓存时同样使用占位，刷新失败保留仍在当前时段的缓存。
- 首页重新活动时及活动期间每分钟使本地 now/next 查询失效；播放器只在选台列表打开时订阅批量查询，每次打开、带列表回前台以及前台列表每分钟重读，不逐频道查询或下载 EPG。播放页保留当前频道的独立完整节目单查询，前台每分钟更新当前/接下来及多日节目显示，单频道查询最多 1000 条；确认节目只打开简介，不换台或回看。无节目单不影响播放。
- 频道和节目单分别事务更新。频道成功、节目单失败时保留新频道、旧节目单与已缓存 EPG 台标，UI 提示更新未完成。刷新按来源 generation 合并，删除/禁用/同 ID 重建后旧回复失效，不覆盖新配置；偏好持有来源归属，删除来源可清理其历史频道偏好。
- XMLTV 下载 8 MiB、解压 32 MiB、保留节目最多 100000 条；拒绝 DTD/实体声明，Gzip 检查 CRC 和长度。解析及保留窗口过滤在后台 isolate（Web 除外）；不是定时磁盘清扫，过期记录在下一次成功替换该来源 EPG 时清除，查询另排除过旧条目。
- 台标采用手动覆盖、频道表、XMLTV 补缺顺序，独立四路下载池、每张 15s/2 MiB，失败显示占位图；不是影视图片磁盘缓存，也不继承媒体请求头。订阅、节目单、图片和媒体请求的完整边界见 [开发网络](development-network.md#直播订阅与媒体流2026-09-20)。
- 频道首页台标固定占位为 64×40 逻辑像素，相比原 48×40 增加横向字标空间，高度与右侧 12 逻辑像素间距不变；解码通过 `ResizeImagePolicy.fit` 保持原始宽高比并限制在 192×120 像素内，不放大小图。显示使用 `BoxFit.contain` 完整居中、不拉伸或裁切；不能同时以默认 exact 策略指定解码宽高，否则横向／方形／竖向原图会在绘制前变形。加载中、下载或解码失败及无有效 URL 时保留同尺寸占位图标。此规则不适用于已移除台标的播放器选台菜单。
