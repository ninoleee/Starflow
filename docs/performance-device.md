# 真机性能验证

更新日期：2026-09-20。本文定义设备测量方法与验收场景；没有附带本次新采集的 TV、手机或桌面性能结果。主机 smoke、JVM 和 Swift 策略回归见 [performance.md](performance.md)，不能作为真机通过证据。

## 测量前提

- 记录 commit / 工作区差异、应用版本、构建模式、设备型号、OS / API、ABI、内存、屏幕刷新率及音频输出设备。
- 固定网络、代理、服务端版本和同一媒体样本，记录容器、编码、码率、时长、字幕轨及音轨；远程地址和认证头不得放入公开记录。
- 固定首页模块、来源与分区、两个启动刷新开关、共享并发值、批次延迟、界面开关、播放器与解码 / 输出模式。
- 区分首次安装、冷进程、热进程、冷缓存与暖缓存；同一组至少重复多次并保留失败样本。清理缓存或应用数据前先保存重要配置，不用清数据代替可控的冷启动。
- Flutter UI 用 profile 模式和 DevTools 分析；用户侧结果再用相同配置的 release 复核。debug 运行耗时不用于发布性能结论。
- 用户可安装的 TV APK 必须按 [README 发布预设](../README.md) 生成，保持 API 23、ARM32 / ARM64、版本与文件名规范；性能任务不要绕过发布约束。

## 指标口径

| 指标 | 起止与数据来源 | 不应混淆的内容 |
| --- | --- | --- |
| 启动可交互 | 启动应用至首页可操作，配合录屏、原生启动记录和 `app.bootstrap` | Bootstrap 的 10s 从控制器开始算，不覆盖 `main()` 前段、原生初始化或同步阻塞 |
| 首页 / 详情就绪 | 操作至首批可操作内容，分别标记缓存、图片、元数据补全完成 | 不把后台全部刮削完成算作首屏 |
| Flutter UI 帧 | DevTools FrameTiming 的 build / raster、设备 traces | Flutter UI 帧不等于播放器解码帧 |
| 播放启动 | 分开记录点击、解析结束、开流、可见画面及声音，关联 `playback.startup / playback.performance` | 不混入先前页面等待，也不直接跨内核比较不同埋点 |
| 播放稳定性 | 视频掉帧、缓冲次数 / 时长、音频 underrun、A/V 同步、CPU / 内存 | 网络缓冲不一定是 UI 绘制卡顿 |
| seek / 切集 | 输入到目标位置实际稳定播放；区分地址解析、定位和缓冲 | 控件上显示目标时间不代表已经播放到该处 |
| 索引刷新 | 明确增量 / 重建、来源数、条目数、请求量、耗时、最终记录数 | 本地分组成本与远端响应延迟分开记录 |

应用默认长帧监测阈值为 **250ms**，属于严重长帧告警，不是 60Hz / 120Hz 流畅度达标线。没有 `app.performance` 长帧告警也不能推断没有掉帧，应使用完整帧时间分布。

Exo 的播放性能数据来自 Media3 Analytics / BandwidthMeter；MPV 读取现有 libmpv 属性，不额外发测速请求。iOS `NativePlaybackMetrics.firstFrameAtIso8601` 当前在 `timeControlStatus == .playing` 时标记，实际是进入播放状态的近似信号，不是已确认视频像素上屏；严格首帧比较需另有录屏或显示层证据。

## 通用场景

| 场景 | 操作 | 重点检查 |
| --- | --- | --- |
| 冷启动 | 无缓存、已有缓存各运行；开启 / 关闭自动刷新分别记录 | 超时是否进入首页、是否重复刷新、焦点是否可操作 |
| 首页与后台 | Hero 翻页、上下滚动、切页、返回、进入后台再恢复 | 图片队列、隐藏页面请求、400ms 恢复等待、保留状态 |
| 详情 | 冷 / 暖历史、慢元数据、多来源多版本、换季、错误 / 空系列 | 按钮不被历史读取隐藏、剧集懒构建、返回后季与滚动不重置 |
| 播放 | 本地与远程同编码样本、首次开流、续播、从头播放 | 原视频与声音、后台任务准入、失败分类与有限重试 |
| 下一集 | 自动边界、手动跨季、预解析命中 / 过期 / 授权失效 | 一次准备、旧结果不污染新会话、失败可手动重试 |
| 保存与索引 | 夸克 / 115 转存、名称修正、STRM 触发、增量刷新 | 重复内容不反复写入、取消边界、刷新时前台仍可操作 |
| 生命周期 | 退出播放、立即重开、后台 / 前台、音频中断、网络变化 | 无叠音、旧实例释放、进度保存、迟到请求不更新新页面 |

“取消”通常意味着停止后续准入和忽略旧结果，不保证已经发送的 HTTP 请求立刻中止。比较请求量时应区分未开始、在途和已完成请求。

## Android TV

至少包括一台低内存 API 23 设备、ARM32 与 ARM64 覆盖，以及可观察 HDMI 能力的现代设备；只有模拟器不足以覆盖这些组合。

### 遥控器与选集

- 控制栏隐藏 / 显示、暂停 / 缓冲状态下分别短按及长按左右 2 / 5 / 10 秒，检查 250ms 合并窗口、松手立即提交和 10 / 30 / 60 / 120 秒加速档。
- 长按中反向、Back / Menu / 确认、焦点丢失和切集，确保旧待执行 seek 不落到新一集。
- 选集面板覆盖单季、多季、列表 / 网格、30 条分段和定位当前集；记录焦点、滚动、请求数和按键到画面恢复时间。
- 分开统计控制层帧时间与解码掉帧；选集外观的 JVM 源码断言失败需先定位，但不直接证明设备帧率回退。

### 音频、TS 与字幕

- AC-3、E-AC-3 / JOC、TrueHD、DTS / DTS-HD、MP1 / MP2 / MP3，覆盖缺失编码元数据和多音轨跨编码切换。
- 自动 / PCM / 设备直通分别测试，记录实际 decoder、输出 encoding、采样率和声道，不把菜单选择等同于实际直通。
- Blu-ray LPCM 覆盖布局 1 / 3 / 9 / 11、48 / 96 / 192kHz、16 / 20 / 24-bit；当前输出 PCM16，其他布局应明确失败，不能无限准备。
- 检查音频单次回退后的进度、暂停、倍速、音量和选轨；确认网络 / 视频错误不被误当音频回退，视频解码策略不变。
- 对高码率 progressive TS 执行长距离 seek 和续播，核对实际画面 / 字幕时间；PCR 搜索窗增大可能增加既有 Range 流量，需同时记录请求量与耗时。
- 内封文本 / PGS、双字幕、在线与本地外挂、编码及偏移分别测试；快速 seek / 换轨 / 退出后不得补播旧 cue，PGS 坐标、长时显示和清屏需目视确认。
- 位图加固后的专项验收：PGS 普通组合复用、多对象/裁剪、调色板动画、连续 seek，VobSub/DVB 正常样本及损坏样本；检查低内存 API 23 设备的峰值内存。MPV 验证 auto、迟到 track-list、位图与文本互切，确认原生与 Flutter 不重复显示。主机合成样本和 JVM Bitmap mock 不能替代这些画面结果，目前没有本次改动的新增设备测量。
- Android TV 不把手机的原生 PiP 能力作为验收项；手机 PiP、通知与媒体按键另测。

本地 LPCM 样本与 FFmpeg 逐字节对照命令见 [主机验证](performance.md)，二进制来源见 [音频依赖](../android/app/libs/README.md)。正确字节输出并不能证明设备音频输出兼容或 CPU 足够。

## iOS 与其他平台

- iOS MPV 与 AVPlayer 分开记录。AVPlayer 使用系统可用字幕轨，当前不具备 MPV / Exo 同等的在线外挂挂载闭环，不按双字幕功能验收。
- iPhone / iPad 检查锁屏、控制中心、后台开关、音频中断、路由变化、原生 PiP，以及封面失败回退；不能只验证 Swift 语言策略。
- 飞牛转码需真实 NAS 检查 HLS 绝对时间轴、seek、换轨新旧会话切换、退出后的资源释放。既有只读层级接口联调没有覆盖这些行为。
- 桌面 MPV 与外部播放器分开验证；外部启动成功不等于应用持有播放状态。macOS / Windows / Linux 的音频解码能力需按各自打包依赖验证，Android / iOS full 覆盖不自动扩展到桌面。
- Web 使用浏览器媒体后端，受格式、自动播放与 CORS 约束；IO 在线字幕仓库、文件字幕选择及文件日志能力不可直接套用。

## 采集与记录

结构化本地日志、预览、筛选、清理和导出仍启用；旧 trace helper 静音不代表关闭日志。比较两组时保持日志等级和容量一致。Android API 30+ 可补充系统历史退出信息，老设备仍有应用原生日志。

Android 可使用 `adb shell dumpsys meminfo com.example.starflow` 采集进程内存，并结合 Perfetto / Android Studio profiler 分析；iOS 使用 Instruments。`gfxinfo` 等 UI 指标不能单独代表 Flutter raster 或独立视频 surface 的全部成本。工具采样本身可能增加开销，应记录是否启用。

每份结果至少包含：日期、版本 / 差异、设备与构建、样本身份、缓存与网络条件、配置、操作步骤、原始采样、统计方法、失败数、结论与仍未覆盖项。公开附件先检查地址、用户名、分享码和凭据；不要提交受版权限制的媒体样本或未脱敏日志。
