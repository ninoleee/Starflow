- `MediaHttpPolicyException` 只保存固定枚举原因：`MALFORMED_URL / UNSUPPORTED_SCHEME / INVALID_HOST / EMBEDDED_CREDENTIALS / INVALID_PORT / HTTPS_DOWNGRADE`。传输层保留该安全原因及 request/redirect 阶段，不链接可能含完整地址的 URI parser 原始异常。点播 Media3 加载策略对该拒绝不重试，避免确定性拒绝反复等待；普通 HTTP 状态及临时网络重试策略不变。
- 点播与直播仍共用原逐跳校验，外域不继承请求头，不允许 HTTPS 降级、userinfo 或非 HTTP(S) 地址。此次只补齐诊断和点播失败处理，不放行未知 CDN、不改写签名地址，不宣称上述真实片源已修复。测试与未完成的真机复测见 [主机验证](performance.md)。

后续 23:21 导出日志已将飞牛夸克 HLS 的失败明确为 `MALFORMED_URL`，不是 `HTTPS_DOWNGRADE`。WebDAV SmartStrm 使用相同 Exo 内核且成功出首帧／续播，飞牛另一条渐进式视频也成功；两种来源的剧集路径分别标为 MP4 与 MKV，不能把同剧集当作已验证的同文件。

使用当前配置重新调用飞牛 `play/info`、`stream` 后，失败主清单均返回 HTTP 200；清单分片的查询参数 `x-oss-process` 原样包含花括号状态表达式，例如 `if_status_eq_404{hls/ts,from_<base64>}`。Java `URI` 拒绝原始 `{}`，同一分片将 `{}` 转为 `%7B%7D` 后返回 HTTP 200 / `video/MP2T`。因此错误位于 OSS 分片查询参数的 URI 转义兼容，不是 CDN 拒绝、缺少 `User-Agent` 或 HTTPS 降级。

后续兼容修复在共享 `LiveTvHttpPolicy` 中仅为资源路径／查询／片段里的可转义字符补编码（空格、`|`、花括号、引号等，路径方括号单独处理），Unicode 通过 URI 的 ASCII 表示输出；不修复 authority，不解码／重编码已有 `%xx`、`+`、分隔符、重复参数或顺序。直接请求及相对／绝对重定向都在同一规范化地址上做 origin 校验并发出请求。控制字符、反斜线、无效 `%` 编码、无效主机／端口、userinfo 和 HTTPS 降级仍拒绝。上述真实 OSS 分片已确认编码后可由 CDN 正常返回；电视端完整播放仍待安装修复版本复测。

### 2026-09-20 N01-N04 与配置 LAN 加固

- Emby PlaybackInfo 和已缓存播放目标统一按 scheme、host、有效 port 判断 origin；外域（含协议相对地址、同主机换协议/端口）不注入会话 token，拒绝 userInfo 和回显源 token 的外域 URL。播放器目标不再携带 `X-Emby-Token / X-Emby-Authorization` 或回显源 token 的 headers；同源媒体使用 URL `api_key`，流专用 headers 独立保留。原生播放器不经过 Dart 请求层，此策略避免原生自动重定向转发自定义 Emby 会话头；原生 HLS 子请求、服务端主动把 token 放进重定向 Location 等仍需按内核/服务器单独验收。
- `PlaybackTargetResolver` 的旧 Emby/NAS 直链不再绕过来源客户端。Emby 同源 `api_key` 更新为当前会话，外域含历史 `api_key` 的 URL 拒绝；历史 Emby Authorization 和已知旧 Token 的回显头也清理。NAS 直链按当前来源 endpoint 完整 origin/目录重建认证，不复用历史 Basic/Cookie；来源已移除或类型变化时拒绝解析。
- Android 点播使用 `NativePlaybackHttpDataSource` 和共享逐跳传输，媒体、HLS 清单/密钥/分片、网络字幕都相对初始媒体 origin 校验，外域不继承来源 headers，HTTPS 降级和 URL userInfo 拒绝。保留 Range、gzip、传输监听和 HTTP 状态错误分类；这不使服务器在 Location 中主动回显的 query 凭据自动安全。
- MPV 与 iOS 原生点播的 NAS/Quark 敏感请求头经实例专属 loopback relay 转发，凭据和 Cookie 按完整 origin 隔离，拒绝 HTTPS 降级并限制重定向。仅引擎使用随机本机地址；历史、续播、源会话和切集目标保留原始身份。关闭或取消中止代理请求；iOS 初始播放与切集都接入，Android 使用自身安全 data source。普通 User-Agent/Referer 不强制代理。支持标准 HLS 点播/动态清单：白名单解析清单标签和带引号的属性，将嵌套清单、媒体/初始化分片、AES-128 identity 密钥及 WebVTT 子请求改写为本会话已登记的地址；外域子请求不继承原始认证。相对地址按每次重定向后的清单 URL 解析，保留签名查询参数。单清单最多 1 MiB、嵌套深度最多 4、会话最多 20,000 个资源；客户端不能指定任意上游 URL。
- HLS 动态清单要求正整数 TARGETDURATION 与至少一个完整分片，刷新响应禁止缓存；注册表在整份清单校验通过后更新，失败刷新不撤销已有地址。非清单资源离开窗口两分钟后可回收，过期地址不重新分配；回退到更早的历史窗口需要重新加载清单，仍受资源上限保护。LL-HLS 的 PART、PRELOAD-HINT、RENDITION-REPORT、PART-INF、SERVER-CONTROL 不下发引擎，按完整分片兼容播放，**不是低延迟模式**。不发送 `_HLS_*` 刷新参数，不接受 SKIP 增量响应或仅有部分分片的清单；未知标签/属性、变量、DRM、DASH、其他播放列表/远程光盘拒绝，不宣称完整 HLS 协议支持。无认证清单与 Android HLS 不受此限制。代理对渐进式媒体做有界前缀验证，会新增一次小 Range 请求；扩展名不明确的 HLS 会在探测后重新读取完整清单，既有“无启动预检”只适用于不经该安全代理的路径。
- Emby JSON 使用 20s 总期限、32 MiB 上限。WebDAV PROPFIND 为 30s / 32 MiB，NFO 为 20s / 4 MiB，STRM 文本为 20s / 1 MiB，DELETE 回复为 30s / 1 MiB。目录响应 href 只接受请求目录内且处于配置 endpoint 目录内的同源资源，拒绝编码路径逃逸；NFO/STRM/删除也在发请求前检查 endpoint 范围，父级侧车探测不越过 endpoint。合法外域 STRM 媒体不继承 NAS Basic 凭据。
- `sendBoundedRequest` 保留 `cancel: Future<void>?`；取消中止当前 AbortableRequest、取消正文订阅，不关闭共享 client。期限覆盖响应头、逐跳重定向与正文；累计字节超过上限立即拒绝。带认证的请求逐跳检查同源，WebDAV 额外检查目录，最多五次跳转，不能依赖底层自动剥离自定义头。Web 开发代理没有禁用上游重定向的契约，因此拒绝需要限制重定向的请求，必须使用能满足 CORS 的直接传输。
- STRM 源文件大小探测由 `WebDavNasClient` 使用 HEAD，再在无有效长度时回退 `GET Range: bytes=0-0`；每条探测链最多 5 次重定向、响应头总期限 5s，取得响应头即取消正文流，不下载完整视频。手动逐跳检查 HTTP(S) URI，跨源后永久移除本次链上的 NAS 请求头；STRM 文本读取本身仍严格限定来源目录。206 必须提供有效 `Content-Range` 总长度，不能用分片 `Content-Length`；200 使用完整长度。请求使用 identity 编码，已知播放列表 URL、文本/JSON/XML/播放列表响应及压缩表示不作为视频大小。探测失败写入大小未知（0），避免 `copyWith(null)` 保留 STRM 包装文件的长度。
- `StarflowHttpClient.get/head/post/put/patch/delete` 是缓冲 API：默认 20s 完整请求期限、32 MiB 正文上限；HEAD 的资源 Content-Length 不算实际正文大小。`send()` 保持流式，不给视频正文套 API 大小/总时长限制；带认证的原始流式请求关闭自动重定向，由调用方处理 3xx。NetworkRequestGuard 的 GET 同样使用可中止 bounded 读取，通用 `run` 的任意业务 Future 仍不能自动取消。
- 日志 formatter 在 category、message、嵌套字段、异常与堆栈截断前统一脱敏 URL userInfo，覆盖编码密码、多 URL 和由该 formatter 处理的 native 文本。结构化本地日志、预览、筛选、清理、导出和 Android native exit capture 仍启用；未经 formatter 的原生文件以及路径中自定义凭据不由此规则保证。
- 配置 LAN 使用 144-bit 随机访问 token、十分钟会话期限、Host/Origin 校验、no-store/no-referrer、单个上传在途。上传限定 JSON、8 MiB 原始字节和 30s 总接收期限，声明长度/分块都检查；页面需确认替换并发送专用确认头。关闭或过期中止未完成接收，读取后/导入前再次检查会话，迟到下载不返回配置。已进入持久化回调的保存不能回滚；这是手机上传页确认，不是电视端二次授权。失败回复/事件不回显上传正文或底层异常。仍是明文 HTTP，只能在可信 LAN 使用。

本节对应修复前审查快照 N01-N04，不把旧审查探针通过视为修复通过。新增测试仅用合成凭据、MockClient 和本机 loopback；不访问真实账号，不代表真机/真实 NAS、CDN、原生媒体重定向或 Web 代理端到端验收。README 与发布段落由主审单独集成。

### 直播订阅与媒体流（2026-09-20）

- 原生直播首页的连通检测由 `live_channel_probe.dart` 独占 HTTP 客户端，使用 `createStarflowTransportClient` 沿用 Dart 运行期代理；不是播放器预检。每次进入／返回等待订阅更新检查结束与列表就绪，自动补测可见的未测／过期频道；空列表延后。只检测视口相交频道的首选线路，不请求离屏缓存行或未访问分组；滚动／切组按新范围继续，恢复调度不清空有效缓存。两路并发、每路 6 秒包含跳转及首包等待，最多三次重定向。GET 携带 `Range: bytes=0-1023`，首个非空块即终止，不保存正文；服务端忽略 Range 或预读时流量可超过 1 KiB，不宣称严格字节上限。
- 自动与手动检测共用 `liveMediaHeaders` 的默认 `Starflow` User-Agent 和对应线路 headers。同源跳转保留 headers，跨源只保留 User-Agent／Range，剥离 Cookie、Authorization、Referer、Origin 及其他自定义头；拒绝非 HTTP(S)、userinfo、HTTPS 降级及过多跳转。每跳显式处理，不借自动跳转转发凭据。不包装 URL 日志客户端，也不记录原始 URL、正文或异常文本；仅向界面返回固定状态、时间及 HTTP 码。
- 新进入视口的线路稳定可见 200ms 才准入，TV 焦点优先，不抢占在途请求；离屏／筛选变化立即取消旧范围。分组下拉展开暂停、关闭继续。快照按线路身份协调，元数据不停止整轮；URL／headers／首选线路变化替换对应任务，删除／隐藏／停用取消。成功缓存 5 分钟，连续失败按 45／90／180／300 秒退避，成功或线路／网络变化重置。仅一个调度定时器处理当前可见项的准入和到期；停留同屏可重新检测，刷新保留旧结果，离屏不刷新，停止／离页不保留检测定时器。
- `connectivity_plus 6.1.5` 在首页存活期间被动消费系统连接类型事件，不发可达性 HTTP／DNS 探测；类型集合去重，网络和代理 runtime 配置变化使缓存失效并取消旧请求。离线暂停准入，在线对可见项等待 200ms；不重开手动暂停或离页会话。正常路由返回复用缓存，后台或监听异常后返回保守失效；系统、代理和生命周期监听随页面销毁解除。同类型 Wi-Fi 切换可能无事件，不能视为完整网络身份检测。插件 Android minSdk 19，应用仍保留 API 23，不变更 TV 发布规则。
- 取消信号中止 HTTP 请求，关闭独立客户端并等待响应流清理，旧清理完成前不释放两路并发名额。离页／后台停止任务，返回自动补测；手动停止本次停留不自动恢复，筛选／网络事件不解除暂停，手动恢复或下次返回才继续。开播前等待清理。`live.probe` 本地诊断记录清理完成／失败耗时和取消标记，超过 1 秒额外告警，无 URL／请求头／原始异常。6 秒请求期限不包含无限底层清理等待，超时报警不视为已释放。结果仅页内内存，无后台扫描、解码或 HLS 子请求；失败退避是下一轮可见项检测，不是单次 HTTP 请求内重试，播放器实际媒体网速采样仍独立。

- MPV 媒体默认 User-Agent 为 `Starflow`，订阅显式值大小写不敏感地优先；同时设置 libmpv 的 `user-agent` 与 Media headers，避免 HLS 子连接回退为 Lavf 标识。只作用于媒体，不改变订阅下载。FFmpeg 6 HLS 允许 HTTP 非媒体后缀；保留扩展名保护、协议白名单限 `http,https,tcp,tls,crypto`，不允许 file/data/UDP。HLS 分片最多追加一次重试并关闭持久连接复用，仍受原启动/进度期限和频道恢复预算约束；不对 403 反复更换标识重试。Exo 沿用既有 `Starflow` 默认值、逐跳同源请求头策略。
- `live_tv/data/live_repository.dart` 使用 `createStarflowTransportClient`，沿用 IO 运行期代理；刻意不包装会记录 URL path 的 `StarflowHttpClient`，避免 IPTV 路径中的账号凭据被记入日志。记录来源 ID、成功/失败；失败另保留频道列表/节目单阶段、固定错误类别和可用的 HTTP 状态，不记录地址、响应正文和底层异常文本。
- M3U/TXT 和 XMLTV 下载均为 30s 总期限、8 MiB 正文上限；XMLTV.gz 解压写入限 32 MiB，并检查 CRC/长度。解析在非 Web compute isolate 执行，保留过去一天到未来七天节目，最多 100000 条。单表最多 10000 频道、单频道 64 线路、全表 50000 线路，超限拒绝而不截断已保存缓存；媒体 HLS 清单不能当频道目录导入。
- 进入直播页按来源 6/12/24/48/168 小时间隔检查，默认 24h；同一来源刷新合并，自动失败检查冷却五分钟，仅下次进入或人工刷新触发，不安排重试定时器。离开直播后不再开始后续来源刷新，已开始请求有期限并允许更新缓存；后台不启动下一来源。
- 选台首页与播放器频道列表的当前节目复用本地 `liveNowNextProvider` 批量查询，页面／列表打开或恢复时及活动期间每分钟失效重读，不触发 EPG HTTP 下载，也不按频道行单独请求；节目单远端更新仍由原订阅期限和手动刷新负责。
- 订阅/EPG/台标不继承媒体播放请求头。M3U 的 `http-user-agent / http-referrer` 与 URL 管道后的 User-Agent/Referer/Origin 仅用于对应媒体线路。首版不支持订阅登录表单、DRM 或运营商 UDP 组播。
- TV 文件扫码使用 `live_playlist_transfer_service_io.dart` 的临时 IPv4 HTTP 服务和随机端口，不经过云端/代理，不复用配置 JSON 上传接口。每会话 144-bit 随机 token，Host/Origin 校验、no-store/no-referrer、页面无外部资源；仅一个上传在途、一次成功接收，文件原始字节最多 8 MiB、接收总期限 30s，后台 isolate 校验频道表。关闭弹窗、进入后台或十分钟过期会废弃未完成上传并关闭端口，成功只进入编辑页等待保存。HTTP 非加密，二维码含访问凭证，只在可信局域网使用；不记录 token、地址、文件正文或原始异常。频道文件模式不能恢复直播备份，也不会覆盖应用设置。
- TV 共用文本输入由 `text_input_transfer_service_io.dart` 提供临时 IPv4 HTTP 服务，仅开放会话页面和 `POST /input?token=...`，与直播文件/备份端点独立。144-bit 随机 token、Host/Origin 校验、no-store/no-referrer、CSP 和无外部资源；UTF-8 `text/plain` 正文声明及分块累计均限制 64 KiB，30s 接收期限、十分钟会话期限、一次成功接收。保留空文本/空白/换行，输入格式由 TV 组件应用，业务校验仍在保存时执行。关闭、后台、过期中止未完成接收；只回填输入弹窗，不调用仓库或自动提交。手机页只接收转义后的字段标题及密码/多行类型，不获取已有值，不读取剪贴板、不请求文本中的 URL，成功后清空手机字段；不记录正文、token 或原始异常。仍为可信 LAN 上的明文 HTTP，密码遮罩不等于加密。
- MPV 开流读取应用代理，Exo 直播使用独立 `LiveTvHttpDataSource / LiveTvHttpTransport`（HttpURLConnection），不继承 Dart 代理。媒体网络支持和自定义请求头在 Web 受 CORS/浏览器能力限制，不使用开发代理宣称全平台可播。直播 Exo HTTP 连接/读取各 10s，应用层最多三次恢复，共用频道级预算。
- 直播右上角网速仅采集现有媒体读取：MPV 本地 `cache-speed` 属性；Exo 每个 open 独立 `LiveTvNetworkSpeed` 汇总 DataSource 的网络字节回调，复用每秒进度任务采样，经带 generation 校验的 `networkSpeed` 通道读取。无额外 HTTP／Range 测速，控制层隐藏且非加载时停止 Flutter 轮询；停止／换台释放旧采样器，不混入订阅、节目单或台标下载。
- 2026-09-20 Exo 错误诊断补齐：原生异常链最多检查 10 层，只上行固定错误类别、Media3 数字错误码和 HTTP 状态；兼容独立直播 transport 的状态异常，开流同步异常和异步内核错误共用摘要。Flutter 白名单解析后随原有失败日志导出，并拒绝旧代次。此变更不增加预探测、请求、重试次数，不调整 User-Agent、跨源 headers、TLS 校验、代理或流格式回退；MPV 仍只有通用内核错误分类。

补充按当前源码核对的限制：

- `LiveSource` 和来源编辑器没有自定义请求头字段；订阅和 EPG 请求没有登录表单、Cookie/Authorization 配置或 NAS 会话注入。只接受有主机、无 URL userInfo 的 HTTP/HTTPS 地址；路径/查询仍可能携带凭据，须自行保管。文件导入不等于可以把 `file://`、UDP/RTSP/RTMP 媒体地址交给播放引擎。
- M3U `#EXTVLCOPT` 与媒体 URL 管道选项解析到 `LiveLine.headers`，仅用于当前媒体线路，不能描述成任意请求头编辑能力。订阅、EPG、台标与播放连接分开；重定向、HLS 子清单/分片的 headers 行为需用真实来源按内核验证，不因 MethodChannel 参数测试通过就宣称鉴权全链路已验收。
- `live_logo_provider.dart` 使用独立 `AsyncWorkPool(4)`，每张台标响应头+正文 15s、2 MiB 上限，排队等待另计；provider 释放取消未完成请求并关闭该请求 client。沿用传输代理，不经记录 path 的 HTTP 包装层，不继承媒体 headers，不使用影视海报的持久化图片缓存。真实台标网络、重定向与设备解码尚未测。
- 原生 MPV 使用 engine 创建时捕获的代理配置，换台继续用该快照；保存代理设置不会即时重配已存在的直播 engine。新建 engine 时才重新读取设置。Exo 使用标准 Media3 source factory 和独立 HTTP data source：清单、密钥、分片与每次重定向都按最初媒体地址的精确 origin 检查，仅同源携带来源 headers；拒绝 HTTPS 降级、URL userInfo 和超限重定向。容器无法识别且异常链含 `UnrecognizedInputFormatException` 时只尝试一次 HLS 回退，不预探测；2026-09-21 起不再限制入口后缀，以兼容脚本和非标准后缀清单，HTTP／解码错误不触发回退。不走点播 SmartStrm 预检、飞牛 resolver、转码或播放地址刷新；直播自动恢复只重开当前/备用线路，不自动刷新订阅以换取过期 token。
- 开流 15s、进展监测 18s 与底层连接/读取期限是不同层次。生产 `CancellableLiveEngine` 在超时/换台/退出时绕过 open 队列请求卸载，收到原生取消确认后才允许串行 stop/dispose/下一次 open；没有取消能力的适配器仍等待旧 open settle。取消确认本身挂起时不继续重开，不能承诺 15s 后网络必定断开。18s 只由 progress/frame 续期，音频焦点暂停/抑制停止检测。三次 2/4/6s 退避限制应用层恢复，不是最多三个 HTTP 请求，HLS 仍持续读取子清单/分片。原生开流回执不等于第一帧。
- 自动更新是页面激活时检查，不是后台服务；节目列表每分钟刷新的是本地查询/时间显示。保存带 URL 或 EPG 的来源后和人工更新会调用刷新入口，仓库跳过已停用来源，同一来源同版本的请求合并。来源版本阻止旧结果回填，但编辑/停用/删除不保证在途请求立即断开。
- IO 的 `starflow-db/live_tv.v2.db` / Web 的 `starflow-live-tv-v2` 保存订阅、EPG、多线路/headers、整理偏好及直播内核，不属于 `AppSettings` 导出、文件/Web/TV 配置传输、WebDAV 手动配置备份或影视收藏自动同步。非 TV 保留本地文件流程；TV 复用扫码服务的隔离模式：`backupImport` 仅接受 `POST /upload` 的直播 JSON（声明/累计上限 32 MiB、接收 30s），校验后等待电视确认；`backupExport` 只提供带令牌的 `GET /download`，发送已校验快照并禁止上传。继承随机 token、Host/Origin 校验、单次传输、十分钟会话与后台/关闭清理，不新增远端同步。备份及数据库未加密，不能把普通配置同步成功当成直播数据已备份。

2026-09-20 合并后的主机验证为 132 项 Flutter、17 项直播 JVM，通过范围见 [主机记录](performance.md#2026-09-20-直播前置验证快照)；真实源/真机未测，已确认 `adb devices` 为空。JVM 本地 HTTP 服务测试不代替真实 CDN/鉴权源。MPV/Exo 同源对照的代理、鉴权、断流及生命周期验收见 [设备清单](performance-device.md#直播双内核对比验收2026-09-20)。

共享 HTTP 的缓冲 API 默认 `20s` 覆盖响应头和正文；流式 `send()` 的 `20s` 只约束响应头，不限制媒体长流正文。豆瓣 / 元数据额外使用 `6s` 总期限，飞牛 API 使用 `20s` 总期限，PanSou 专用客户端使用 `60s`；字幕下载与 WebDAV 同步分别有自己的正文大小和总等待限制。应按实际入口排查，不把一个超时值套到所有请求。

## 请求行为与历史演进

- 2026-09-20 播放器修复：iOS 不再首播前逐集解析剩余季队列，使用 Android 已有的延迟 resolver 契约，切集仅解析选中条目，30 秒容器等待上限和迟到结果释放不新增测速或预取全季。飞牛 iOS 解析会话接入既有 Dart 会话所有者，退出释放。MPV 外挂字幕仍用原有下载、鉴权、正文边界，但不阻挡媒体可操作状态；取消后的结果不能覆盖新会话或手动选轨。AVPlayer 从 item 时间轴修正直播策略，不为分类额外探测 URL。

### 2026-09-20 请求生命周期优化

- 图片使用四路传输池，名额覆盖响应头及完整正文，区别于 TV UI 的 4s/8s 放行租期；IO/Web 入口均设 15s 总期限、32 MiB 累计字节上限，超时/超限通过 AbortableRequest 中止传输。排队时间不计入这 15s。Web 开发转发保留 abort 信号，仍遵循 CORS。
- 隐藏/销毁组件取消未完成图片；IO 持久缓存按 URL+headers 共享请求，只有最后一个持有者离开才中止，已显示图片保留。取消不关闭共享 HTTP client，不影响其他图片或媒体流。
- NAS 目录 PROPFIND 增加 30s 响应头+正文期限和 32 MiB 上限，不改变同步备份自身的 16 MB 限制，也不套用到视频流。播放启动发出后台停止请求后继续准备，仍保留旧播放器串行清理。
- 同一搜索页的连续查询共用可调并发池，过期排队任务不再启动；已经开始的搜索仍自行收尾。首页/元数据/扫描池仍独立，配置值不是全应用网络连接总数上限。

### 一致性修复的网络影响

- 缓存图片的 URL 和 headers 从同一目标选取，空 headers 表示该图片无需继承旧凭据；混合鉴权背景图不再合并为一个列表。此修复不增加图片预取、代理或重试请求。
- NFO 共享解析仅处理已经读取的 XML；WebDAV 仍负责相对图片解析与同源鉴权，Quark 仍负责下载地址解析。两者不新增扫描请求。
- SmartStrm 请求失败不撤销已经成功的转存，也不阻止独立的媒体源刷新；结果包含附加警告，不自动重试转存或 Webhook。两个网盘的来源筛选和零新增策略保持各自原有行为。
- 媒体源目录重映射比较完整 origin（scheme、host、有效 port），避免同主机换协议 / 端口后仍访问旧服务。播放记忆串行写入与共享阈值均为本地逻辑，不新增网络探测。

### 2026-09 元数据与查询链整理

- 组件重构后的 `DetailLibraryMatchCoordinator`、`SearchSession / SearchShareValidator` 和 `CloudSaveDispatcher` 继续调用原有客户端，不新增协议、轮询或转存写重试。搜索会话失效阻止排队和迟到结果提交，不等同于已发 HTTP 请求立即中止；旧请求在结束前仍占并发名额。缓存组件拆分不触发迁移或额外远端刷新，播放器资源所有者拆分不增加启动探测。
- 详情与后台补全共用元数据执行服务，保留后台按需补缺和强制刷新策略；WMDB/TMDB/豆瓣请求失败进入统一结果状态，不将吞掉异常后的原始目标标成成功。部分来源成功的数据保留，不新增轮询或自动重试。
- 媒体仓库移除未调用的旧查询、夸克目录遍历及 NFO 链，实际网络访问继续由现有查询服务、索引和夸克客户端负责。仓库文件改名不改变协议、鉴权或分页。
- 首页刷新移除固定 `140ms` 等待，来源配置读取移除 `120ms` 人工等待；首页请求并发、限流与启动模块等待保持原有策略。编码路径的删除清理及评分合并均为本地逻辑，不增加网络请求。

- 2026-09-20 音轨菜单新增当前流不可用音轨的显式转码入口；浏览菜单只使用现有流元数据，不发起探测或创建会话。用户选择飞牛实际返回的转码档位后复用 `play/info -> stream -> play/play`；显式音轨 GUID 在新 `stream` 中不存在时终止，不申请其他音轨的会话。Exo 进度和画质切换对音轨 GUID 的反向映射保留不支持轨道的位置，列表数量不一致且元数据无法唯一匹配时不猜测。

- 服务器地址由用户配置，建议局域网直连或 HTTPS；可填写根地址、以 `/v` 或 `/v/api/v1` 结尾的地址，反向代理前缀会保留。当前不执行 FN ID / 中继发现，也不跟随登录和 API 请求的 HTTP 重定向；重定向时应填写最终影视服务地址。
- 登录使用 `POST /v/api/v1/login`，随后 `GET /v/api/v1/user/info` 验证用户；API 使用飞牛 Web 客户端的 `Authx` 签名及 `Authorization / Trim-MC-token` 会话。密码原样发送，不去除前后空格。签名协议参考 [FlyNarwhal](https://github.com/FNOSP/FlyNarwhal) 的公开 v1 实现，不引入其服务端依赖。
- 分区请求 `GET mediadb/list`；条目分页使用 `POST item/list`，以 `ancestor_guid` 或 `parent_guid` 指定作用域；子层级使用 `GET item/{guid}`、`season/list/{guid}` 和 `episode/list/{guid}`。这些路径均位于 `/v/api/v1` 下。
- 媒体库刷新通过 `POST item/list` 的 `ancestor_guid` 读取分区，并显式传入 `tags.type = Movie / TV / Directory / Video / LiveChannel` 与 `exclude_grouped_video: 1`，避免飞牛服务端把剧集层级中的单集直接混入媒体库根列表；目录浏览使用 `parent_guid`、`exclude_grouped_video: 0`、`sort_title / ASC`，保留目录内实际层级。播放前请求 `POST play/info` 和 `POST stream`，版本列表使用 `GET stream/list/{guid}`。本地文件使用 `GET media/range/{media_guid}`，播放器负责标准 Range 和续播；云盘返回的画质索引或 STRM 外链使用服务端返回信息，不发送额外测速或 Range 预检。
- `POST stream` 请求体包含 `media_guid`、`level: 1`、`ip: MD5(trim(accessToken))` 及 `header: {"User-Agent": [播放器 UA]}`。`ip` 是飞牛协议中的会话摘要，不是设备 IP；这些字段参与完整 JSON 的 Authx 签名。播放器默认使用相同 UA，第三方直链的服务端 UA 优先。旧实现漏传 `ip / header`，设备日志显示该阶段返回业务码 `-1`；回归测试按完整请求契约校验。
- 飞牛本地缓存刷新前按当前选中的媒体库根目录调用 `POST item/refresh`，请求体为 `{"item_guid": "<分区 GUID>"}`，使用同一 Authx / 会话签名；未限定分区时先通过 `mediadb/list` 枚举可浏览库。该请求用于先通知服务端更新，再在原有 `mediadb/list` / `item/list` 读取链路写回本地分片。服务端通知失败只记录不含 GUID 和凭据的警告，不阻断本地刷新。
- `stream` 返回的 `audio_streams / subtitle_streams` 会随播放目标进入现有播放器音轨和字幕入口；`play/info` 的 `audio_guid / subtitle_guid` 作为默认轨道。外挂字幕通过 `GET /v/api/v1/subtitle/dl/{guid}` 下载，沿用当前会话鉴权和 Authx；应用保留原始字节，支持 ZIP 内 `SRT / ASS / SSA / VTT` 文本字幕及 UTF-8 / UTF-16 / GBK 解码，位图字幕不会伪装成文本加载。媒体流返回多个 `direct_link_qualities` 时，播放器“播放设置 -> 画质”重新打开 `media/range` 或直链继续播放，并保留当前时间点。
- `stream.qualities` 的原画之外档位接入同一画质菜单。用户明确选择转码时，`POST play/play` 按完整 JSON 签名发送 `media_guid / video_guid / video_encoder=h264 / resolution / bitrate / startTimestamp / audio_encoder=aac / audio_guid / subtitle_guid / channels=2 / forced_sdr=0`。`startTimestamp` 为当前播放秒数，播放器仍按绝对时间续播；服务端内置字幕使用 GUID，关闭或客户端渲染的外挂字幕传空 GUID。响应原始 `play_link` 用于控制和进度回写；相对地址保留配置的反向代理前缀，绝对地址必须与 NAS 同源，才携带 NAS 会话头。无新增测速 / Range 预检，默认原画不发送转码请求。
- 画质菜单的分辨率合并与“自定义”码率展开仅处理已返回的列表，不增加接口请求或网络探测；选择分辨率后使用当前同组码率或服务端第一档，仍按原始档位索引、分辨率和码率执行既有解析流程。
- 画质、转码音轨和字幕切换通过新建会话保留旧会话回退能力，不原地修改旧流；新播放就绪释放旧会话，失败或过期结果释放新会话。释放使用同一 Authx 客户端 `POST media/p`，请求包含 `req: media.quit / reqid / playLink`；业务结果检查 `result: succ`，失败仅记录脱敏警告，不阻止退出。MPV / Exo 都在退出时排完最后进度后清理活动会话；请求超时仍受 API `20s` 上限约束，无法获得 `play_link` 的服务端分配由 NAS 超时回收。能力日志仅记录数量与转码布尔值。
- 图片通过 `sys/img` 读取；NAS 登录凭据仅添加到同源图片和播放 URL，不附加到第三方图片 / STRM 外链。应用不记录密码、Token、Authx 或响应正文，网络请求继续使用共享 HTTP 客户端、运行期代理及脱敏结构化日志；飞牛 API 总等待上限为 `20s`，POST 不自动重试。
- `library.fntv` 业务错误日志仅记录操作阶段、HTTP 状态码与业务码；错误提示区分播放信息和媒体流解析阶段，不记录请求体、会话摘要、播放地址或服务端错误正文。
- 缓存读取不额外扫库；显式或首次刷新每分区最多读取 `200` 条并分页写入现有分片。飞牛分区失败会让本轮刷新失败并保留已保存缓存。启动同步复用“同时刷新 Emby / 飞牛影视媒体源”开关，TV 默认关闭。
- 播放器按约 `10s` 节流调用 `POST /v/api/v1/play/record` 回写 `item_guid / media_guid / video_guid`、当前音视频轨道、画质、时间、时长、播放地址和设备信息；回写失败不影响播放，未拿到完整 GUID 时静默跳过。转码会话回写原始控制 `play_link`，不使用拼接后的绝对播放 URL。转码与释放流程目前以 mock HTTP、Flutter 单元 / 组件和 Android JVM 测试为主要证据；上文 2026-09-19 的真实服务只读验证不覆盖 HLS 时间轴、长距离 seek 或 NAS 资源回收，这些仍需真机联调。FN ID 中继、双重验证与直播库不在当前接入范围。
- MPV 与 Android Exo 共用 Dart 飞牛网络客户端；Exo 不另建 HTTP / Authx 实现。原生播放画质复用既有解析通道，外挂字幕按字节下载、解压 / 转为 UTF-8 后交给 Media3，退出会话清理临时文件。原生飞牛通道等待上限为 `30s`（底层 API 仍为 `20s`），迟到回调忽略；进度请求串行发送，合并同一影片待发送快照，保留换集 / 退出最后进度。回写失败仅记录不含地址和凭据的结构化警告，不弹窗中断播放。该路径增加了 Android JVM 队列、完成进度、过期请求和失败回退测试；仍需真机与真实 NAS 联调。
- 飞牛外挂响应体同样受 `16 MiB` 上限约束，`20s` 覆盖响应头与流式读取；解压与字符解码放入后台 isolate，共享在线字幕的 ZIP 和格式限制，不改变 Authx、重定向或来源鉴权规则。

## 运行期统一网络策略

公共实现位于 `lib/core/network/`：

- `starflow_http_client.dart`：共享传输客户端、运行期 HTTP 代理、Web 开发转发适配、`20` 秒响应头超时与脱敏请求日志
- `network_proxy_config.dart / network_proxy_runtime.dart`：代理配置持久化、局域网绕过判断与进程内动态配置
- `starflow_http_transport*.dart`：IO 平台的 HTTP 代理、HTTPS CONNECT 和可选 Basic 认证；Web 端保持浏览器传输实现
- `network_failure.dart`：统一分类超时、TLS 握手、DNS、连接异常、连接提前关闭、HTTP 状态、熔断、取消与未知错误
- `network_request_guard.dart`：按业务策略和主机隔离连续失败计数，提供总请求超时、可选幂等重试和熔断

当前行为：

- Emby、WebDAV、豆瓣、元数据、搜索、字幕、夸克和 SmartStrm 等使用共享客户端的入口都会记录统一的 `failureKind` 与 `transient`
- `PanSou` 搜索另行记录开始、完成和失败事件，包括 provider、主机、耗时、结果数或错误；日志只记录搜索词长度，不记录正文
- 豆瓣和 `WMDB / TMDB` 元数据请求默认总超时 `6` 秒；同一业务策略下同一主机连续 `3` 次临时故障后暂停 `2` 分钟
- `408 / 425 / 429 / 5xx` 视为可恢复的临时 HTTP 状态；`401 / 403 / 404` 等不会被当作临时网络故障
- `NetworkRequestPolicy.maxRetries` 默认是 `0`；只有调用方显式启用的幂等请求才会有限重试。POST、DELETE、保存、删除和 Webhook 等写操作不会盲目重试，不能把“临时错误”理解为所有入口自动重发
- 共享日志只保存 method、scheme、host、port、path、status 和错误类别，不保存 headers、Cookie、Token、密码或完整 query
- 共享日志会额外记录当前请求是否选择代理，但不会写入代理地址、用户名或密码

### 应用运行期代理

Android、iOS 和桌面端可在 `设置 -> 网络 -> 代理设置` 配置标准 HTTP 代理：

- 支持 HTTP 请求转发和 HTTPS CONNECT
- 支持可选的 Basic 用户名与密码
- 默认让 localhost、`10/8`、`172.16/12`、`192.168/16`、链路本地地址和 `.local` 主机直连
- 保存后，应用接口、Emby / WebDAV、豆瓣、元数据、搜索、在线字幕、夸克、SmartStrm 和图片的后续请求立即使用新配置
- 内置 MPV 在打开 HTTP / HTTPS 远程媒体前读取同一代理配置；外部系统播放器及 App 内原生播放器继续遵循对应平台或播放器自身的网络设置
- 页面内“测试代理连接”会通过当前代理请求 Starflow 实际依赖的 TMDB HTTPS 主机，最多等待 `10s`；未携带 TMDB Token 时返回鉴权状态也代表代理链路已经建立

Web 页面不能自行指定浏览器系统代理，因此 Web 端该页只展示能力边界；开发时继续使用下文的 `STARFLOW_WEB_PROXY_BASE` 方案。

日志里的常见 `failureKind`：

| 值 | 含义 | 优先检查 |
|---|---|---|
| `timeout` | 超过当前策略的等待上限 | 服务响应、代理、路由和设备负载 |
| `tlsHandshake` | TLS/证书握手中断 | 系统时间、证书链、代理和网络劫持 |
| `dns` | 域名解析失败 | DNS、路由器与网络连通性 |
| `connection` | 拒绝、重置、不可达或 Socket 异常 | 服务端口、防火墙和链路稳定性 |
| `connectionClosed` | 响应完成前连接被关闭 | 反向代理、服务端 keep-alive 和弱网 |
| `httpStatus` | 服务返回非成功状态 | 同条日志中的 `statusCode` |
| `circuitOpen` | 连续临时故障后暂时跳过请求 | `retryAfter` 与前序失败日志 |
| `cancelled` | 页面退出或调用方主动取消 | 通常无需按网络故障处理 |

补充说明：

- `WebDAV / NAS` 标题识别会在本地剥离 `{tmdbid-...}`、`{tvdbid-...}`、`{imdbid-...}`、`{doubanid-...}` 这类嵌入式外部 ID 标签；这一步只影响本地展示标题和搜索词，不新增网络请求
- `NasMediaIndexer` 的主文件与多个 `part` helper 属于同一条刷新链路，文件拆分本身不改变请求扇出；排查时需连同 storage / refresh / grouping 实现一起看，不能用主文件行数代替性能结论
- 如果条目后续已经刮削过或手动关联过详情信息，首页、媒体库和详情页展示时会优先使用缓存里的更新后标题；这同样只是本地缓存合并优先级调整，不增加新的网络请求
- `WebDAV / NAS` 识别里新增的包装目录 / 版本说明忽略，例如 `分段版 / 特效中字 / 会员版 / 导演剪辑版 / 清晰度 / 音轨 / 字幕`，也完全发生在本地，不增加新的网络请求
- 同一电影根目录下的多个技术版本目录会在本地结构推断中收口为一个电影和多个播放版本；清晰度、语言（包括英语、日语、韩语）、字幕或码率等组合均可作为技术标签，版本目录下的嵌套文件也沿用同一影片根目录，无季集信号的平铺画质版本也不自动推为剧集。不新增远程请求。完整增量扫描重算本地结构并保留已有在线结果；在线误匹配仍通过重建索引或显式元数据操作修复
- 外层有效片名下仅有一个“片名 + 年份 / 语言 / 字幕”发布包装目录且只有一个无季集信号的视频时，也会在本地使用外层目录名索引成电影；这一窄规则不增加请求，明确的 NFO 标题仍优先
- 电影多版本详情页在 Hero 下方直接展示“播放版本”选择控件；“本地资源”来源切换与当前来源内的播放版本选择分别维护，WMDB / TMDB 只用影片根目录名匹配，文件名中的清晰度、编码和发布组信息不会再作为电影标题提交（明确匹配的 NFO / sidecar 仍优先）。版本展开按来源、分区和条目读取本地索引，也支持只索引选中目录的 NAS / WebDAV 来源，不会重新扫描目录；`.strm` 列表不会批量解析，只有当前选中版本会读取 `.strm` 并通过 `HEAD / Range` 获取源视频大小
- `WebDAV / Quark` 的“顶层推断目录”只补充一级媒体目录之前的自定义包装层；确定媒体目录后，子目录不能重置归属边界。结构推断开启时，每个一级媒体目录最多生成一个剧集或电影入口；混合记录、电影播放版本与季集归并均在本地完成，不增加新的请求类型。
- 2026-09-23 历史 v16 检查只验证 85 个 STRM（含歌曲）最终为 1 个剧集入口，不能代表当前资源过滤和季集结果。2026-09-24 v17 重新使用本机配置只读 `PROPFIND` 验证《重启人生》：排除 46 个音频 STRM 后为 39 个视频资源、1 个剧集、10 集正片且每集 3 个版本、9 集番外。`tool/debug/webdav_directory_grouping_test.dart` 通过 `STARFLOW_SETTINGS_JSON` 和 `STARFLOW_CHECK_DIRECTORY` 读取配置与目录，禁用 sidecar/在线/播放地址补全，索引只写入内存；不输出凭据、不写远端或设备索引。这是主机网络与索引验证，不是 TV 真机验收。
- 扫描结果携带完整性标记。命中条数或递归深度上限、夸克缺少 Cookie 等情况不能视为远端删除；任一分区不完整时保留全来源未见记录和已有分类，强制重建也遵守此规则。不增加后台补扫或远程探测；已知音频 STRM 按文件名过滤，不为分类下载 STRM 内容。
- 新增的“剧集只按剧名层级搜刮”只会改变结构推断剧集条目的在线 metadata 查询词；开启后会只用目录剧名查询，并跳过按单集继续请求剧照，整体上会减少这类请求，不会引入新的服务端协议
- 新增的综艺/节目文件名轻量识别，例如 `第X期`、`01 会员版` 这类“集号 + 版本说明”形式，同样只在本地解析，不新增网络请求
- 目录名里如果能识别出明确季号，例如 `Season 1`、`S02`、`SE08`、`第2季`、`Stranger.Things.S02.2160p.BluRay.REMUX`，就会在本地结构推断里直接把这一层当作季目录，不新增网络请求
- `SE08.06` 与父目录中的独立 `#19` 集号同样只在本地识别；后者会跳过单集目录标题并归入上一级剧名的第 1 季
- 对 `2.巴以 / 5.美国 / 9.韩国` 这类“数字 + 标题”的专题目录，会额外要求同级里存在多个同类兄弟目录；这一步同样只发生在本地结构推断阶段，不会为了重新判季额外发网络请求
- 明确剧名下的 `2025 / 2026（4K）` 年份分组会在本地继承上级剧名并保留为季名；`4K 12集` 等看不出季名的画质/版本/总集数目录只作为包装层，文件自带季号时按季号归组，否则进入默认季。两类目录都不会作为系列名提交给 `WMDB / TMDB`，该规则不新增网络请求，媒体源顶层的纯年份目录仍保留为可用剧名
- 已识别年份会和查询标题分开提交；查询标题末尾相同的年份会先移除，例如 `披荆斩棘2026` 配合年份 `2026` 时实际搜索标题为 `披荆斩棘`
- 一旦当前层被识别为季目录，就会把上一级当剧名；像 `怪奇物语/Season 1/Season 2`、`怪奇物语/Stranger.Things.S02.2160p.BluRay.REMUX` 都会把 `怪奇物语` 作为剧名，这同样只是本地结构层级判断，不新增网络请求
- 图片请求如果遇到单张 `404`，展示层会自动尝试备用 artwork；全部候选失败后会按 `1s / 4s / 12s` 有限重试，单次请求上限 `15s`，过程记录到 `image.load`，日志只保存 host、缓存策略和重试次数，不保存带鉴权参数的完整 URL
- 持久化图片缓存当前按 `URL + headers` 区分 identity，避免不同鉴权头误共用同一份缓存；远端失败但本地还有旧字节时，也会优先回退到 stale bytes
- 首页现在拆成 seed 抓取层和详情缓存装饰层；详情缓存变化只会重做本地 merge，不会重新跑一轮来源或豆瓣请求
- 详情页、媒体库、人物作品页和搜索页在页面失活时，只会取消当前会话、刷新或搜索任务，不会顺手把稳定结果一起失效掉
- 详情页被播放器覆盖后暂停 provider 订阅和新增后台任务，但保留已展示的剧集 / 剧照组件、季选择与滚动位置；路由真正销毁才释放组件。单集图片在 `TV` 上复用并发门，隐藏页取消尚未开始的加载，已发出的请求不保证立即终止
- `TV` 图片并发门固定四路，并由 gate 自身为活动 permit 设置 `8s` 租约；租约异常到期会写入 `image.load-gate` 并自动释放，防止 Hero 与海报同时长期等待
- 搜索页空关键词会直接短路；多来源结果按来源返回进度短节流提交，夸克与 115 结果则按单条验证完成逐步补入，共用 `taskMaxConcurrency` 上限
- `TV` 模式除了现有详情、搜索、播放和图片请求链路外，配置管理还会临时启用一个局域网 HTTP 传输入口，供手机上传或下载配置 JSON
- 文件、Web 与 TV 局域网配置导入统一校验当前 `schemaVersion: 3`；旧 JSON 会在写入前被拒绝，不会触发字段迁移
- Web 端的配置管理直接走浏览器下载和本地文件选择器，不依赖应用私有目录，也不会额外启用局域网传输服务
- 网络同步通过统一 `StarflowHttpClient` 访问用户配置的 WebDAV：连接测试使用 `PROPFIND Depth: 0`，子目录 404 时额外 PROPFIND 基础地址；基础地址成功则报告连接成功、目录待创建，基础地址也 404 则提示接口地址错误，认证等错误不忽略。目录留空时不重复探测同一路径。测试只读，不创建目录或验证写权限；实际上传逐级 `MKCOL` 创建相对目录，每次返回 200 / 201 / 204 / 405 后立即以 `PROPFIND Depth: 0`、`Cache-Control: no-cache` 验证目标；需响应中同源、匹配路径的成功 DAV 属性确认是 collection，404、同名文件或无效响应均停止，不继续 GET / PUT。验证完成才 `GET` / 条件 `PUT` 更新 `starflow-sync.json`，下载使用 `GET`。基础目录需预先存在，不向上创建基础地址中的路径。请求不跟随重定向，用户需填写最终地址；采用可选 Basic 认证，建议 HTTPS。没有为验证引入计时器或写入重试。
- 同步请求包含响应读取最多等待 30 秒，单个文件上限 16 MB；认证、格式、缺失内容和手动配置 ETag 冲突均显示失败，不将服务端响应正文放进错误消息。Web 端受 CORS 限制，服务器或开发代理须允许 `PROPFIND / MKCOL / GET / PUT`、认证、Depth、Cache-Control 及手动配置所用条件请求头；收藏设备文件不依赖 ETag，服务器须支持目录列举及文件读写。
- `sync.webdav` 为同步请求补充响应日志，包含方法、主机、路径和状态码，也记录成功的 MKCOL；不包含账号、密码、认证头、查询参数或正文。创建目录、验证目录、读取与上传文件的失败提示带阶段及 HTTP 状态，避免只凭上传 404 误判创建结果。日志仍遵循用户的日志开关和等级过滤。
- 收藏设备文件 PUT 日志包含 `writeMode: device`，读回缺少本次变更记录 `readbackMismatch`。`sync.favorites` 记录 `trigger`、读取的 `deviceCount`、完成结果和失败阶段（含 `device / verify`），失败不再只表现为 GET 200；不输出收藏或任意异常正文，不再进行 ETag 属性探测。
- 网络同步连接现纳入 `AppSettings.webDavSync`，本地保存不联网；JSON 文件、Web、TV 局域网导出和手动配置上传包含同步地址及明文账号密码，导入直接替换本机连接但不立即触发收藏同步。收藏独立同步文件不携带应用配置，原有首次进入／增删触发规则不变。
- 网络同步表单与其他配置页一致自动保存：250ms 仅用于合并本地连续输入，返回补存，网络操作前等待本地队列；没有独立保存按钮，自动保存失败会阻止该次网络操作。这不是网络同步计时器，不新增启动、定时、页面重进或配置变更同步。
- App 启动不发起收藏同步请求。收藏可选自动网络任务（默认关闭）由本次 App 运行中第一次进入收藏页、成功新增／删除收藏触发设备文件同步；右上角手动按钮可随时触发同一合并链路。首次进入在异步请求前记为已使用，首次未开启或失败也不因重进补发；页面重建、连接设置保存和恢复前台均不重置，App 重启后才重新计数。没有定时巡检、延迟防抖、网络恢复探测或失败定时重试，海报补全和远端合并不额外同步。失败等待增删事件或手动点击，后台不发起新任务，已发出的请求不保证取消但不应用过期结果。配置仍不自动同步。
- 收藏同步以 no-cache `PROPFIND Depth: 1` 列举同步目录的 `starflow-favorites-<设备ID>.json`，仅读取同源直接子文件，不跟随异域 href、子目录或无关文件；需成功 DAV 属性及有效目录响应。最多列出 100 份设备文件，GET 正文合计最多 16 MB；本设备文件即使未列出也直接读取。目录 404 可等待首次写入创建；已列出的设备文件暂时 404、认证或解析失败会终止，不按空收藏处理。设备 ID 为本机持久化的随机安装身份，不联网获取，不随配置 JSON 导入／导出。
- 合并各设备和本机文档后，只有本设备远端关键内容不同时才 PUT 自己的固定文件，新设备首次写入先逐级 MKCOL 并验证目录；无记录时不创建空文件。不覆盖其他设备路径、不创建共享索引、不累积逐次快照、不删除旧文件，不发送 ETag 条件头或执行 ETag 探测。每次成功 PUT 后追加 no-cache GET 验证，确认本次变更已保存后才显示成功；未通过则保留本地数据，不定时重试。文件由不同安装各自写入，避免跨设备覆盖；服务器仍需可靠保存并最终列出新文件，同机多进程／整份私有数据克隆不属于独立设备保证范围。设备之间的变更在下一次既有触发时合并，不是实时推送。手动 `starflow-sync.json` 链路不变。
- 收藏设备文件使用精简 JSON，只传标题、链接／提取码、文件夹、来源和媒体标识、必要详情／播放入口及增删版本；播放地址、鉴权头、容器／编码以及影响播放缓冲或字幕匹配的数值参数保留，海报地址与图片头、简介、图片列表、评分和演职员等缓存不传。读回验证只比较关键字段，不因云端缺少海报误判失败。已有本机缓存保留，新设备缺图按既有后台补图流程处理，补图不推动同步版本或造成下次重复 PUT；列表隐藏缺失简介和标签，不为此额外请求网络。客户端只读取固定设备文件格式，不读取共享旧文件。此优化减少传输正文与序列化负担，不减少目录列举和读回验证次数，实际耗时仍取决于设备数量及 WebDAV 响应延迟。
- iOS / iPadOS 的配置导出现在改成系统文件导出器，只会弹出原生保存面板，不会额外引入新的网络请求
- `TV` 默认可见性滚动及首页／选集等特定路径的显式居中都只是本地交互，不增加新的网络请求
- TV 确认／菜单重复事件消费、松键后打开文本编辑、缺焦恢复、目录与合集首焦点、分页边界保焦及字幕结果去除重复焦点都只调整本地输入与控件。原有搜索、下载、目录读取与缓存链路不变；保焦的忙碌按钮仍拒绝重复操作，不新增探测、预取或重试。
- `TV` 页面删除空的焦点记忆壳并恢复默认方向寻焦；文本编辑弹窗只在输入框局部保留上下键退出处理，这些都只影响本地控件交互，不增加网络请求
- `TV` 左侧菜单的自动隐藏现在直接跟随菜单焦点范围，隐藏菜单退出寻焦候选，避免动画与焦点状态短暂错位；该修复只改变本地布局和焦点树，不增加网络请求
- `TV` 一级页面左边界返回菜单会主动安排本地更新帧，避免静止页面需要第二次按键才能执行聚焦；只调整帧调度，不增加网络请求。
- 页面生命周期失活处理不再等待绘制帧，使已有任务取消与会话失效逻辑在后台停帧时仍及时执行；恢复前台继续按页面可见性和既有准入规则执行。首页、设置页焦点恢复与首页滚动边界等待主动调度更新帧，不新增网络协议、请求类型或重试策略。
- TV 延迟识别后的设置页首焦点检查只调整本地焦点；信息管理页自动更新按钮忙碌时可聚焦但仍禁用确认，不重复发起元数据请求，不改变既有解析、缓存写入与失败处理。

- 进入播放器后，播放会话本身就会把首页 `Hero` 补数、详情页自动补元数据 / 自动本地匹配、隐藏页网络图片加载压住；从网络侧看，播放期间不应继续新增这几类后台请求
- 内置 `MPV` 新增的启动期缓存、回看缓冲、`demuxer thread` 和 `fast profile` 调优也都发生在本地播放器参数层，不会引入新的网络协议；它们只是在已有播放地址上改变本地缓冲和解码策略
- 本地 `ISO` 走 `dvd-device / bluray-device`、远程 `ISO` 回退普通直开，也只是既有播放地址上的本地打开方式切换，不会引入新的服务端协议
- 详情页资源信息区切换播放器只会把本地默认播放器设置写回 `SettingsController`，不引入新的网络请求
- 从详情页进入的 `/detail-search` 只是复用现有搜索页并补上返回工具栏与无转场，本身不新增新的搜索接口
- 人物作品卡片右上角的题材/类型标签来自 `TMDB` 人物作品结果里的 `genre_ids` 本地映射，不额外请求详情接口
- 页面级 `RetainedAsync` 会优先复用最近一次已完成的详情 / 人物作品结果，因此切页返回或播放结束回到页面时，不会因为保留态本身新增一次元数据请求

## 4. Web 开发代理

仓库里还带了一个 Web 调试脚本：

```powershell
.\scripts\run_web_with_proxy.ps1
```

这个脚本会：

- 默认在 `8787` 端口提供本地代理
- 用 `flutter run -d edge` 启动 Web
- 通过 `--dart-define=STARFLOW_WEB_PROXY_BASE=http://127.0.0.1:8787` 把代理地址注入应用
- 当前脚本内置了本机 `Flutter` 与 `JAVA_HOME` 路径，换机器时通常需要先按自己的环境调整

适合本地 Web 调试时统一转发部分请求。跨机器可在仓库根目录开两个终端，不依赖该脚本内硬编码的 Windows 路径：

```sh
# 终端 1，保持运行
dart tool/web_dev_proxy.dart
```

```sh
# 终端 2
flutter run -d chrome --dart-define=STARFLOW_WEB_PROXY_BASE=http://127.0.0.1:8787
```

代理默认只监听 `127.0.0.1:8787`，提供 `/health` 与 `/proxy`。它开放跨域但没有身份认证，仅用于可信本机开发；不要作为公网转发服务部署。部分转发 headers 以 Base64 放入 URL，Base64 不是加密，浏览器记录和代理访问日志仍可能泄露凭据。

当前 `tool/web_dev_proxy.dart` 的 CORS 方法白名单缺少 `MKCOL`，请求头白名单缺少 `Cache-Control / If-Match / If-None-Match / Authx / Trim-MC-token`。因此现有脚本不等于完整支持 WebDAV 同步或飞牛浏览器联调。遇到预检失败先核对实际请求及目标服务器的 CORS 配置；本文仅记录限制，没有修改代理实现。

## 6. 实用建议

- Android 构建优先先确认 `android/local.properties` 里的 `sdk.dir` 和 `flutter.sdk`
- 如果 `flutter test` 或 `flutter pub get` 很慢，优先先试镜像脚本
- 如果 MuMu 已经开着但 `flutter devices` 仍然看不到模拟器，先运行 `.\scripts\connect_mumu.ps1`
- Web 调试可用上面的双终端命令；Windows 包装脚本需先核对本机路径和 CORS 限制
- 切回官方源需清理已有镜像环境变量，`-UseOfficialSource` 本身不清理
- TV 安装包默认用 `.\scripts\build_tv_apk.ps1` 生成，并直接输出到桌面
- `build_tv_apk.ps1` 与 `build_tv_apk_to_icloud.sh` 内部固定使用 `flutter build apk --release --target-platform android-arm,android-arm64 --android-skip-build-dependency-validation`，单个 APK 仅包含 ARM 32 位与 ARM64，不再构建或打包 `x86_64`，继续保留 `Android 6.0 / API 23` 兼容目标
- 两脚本统一选取 `STARFLOW_FLUTTER_SDK` / 项目 FVM / PATH 中的 Flutter 和同目录 Dart，预检校验锁定 framework/engine、签名私钥可读和静态检查工具。配置 JSON 预检不回显正文，原有 bootstrap 在构建结束或失败时恢复；输入配置先建立独立快照。APK 交付检查包名、内部版本/版本码、双 ABI、配置字节、固定签名及 v1/v2、原生库标记/强符号；静态检查不替代 API23 真机启动。
- `build_tv_apk.ps1` 只会在显式传入 `-SettingsJsonPath` 时临时嵌入配置 JSON
- 当前 TV 显示版本号只保留标准三段式 `主版本.月份.序号`
- 当前 Release APK 启用了 `v1 + v2` 签名，兼容老一些的电视安装器
- Release 通过不入库的 `android/key.properties` 显式配置签名，不再回退自动生成的 debug key；发布工具核对 `config/android_release.json` 中固定指纹。历史安装身份为 Android Debug 证书，需恢复同一把旧 key 才能覆盖升级，并未迁移为新证书。必须卸载时先分别导出应用配置和直播备份，因为卸载会删除本机数据。
- 无 PowerShell 时使用 `ICLOUD_INSTALLER_DIR="$HOME/Desktop" ./scripts/build_tv_apk_to_icloud.sh`，保持 TV 默认交付到桌面；不设此变量时该 Bash 脚本输出到 iCloud Drive 的 `Installers`
- iOS 预设 `scripts/build_ipa_to_icloud.sh` 默认输出到 iCloud Drive 的 `Installers`，固定构建未签名 IPA；未签名包不能直接通过常规 iOS 安装流程安装。TV 与 iOS 只在显式选择相同输出目录时放在一起
- 四个 TV / iOS / Windows 发布预设均调用 `tool/release_version.dart`，可在显式固定批次时传入 `STARFLOW_RELEASE_VERSION=主版本.月份.序号`；省略时继续按月递增。该本地工具读取 `config/release_version.json` 并修改 pubspec，不联网，PowerShell 也需 PATH 中有 Dart
- Windows 安装器默认用 `.\scripts\build_windows_installer.ps1` 生成，并直接输出到桌面
- 这条脚本会先执行 `flutter build windows`，再调用 Inno Setup 生成单个安装器
- 当前脚本会优先在 `E:\Program Files (x86)\Inno Setup 6\ISCC.exe`、`E:\Program Files\Inno Setup 6\ISCC.exe`、`C:\Program Files (x86)\Inno Setup 6\ISCC.exe`、`C:\Program Files\Inno Setup 6\ISCC.exe` 查找 Inno Setup
- Android TV 的 `设置 -> 数据与维护 -> 配置管理` 已切换为局域网传输模式，不再依赖系统目录 / 文件选择器
- 打开后电视会显示访问码、端口和本机地址，手机连同一网络即可直接上传或下载配置
- 关闭传输弹窗后，临时传输服务会立刻停止
- Web 端的 `设置 -> 数据与维护 -> 配置管理` 会直接下载当前配置 JSON，或选择本地 JSON 立即导入覆盖，不需要额外的目录权限或应用私有路径
- iPhone / iPad 的 `设置 -> 数据与维护 -> 配置管理 -> 导出当前配置` 会直接打开系统文件导出器，可保存到“文件 / iCloud / 本机其他位置”
- iPhone / iPad 的配置导入继续走系统文件选择器，不需要手填应用私有目录路径
- `设置 -> 数据与维护 -> 日志` 可以控制本地日志开关、最大容量和记录/展示级别；默认容量为 `20 MB`，默认记录 `INFO / WARNING / ERROR`，高频 `TRACE` 仅在排障时手动开启
- 为避免大批量预取产生噪音，成功的 TMDB 缓存命中、加入已有请求和空 sidecar 上下文不会逐条写入 `TRACE`；真实请求、失败及阶段结果仍保留
- 日志预览读取最近 `300` 条并展示筛选后的最新 `100` 条；TV 端支持焦点进入固定预览区域并上下浏览
- TV 的配置传输和日志导出都会显示完整局域网地址与二维码；手机和电视连接同一网络后可直接扫码
- IO 平台导出的日志会合并当前、上一份轮转文件和可用的 Android 原生日志，并隐藏常见 Cookie、Token、密码和授权信息；Android 系统历史退出捕获依赖 API 30+，API 23 仍有本地原生日志。Web 使用文件日志 stub，不具备同样的文件预览和导出能力
- 如果要管理夸克当前保存目录或删除目录内文件，先确认夸克 Cookie 仍然有效
- 当前目录删除走夸克回收站语义，不是应用侧永久粉碎
- 如果启用了“同步删除夸克目录”，命中已选 `WebDAV` 监听目录的删除成功后还会继续请求一次夸克目录删除接口；同样走回收站语义
- 如果 `WebDAV` 删除在服务端回了 `2xx`，但父目录复查仍能看到目标文件/目录，或复查请求失败，应用会把它当作结果未确认处理，不继续 115 删除或清理本地索引

## 7. 在线元数据相关请求

当前仓库除了依赖下载，还会在运行期访问这些在线元数据 / 图片服务：

- `TMDB`：标题匹配、人物 / 公司作品、`poster / backdrop / still / profile / logo` 图片与 `TMDB` 评分
- 其中人物头像使用 `profile`，详情页公司 Logo 使用 `production_companies.logo_path`；当前不再把 `networks` 当作公司 Logo 展示
- 详情页公司 Logo 位于资源信息之后的页面底部，使用带柔和高对比度背景卡片的单行横向列表，超出可视区域时由用户左右滑动查看，TV 端每个 Logo 也提供独立焦点目标和轻微放大提示；列表布局本身不增加网络请求，点击 Logo 后才发起公司作品查询
- `WMDB`：中文资料、豆瓣 / IMDb 评分标签与外部 ID 补全
- IMDb 是 NAS 索引的可选链路，`imdbRatingMatchEnabled` 默认关闭，详情不订阅该开关。开启后保留原建议接口及 `https://datasets.imdbws.com/title.ratings.tsv.gz`；数据集请求沿用 metadata guard 的 6 秒期限、按主机熔断及运行期代理，并补充覆盖正文的中止与 32 MiB 上限。下载和后台解压索引共享一次 Future，失败释放以供下次请求，不增加自动重试。展开上限 128 MiB、400 万行、单行 256 字节；只保留 TSV 字节和行偏移，不常驻压缩副本或每行对象。Web 的 compute 不提供独立 isolate，不据此声称 Web 解析已离开 UI 线程
- 豆瓣：兴趣、推荐、片单、轮播等发现内容，以及按条目 ID 读取 `rating.count` 的详情人数

`TV` 模式下新增的这些交互也会继续命中同一批网络能力：

- 首页 `Hero` 和详情页会根据屏幕横竖方向切换横版 / 竖版 artwork
- 首页 `Hero` 对信息不全且没有已刷新成功 / 失败标记的条目，会在启动后的后台做一次 best-effort 元数据刷新；刷新结果和状态会写回本地详情缓存，避免应用每次启动重复请求
- 详情页人物关联影片页会访问 `TMDB` 人物作品接口；公司作品页会直接使用详情数据里的 `TMDB` 公司 ID，通过 `discover/movie` 与 `discover/tv` 的 `with_companies` 参数读取电影与剧集作品。公司页每次只请求当前页的电影与剧集结果，读取 `total_pages` 驱动上一页 / 下一页并合并展示，不预取其他页；切换最新 / 最旧 / 评分排序时重置到第 1 页，并把对应 `sort_by` 交给 `TMDB`，`TMDB` Discover 的第 500 页上限会同步作为分页边界。导演 / 演员继续只请求一次人物作品接口，在网络结果之后本地排序筛选并按每页 40 条切页，翻页与排序不追加请求
- 关联作品卡片右上角的类型角标直接复用同一批作品结果里的 `genre_ids`，不会为了标签再额外请求作品详情
- 导演 / 演员作品页的排序与类别筛选基于已经拿到的完整结果在本地完成后再切页；公司作品页的类别筛选作用于当前页，排序由 `TMDB` 服务端分页结果决定
- 搜索页最近搜索词和来源记忆保存在本地，不新增服务端依赖
- 搜索页顶部来源按钮现在只是统一了本地容器高度与通用按钮样式，不涉及新的搜索接口或筛选协议
- 页面焦点居中滚动属于本地滚动与焦点管理，不依赖额外接口
- 设置编辑页的 TV 文本弹窗只在本地写回控制器，不额外请求服务端
- 配置管理页会在局域网内临时开放一个仅当前会话有效的 HTTP 地址，用于配置上传和下载

开发联调时如果这些服务需要代理，除了构建代理外，还要确认应用运行环境本身能访问外网。

如果 TV 端局域网传输页已经弹出，但手机仍然无法访问，优先检查：

- 手机和电视是否连接到同一个局域网，且路由器没有开启 AP 隔离 / 客户端隔离
- 电视端当前显示的 IP 是否是可访问的局域网 IPv4 地址
- 设备或系统是否限制了明文 HTTP 局域网访问
- Android TV 构建是否已经包含 `INTERNET`、`ACCESS_NETWORK_STATE` 与明文流量支持

和元数据最直接相关的本地设置有：

- `设置 -> 元数据 -> 元数据匹配 -> TMDB Read Access Token`
- `设置 -> 元数据 -> 元数据匹配 -> 启用 TMDB 自动补全影片信息`
- `设置 -> 元数据 -> 元数据匹配 -> 启用 WMDB 自动补全影片信息`
- `设置 -> 元数据 -> 元数据匹配 -> 自动匹配本地资源`
- `设置 -> 内容与来源 -> 媒体源管理 -> 详情页匹配来源`
- `设置 -> 性能与后台 -> 任务调度 -> 最大并发任务数 / 首批数量 / 后台批次间隔 / 交互结束后恢复时间`

“最大并发任务数”同时供首页、元数据、Emby 和 NAS / WebDAV 各级调度读取；NAS 内部仍将来源刷新封顶为 `2`、集合与单源补全封顶为 `4`，在线 metadata 条目还需获取全局 metadata permit。目录结构推断出的剧集只使用剧名发起系列匹配，同剧各集复用 provider 的 in-flight / resolved cache，避免将季集文件名重复发送给 `WMDB / TMDB`。

Emby 来源刷新时，每个媒体分区也会作为 maintenance 任务进入这个全局并发器。这类显式刷新优先于普通后台补全，但不会超过“最大并发任务数”，避免 Emby 所有分区与 NAS 补全同时堆叠网络请求。

界面、播放和网络调度设置分别保存，不会互相改写。默认元数据批次间隔为 `300ms`、交互恢复时间为 `400ms`；首页或媒体库的“内容加载中”只会在状态首次进入时申请一次暂停，不会因重复构建持续推迟网络补全。

详情评分人数与豆瓣评分使用同一请求：`https://m.douban.com/rexxar/api/v2/movie/{id}?for_mobile=1` 的 `rating.count`；该请求复用豆瓣网络熔断、代理和可选账号 Cookie。自动获取由缺豆瓣评分或新匹配豆瓣 ID 触发，不再由人数缺失单独触发；已有评分但无人数时不会为人数反复请求。手动更新影片信息在元数据匹配后按最终豆瓣 ID 请求一次，同时更新评分与人数。豆瓣列表已有的 `rating.count` 直接复用，不额外请求详情。成功取得的人数会写入详情缓存，并在 resolver 路径写回媒体缓存或本地索引；首页与媒体库入口通过批量缓存合并直接恢复。请求失败或响应没有有效人数时保留已有评分和人数，无缓存人数则隐藏，不使用 WMDB `doubanVotes` 等回退。

如果详情页图片、评分或人物关联影片页为空，优先先检查：

- `TMDB Read Access Token` 是否已填写
- 当前网络或代理是否能访问 `api.themoviedb.org` 与 `image.tmdb.org`
- `WMDB / 豆瓣` 相关站点是否被本机网络策略拦截

和手动元数据更新相关的当前行为：

- 详情页“手动更新信息”会无视当前是否已有标题、简介、图片或外部 ID，直接重新搜索在线元数据
- 只要搜索命中，当前详情缓存就会被命中结果直接覆盖
- 手动索引管理页在应用匹配结果时，也会把 `IMDb ID` 和 `TMDB ID` 一并写回本地索引与详情缓存
- 详情页评分标签会在本地按来源归一去重并固定按 `豆瓣 -> IMDb -> TMDB` 排列；`豆瓣 / IMDb / TMDB` 各最多保留一条，这一步只影响缓存合并与展示，不新增网络请求
- “匹配来源”会直接限制详情页本地资源匹配时实际访问的 `Emby / 飞牛影视 / WebDAV / Quark` 来源；如果没有单独勾选，则默认使用全部已启用来源
- 删除某个已匹配 `WebDAV` 资源后，详情缓存只会精确失效这条资源相关的本地匹配关系；影片本身的在线详情信息和其他候选资源不会因为这次删除被整批清空
- 如果详情缓存里恢复到的是剧集下的某个单集或文件资源，页面仍会保留原来的剧集结构上下文；这一步直接复用本地缓存，不需要额外发请求去重建季/集结构

和搜索来源相关的当前行为：

- `设置 -> 内容与来源 -> 搜索服务管理 -> 搜索来源` 只决定搜索页展示哪些本地媒体源与在线搜索服务 tab
- 这里的本地媒体源现在包括 `Emby / 飞牛影视 / WebDAV / Quark`；其中 `Quark` 只会在已经选定根目录后参与搜索
- 如果设置里没有单独勾选任何来源，则搜索页展示全部已启用来源 tab
- 搜索页来源 tab 支持多选；实际请求只访问当前选中的 tab，“全部”会访问所有当前可见来源
- 设置变更后会保留仍然可见的已选 tab；如果保存的 tab 已全部失效或被隐藏，则回退到“全部”
- 详情页“搜索在线资源”会等待搜索页保存的 tab 选择恢复完成，再用预填片名自动请求，因此不会在初始化期间误搜未选中的可见来源
- 配置夸克 Cookie 时，每条去重后的在线夸克结果会请求分享 token，再用 `_size=1` 读取一次分享内容首页，避免“token 可用但内容已失效”的假阳性，不遍历完整文件列表；并发复用设置中的“最大并发任务数”，两步合计最多等待 `8s`。无需验证的结果先提交，夸克 / 115 验证结果逐步补入；明确死链不会进入列表，超时、握手失败或限流不会触发重试风暴，也不会误丢结果；用户保存时仍重新获取 token 和文件列表完成最终校验
- 搜索同分享去重在本地按已知网盘类型和分享码完成，不访问重定向或扫描文件内容。相同身份和凭据的跨来源链接只验证一次；仅当后来来源补齐原本缺失的接收码时再次只读验证，若旧验证仍在途则等待其结束，不并行验证同分享。不覆盖已有冲突接收码，不写入日志中的分享码或密码，不改变转存行为。

## 8. 在线字幕相关请求

处理与播放器能力矩阵见 [字幕链路](subtitles.md)。字幕凭据保存在本地设置或构建配置，不代表已经验证真实账号额度。

当前应用内在线字幕链路的要点：

- 在线字幕来源由 `设置 -> 播放 -> 字幕` 统一控制；当前支持 `ASSRT / OpenSubtitles / SubDL`
- 字幕设置里的“在线字幕优先语言”提供 `简体中文 / 繁体中文 / 英语 / 日语`，只影响在线字幕搜索/下载排序；播放默认使用独立的单选设置，默认双字幕还可分别选择主/副语言
- 播放开始时的自动选轨不增加网络请求：先读取全局“默认字幕”，指定语言或双字幕不可用时回退系统语言，再按片源 Forced / Default 标记收尾；“默认关闭”会跳过自动选轨。某部剧的手动选择只从本地播放记忆读取并优先于全局默认
- 字幕语言代码、三字码和发布组常用简写的识别完全在本地完成；会同时读取轨道 language 和标题，不为 `chs / cht / eng / jp / jpn` 等别名发起额外查询
- 独立字幕搜索页和播放器页里的“在线查找字幕”复用同一个仓库实现
- 默认结构化搜索基于可用的文件路径、哈希、大小、`IMDb ID / TMDB ID`、季集、年份和标题；哈希只读取可访问的本地文件，不下载整部远程媒体计算哈希。编辑关键词后不再使用旧影片身份。搜索阶段只读取元数据，点选才下载和验证文本或 ZIP 字幕
- 结构化源当前会按来源分别访问：
  - `ASSRT API`：`https://api.assrt.net/v1/sub/search`、`/detail`
  - `OpenSubtitles`：`https://api.opensubtitles.com/api/v1/login`、`/subtitles`、`/download`
  - `SubDL`：`https://api.subdl.com/api/v1/subtitles`
- `ASSRT` Token 当前保存在设置页；未填写时不会启用 `ASSRT` 字幕源
- `OpenSubtitles` API Key 当前通过 `--dart-define=STARFLOW_OPENSUBTITLES_API_KEY=...` 注入；账号密码保存在设置页
- `SubDL` API Key 当前直接保存在设置页
- `ASSRT` 结构化链当前只会访问官方 API：`https://api.assrt.net/v1/sub/search`、`/detail`
- 多字幕源搜索并行执行，每来源最多等待 `30s`；`OpenSubtitles` 登录态缓存 `15min`，避免同一轮搜索里重复登录
- OpenSubtitles 搜索不调用 `/download`；结果保存文件 ID，点选才申请链接。登录返回的主机名补全 HTTPS 与 `/api/v1`；下载授权遇 401 重新登录一次，406/429 明确显示额度/频率错误，不重试消费额度请求
- SubDL 不支持的哈希查询会跳过，IMDb/TMDB 查询不混入 `film_name`；相对 ZIP 链接以 `https://dl.subdl.com/` 解析
- 只有播放器页和独立字幕搜索页手动触发搜索，设置“单次最多结果数”控制数量，结果初始状态为待下载而非已验证；页面请求代际检查会丢弃迟到结果，不保证取消共享客户端已经发出的网络请求
- 下载验证管线使用 `30s` 期限与 `16 MiB` 响应体上限；OpenSubtitles 点选后的下载授权是此前独立的等待阶段，不能保证整个点击流程在 `30s` 内完成。ZIP 解析在后台 isolate，最多 256 项、声明总量 64 MiB、单文件实际输出 16 MiB，验证 CRC 与文本格式后写 UTF-8
- 下载缓存写入 `starflow/online_subtitles/download-*`，不复用旧下载链接；旧会话、旧验证缓存和旧 native 偏移缓存都纳入本地存储统计/清理，下载时清理超过 7 天的缓存。已挂载 MPV 文本与 Android 独立播放副本不依赖下载缓存
- 如果在线字幕来源被全部关闭，则不会发起这类请求
- Android `TV` 从原生播放器进入独立字幕搜索页时，会保留当前 `query / title / input`，因此后续手动搜索会沿用当前片名或剧集搜索词，不会再以空查询打开

## 10. 本地匹配与凭据边界

- 当“详情页自动匹配本地资源”关闭时，进入详情页不会自动触发本地资源匹配，只能手动点击“重新匹配资源”
- 如果详情页已经恢复到已匹配资源，重新进入时也不会再次自动匹配本地资源
- 本地资源手动匹配采用并发搜索；某个源先返回时会先展示该结果，但其余搜索源仍会继续完成
- 如果一次手动匹配命中多个本地资源，候选列表和当前选中项也会一并写入本地详情缓存
- 完整候选和当前选中项会一起写入详情缓存；再次进入时由本地状态恢复“本地资源”来源及该来源内的“播放版本”，不新增额外请求
- 跨来源候选只进入“本地资源”来源选择；只有当前来源内存在多个可直接播放文件时，Hero 下方才显示“播放版本”。`movie` 和单集等叶子项都走这条本地派生与切换路径，不新增额外网络请求
- 外部 ID 强匹配只要求任一已知 ID 命中；详情页展示的命中原因会按实际命中的 `IMDb / TMDB / 豆瓣 / TVDB / Wikidata` 组合输出，不表示必须全部同时命中
- 豆瓣等在线详情如果此前已经缓存过本地资源命中结果，重新进入详情页时会直接复用缓存中的资源状态、播放信息和多候选资源选择状态
- 如果恢复到的本地命中项本身是单集或文件，详情页仍会继续保留剧集结构目标和季/集浏览区；这是本地缓存恢复行为，不新增额外网络请求
- 退出详情页时，当前页的本地资源匹配会话会立刻失效；未启动的后续来源任务不会继续执行

配置导出、手动 WebDAV 配置快照和显式嵌入安装包的设置 JSON 可能包含明文账号、密码、Token 和服务地址。115 Cookie 单独保存在本机偏好中、不进入设置 JSON；这不等于使用系统 Keychain / Keystore 加密。收藏同步文件虽然不包含整份设置，仍可能携带播放地址、鉴权头和分享提取码。只同步到可信存储，不把这些文件、嵌入配置的 APK 或原始日志提交到公开仓库；日志脱敏也不能替代分享前检查。
