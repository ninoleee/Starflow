# TV 焦点清单

核对日期：2026-09-24。本文记录当前工作区的焦点边界与本轮修复，不代表真实遥控器／输入法验收通过。组件职责以 [架构说明](architecture.md) 为准，网络影响见 [开发网络](development-network.md)。

## 公共规则

- `TvRemoteShortcuts` / `TvRemoteKeyHandler` 统一返回、确认和菜单命令：按下记录、消费重复、配对松开执行一次；焦点中途移走、失活、合成松开和销毁取消待执行动作。共享按钮、海报、弹窗、MPV 页面、详情预览、元数据编辑和直播覆盖层复用，应用入口对 TV 提供标准返回／确认快捷键兜底。方向导航和左右 seek 仍允许连续输入。
- Tab 只保留两类共享语义：`StarflowSingleSelectTabBar` 负责互斥选择，`StarflowMultiSelectTabBar` 负责集合勾选；两者复用相同视觉、焦点和圆角。普通 `StarflowChipButton` 继续用于动作、独立筛选或非 tab 控件，不再由各页面自行拼接 tab 样式。
- 普通禁用控件退出寻焦，包括 Flutter `NavigationMode.directional`。只有显式 `focusableWhenDisabled` 的忙碌操作／边界分页保留焦点，`onPressed == null` 时确认无效。
- `TvPageFocusScope`、方向面板与全局安全 Action 共享未布局候选保护。普通寻焦沿用 Flutter；不另建坐标排序、全局焦点缓存或逐帧恢复。
- `scheduleTvFocusRecovery` 只做一次帧末检查并主动安排帧；页面失活、路由被覆盖、目标卸载／禁用或已有可操作焦点时不抢焦点。
- `TvTextInputLauncher` 统一松键后打开编辑器，等待／打开期间拒绝重入，松键前移走焦点则取消。输入框只局部处理上下键离开；返回先到有效操作按钮，再次返回关闭。
- 轻量焦点是绘制与重绘优化，不是全部取消缩放。共享控件自身 State、海报 ValueNotifier 分别更新外观；默认可见性滚动不等同于强制居中。
- Hero 自动轮播的旧持焦页在交接前通过焦点感知的 keep-alive 保留，避免惰性回收触发 scope 历史焦点恢复到下方模块；交接后释放保留，用户主动移焦仍暂停轮播。回归覆盖先访问下方模块再返回 Hero、五张卡片连续两轮、普通／无边框与动画／简化模式。
- 2026-09-25 起，共享文字／图标按钮在 TV 的页面与弹层统一使用低亮度主按钮底色，白色描边仅表示焦点；首页编辑的开启状态继续由文字和开关图标表示，避免浅色强调色与焦点混淆。非 TV 配色不变，覆盖入口见 `test/core/widgets/tv_dialog_button_style_test.dart`，主机验证记录见 [performance.md](performance.md)。

## 直播焦点边界（2026-09-20）

- 直播返回键在当前路由消费完整的 KeyDown / KeyRepeat / KeyUp 周期：2026-09-22 起，菜单关闭与退出播放器均等待匹配的 KeyUp；进入后台取消待松键意图。播放器不能先退场后让松键落到主界面，再触发一次系统返回。`live_tv_page_test.dart` 使用 GoRouter 宿主检查三类叠层的按键处理结果、焦点恢复和播放会话保留；`live_navigation_resume_test.dart` 保留菜单栏打开的真实播放器，mock Android 平台视图通道，检查长按与系统返回只回频道页、不弹退出 App 确认。这是主机组件回归，真实遥控器仍需复验。

- 播放器无底栏，顶部固定 112dp，右上角设置按钮／菜单键按需打开独立全屏设置。频道列表、节目单和播放选项均在设置中，不提供上一／下一频道按钮；画布上下键仍换台。设置打开后聚焦 `live-settings-close`，方向键寻焦而不换台；设置期间禁止自动收栏，返回关闭设置并恢复画布。音轨弹窗和线路下拉仍优先处理返回。

- 一级导航保持原有五个分支索引，直播追加为索引 5；已有菜单配置不强制插入直播，隐藏状态不产生侧栏焦点。设置“内容与来源”仍有直播和订阅入口。路由索引不等于可见菜单索引。
- 频道页使用 `TvPageFocusScope`，数据就绪后以订阅按钮为首焦点，空频道列表仍可进入订阅；初始数据库加载态只有进度指示，读取失败提供重新读取按钮，不能宣称所有异步阶段都有常驻页头焦点。搜索与频道映射复用 `SettingsTextInputField` 的 TV 松键后编辑机制。
- 订阅页 AppBar 的添加按钮在加载/错误/空列表时仍存在；编辑页名称首焦点，保存中保焦但不执行重复提交。删除确认默认取消。`LiveIconButton` 固定 48dp、带 Tooltip/语义标签，显式 `focusableWhenDisabled: true`；更新忙碌及本地源无可更新地址时仍可聚焦、确认无效。下拉框、FilterChip 和 Switch 沿用 Flutter 控件，不能将自定义按钮的重复按键契约泛化为已测的所有控件行为。
- `LivePlayerPage` 初始焦点落在 `live-player` 画布。仅当它持有主焦点、且未打开频道／节目单／设置时，上下/频道键才循环换台，长按允许重复输入，由播放控制器的 180ms 窗口合并开流；确认/左/右/菜单在配对 KeyUp 执行一次打开命令。确认打开频道、左打开频道/分组、右打开节目单，菜单打开播放设置并帧末把焦点移到 `live-settings-close`。
- 频道叠层左侧分组、右侧频道，每次打开切回当前播放频道所属分组并滚动、聚焦当前频道；当前频道不可见时回退首个可见频道，空列表落到全部分组。TV 不显示关闭按钮及标题整行，上下键列内移动，首项向上保持焦点，返回键关闭；非 TV 保留页头。左右键跨列，右列返回左列时定位当前分组。分组获焦或点击只筛选列表，确认频道才选台，画布上下换台仍遍历全部可见频道。节目单叠层仍默认聚焦关闭按钮，不自动定位当前节目；节目项确认打开简介弹窗，关闭按钮首焦点，不触发回看或 seek。
- 子控件持有焦点时，画布处理器忽略方向键，防止移动叠层焦点时意外换台。Android `AndroidView` 使用 `ExcludeFocus`，原生 root/TextureView 均不可聚焦；两内核共用 Flutter 交互，不套用点播 Exo 的原生 RemoteController 测试结论。
- 返回先由顶部弹窗/下拉菜单处理，再消费频道／节目单／设置共用的播放器本地返回记录并恢复画布；再返回退出播放。系统返回和页面 `Navigator.pop` 均先关闭局部界面，遥控器长按重复事件不再次退出。自动隐藏为 5s，但只有当前路由且画布持主焦点时隐藏；设置、叠层及弹窗操作中不应被计时器移走焦点。频道叠层先按固定行高定位，再在惰性行挂载后聚焦；节目单打开后帧末聚焦关闭按钮。选择频道和关闭叠层恢复画布，其他弹窗依赖 Flutter 恢复，须单独设备复验。
- 失败重试按钮有 autofocus；需在真实遥控器上验证确认、返回、菜单能否离开失败态。主页面刷新引发频道消失/重排、关闭来源和切换内核后的焦点恢复不应只凭稳定 key 推断通过。

TV 直播文件导入复用配置/日志传输的二维码地址组件，弹窗初焦点为“关闭服务”，地址项可聚焦并滚动到可见范围；返回立即停止接收，进入后台同样关闭，不自动重新开放端口。收到文件返回编辑草稿，用户保存后才入库。TV 不再打开系统文件选择器。

验证边界：2026-09-20 五任务合并后指定 9 文件/132 项 Flutter 测试通过，包含导航、旧菜单保留、旧分支索引、7 项直播页面测试。320/390/1280 宽度组件布局已检查，播放器使用 fake engine，不证明真实画面输出；该批早于后续扫码导入修改。记录见 [主机验证](performance.md#2026-09-20-直播前置验证快照)，真实遥控器、TV IME、手机扫码上传与原生 TextureView 未测，设备对照见 [直播验收清单](performance-device.md#直播双内核对比验收2026-09-20)。

## 本轮修复

- 2026-09-28 豆瓣选片连续加载（现行）：移除手动翻页，距底部约一屏半时后台预取紧邻下一页，滚动接近底部或末排海报获得焦点时追加；追加结果与旧海报连续显示，不替换列表、不跳回顶部、不抢当前焦点。接入点在加载期间只发一次请求；空批次、末页或重复条目停止追加。失败保留现有内容并关闭自动重试，底部“重试”从前一批末尾继续。手动刷新会清除当前条件的全部分页缓存，避免旧下一页混入。主机测试覆盖预取不提前插入、触底复用、去重、TV 末排转接、失败重试、空批次和旧请求丢弃。真机滚动和长列表性能仍待验收。
- 2026-09-28 海报网格纵向寻焦修正（现行）：惰性 `SliverGrid` 的第二次跨排方向键不再交给默认几何遍历，而是按当前列数显式计算上一排／下一排。目标排已布局时直接聚焦并滚到可见；尚未布局时先滚动一排再于帧末重试。首排向上交回筛选区，末排向下消费按键并继续追加；连续两次向下、两次向上回首排、再次向下均有主机回归。
- 2026-09-28 豆瓣页码指示（现行）：右侧中部悬浮两行数字，上一行是当前可视页，下一行是总页数；无文字、斜杠或按钮，也不注册焦点。当前页按网格首排索引计算，追加后滚回旧结果会下降。主机测试覆盖首屏、追加后滚到底为第 2 页、回到顶部恢复第 1 页和纵向顺序。
- 2026-09-28 Tab 单选与多选统一（现行）：单选 `StarflowSingleSelectTabBar` 用于发现页模式／类别、媒体库筛选、演职员排序／类别／类型、Hero 展示方式、元数据优先来源、搜索网盘类型／清晰度和选集季；多选 `StarflowMultiSelectTabBar` 用于搜索来源、字幕来源和日志级别。单选只保留一个值并支持可选空值；多选支持叠加、取消、最小／最大数量和可选勾选。两者共用 `18dp` 圆角、透明未选项、强调文字、轻量同色底、底部指示条、等宽／换行／横向滚动布局和独立白色焦点框。发现页第一行居中，第二行采用更小尺寸并靠左；类别 tab 按下直接聚焦年份，筛选 Wrap 内任一入口按下直接聚焦排序，排序按下直接聚焦首排海报。历史、面包屑和工具入口继续使用普通 Chip。
- 2026-09-28 发现页模式焦点（现行）：TV 保存为“选片”后首次进入会在挂载完成后聚焦“选片”标签；在“搜索／选片”之间切换时，选片模式回到标签，搜索模式回到查询入口，不再留下无可见焦点状态。“选片”标签向下显式进入当前电影／电视剧／综艺类别，避免右侧标签按几何顺序总落到“综艺”。相关主机回归见 [性能与回归验证](performance.md#2026-09-27-豆瓣选片主机验证增量)。

### 十方向复审 T01–T04 修复（2026-09-20）

- 点播 MPV 使用独立 `PlaybackPlayIntent`、`PlaybackPauseIntent`、`PlaybackToggleIntent`，媒体键不再借用 `ActivateIntent`。Play/Pause 分别是幂等方向命令，确认仍激活当前工具；按住媒体键不重复执行。
- `TvFocusableAction` 的 TV 分支统一处理 pointer 主点击、右键及长按。主点击请求当前控件焦点；子控件自己的手势通过 Flutter gesture arena 优先处理，不重复调用外层按钮。禁用按钮不响应 pointer。
- 仅有 `onContextAction` 或 `TvMenuButtonScope` 时注册局部菜单快捷键与 Action；没有 handler 时让页面菜单处理，不吞掉播放器选项菜单。局部 handler 优先于 scope。
- 搜索历史横排与非 TV 来源横排按实际 text scaler 的行高、垂直 padding 和最大焦点边框计算高度，并保留上下 6dp 空间。共享 chip 的边框布局宽度固定为 3dp，聚焦不再改变内容高度；长文案保持单行省略而非压低行高。
- 新回归入口：`tv_playback_input_test.dart` 覆盖四类工具焦点、三种媒体命令、重复事件、菜单回退、pointer/长按/禁用及嵌套手势；`search_page_text_scale_test.dart` 覆盖 1.0/1.3/2.0 字号、长文案、390dp 手机和 1280×720 TV 几何与聚焦尺寸稳定性。设置 `STARFLOW_LAYOUT_SCREENSHOTS` 可输出本机截图；不把主机字体截图当作真实 TV 验收。
