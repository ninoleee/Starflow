# 阿里保存与可选转 115

实现核对：2026-09-26。当前提供应用内直接秒传；默认消费版不依赖 OpenList、小雅或外部中转服务，可选的阿里开放平台登录模式仅使用 OpenList 官方授权服务换取 Token，不上传文件正文。主机协议模拟测试不等于真实账号联调。

## 使用入口

1. 在“设置 → 内容与来源 → 网盘与转存 → 阿里云盘”选择默认消费版模式或开启“使用阿里开放平台 OAuth”后点击“扫码登录”，再使用阿里云盘 App 扫码确认。消费版模式仍可手动填写 Refresh Token；开放平台模式也可手动填写 Open Refresh Token。两种 Token 不是同一种凭据，必须使用对应模式。Token 只在当前设备保存，不发送给他人。
2. 默认点击搜索资源的保存按钮只保存到阿里，不要求配置 115，不删除任何文件。保存到所选阿里目录下的搜索词或收藏保存名目录，内部保留分享结构；重复保存核对同名文件 SHA1 和大小，相同则略过，不同则停止且不覆盖。
3. 需要跨盘时，在“115 网盘”配置 Cookie 和保存目录，再到“阿里云盘”开启独立开关“保存时转到 115 并删除阿里副本”。该开关默认关闭，保存到设置 JSON 并支持导入导出。
4. 开关开启后，搜索保存直接转 115，不再弹出逐次确认框。全部成功并校验通过后自动清理本次阿里暂存文件；关闭后恢复仅保存到阿里。不会清理此前单独保存的文件、分享者原文件或阿里回收站。

## 扫码登录

- 消费版二维码直接来自阿里官方消费端接口，没有第三方 Token 中转服务。支持等待扫码、手机确认、过期、取消及手动刷新；轮询间隔 2 秒，本地有效期最多 2 分钟，显示倒计时。TV 二维码为 360 逻辑像素，手机 256；进入后台暂停，返回前台核对期限继续查询。瞬时网络错误最多重试三次，间隔 2/4/6 秒。
- 内置开放平台模式调用 OpenList 官方授权服务 `api.oplist.org/alicloud2/...` 的生成二维码、状态查询、用户信息和刷新端点，在服务不可达时回退同接口的 `api.oplist.org.cn`，再以返回的 Open Access Token 访问 `openapi.alipan.com` 的 `openFile` API。第三方 Client Secret 留在服务端，不写入 Starflow；Open Refresh Token 和消费版 Refresh Token 分槽保存，普通设置 JSON 只保存模式，导入导出不带任一 Token。该模式依赖 OpenList 授权服务可用性，真实账号仍需设备联调。
- 退出扫码页面后停止后续轮询；已发出的请求可能完成，但迟到结果和旧二维码结果不再触发登录。确认后的 Refresh Token 交给既有登录客户端验证消费版设备会话，成功后保存最新轮换值；失败、取消或验证期间账号被其他操作更改时，不替换原账号。
- 扫码和手动新凭据均验证后替换；正常 Token 轮换保留原目录。阿里用户 ID、115 已验证 Cookie 的 UID 用于账号绑定；夸克暂以凭据指纹保守绑定，Cookie 变化会要求重新选择目录。换账号或无法确认旧账号身份时，解除旧目录并关闭该盘同步删除，保留公共配置与任务名。不自动重新开启删除。
- 三盘转存凭据及本机账号状态通过 `flutter_secure_storage` 存储，iOS/macOS 使用 Keychain，Android 使用 Keystore 支持的加密偏好；Android 禁止应用备份，避免恢复密文但缺少设备密钥。Web 使用插件的浏览器实现，不等同设备 Keychain。迁移先写入并读回核验，再移除旧明文项；安全存储不可用时失败，不回退明文。设置 JSON、导出、导入和 WebDAV 配置同步不携带或替换三个网盘的本机登录；其他媒体源或 WebDAV 连接凭据不属于本次迁移。
- iPhone 支持显式确认后将二维码 PNG 写入相册，只申请添加权限，不读取照片。二维码是临时登录凭据，不应转发，使用后删除相册副本。阿里 App 从相册识别的兼容性尚未真机验收，不承诺同机登录必定成功。
- 2026-09-26 已验证官方匿名二维码生成及 `NEW` 轮询响应，完整手机确认、风控和设备授权尚未使用真实账号验收。

## 设置归属

| 设置 | 单独保存到阿里 | 开启转 115 |
| --- | --- | --- |
| 保存目录 | 阿里独立配置 | 115 配置 |
| 名称修正规则 | 通用规则 | 通用规则 |
| SmartStrm 任务名称 | 阿里任务 | 115 任务 |
| WebDAV 同步删除监听 | 阿里监听与保存目录 | 115 监听与保存目录，暂停阿里监听 |
| Webhook、STRM 延迟、刷新媒体源与延迟 | 复用现有公共配置 | 复用现有公共配置 |

公共配置集中在“网盘与转存 → 通用设置”，阿里、夸克与 115 单项页不再重复放置入口。配置仍使用原 JSON 字段，不要求迁移；各编辑页仅提交自己所属的字段，STRM 测试使用最新公共 Webhook 与延迟。

名称规则只在“通用设置”配置一套自动修正开关和移除字符，夸克、115 与阿里单项页不再提供独立开关或字符。旧单项字段仍参与 JSON 读取和导出兼容，但不再决定实际改名；通用关闭或字符留空均不改名。保存、去重、名称后处理、检查更新和阿里转 115 统一读取该规则，阿里转 115 上传前完成名称修正后不重复执行后处理改名。阿里预览在未指定资源子目录名时也比较现有内容，与实际保存去重一致。

- 阿里提供目录选择、目录浏览、单项删除和清空当前目录；手动删除需确认，文件移入回收站。
- 同步删除默认关闭。按所选 WebDAV 监听目录的相对路径匹配，支持 `.strm` 对应唯一视频；空监听、保存根目录、歧义或多网盘监听重叠拒绝删除。WebDAV 删除成功后才删除阿里目标，失败不清理本地索引。
- 详情页“检查更新”按当前保存模式比较阿里或 115 目标目录，不复制、删除或触发 STRM。名称修正后冲突直接拒绝保存。
- 配置阿里凭据后启动搜索验链，仅请求分享授权和目录第一页，最多等待 8 秒，不使用或轮换账号 Token，不依赖 115 Cookie。明确分享错误或空目录排除，网络、登录或格式异常保留为暂未验证。
- 分享授权接口返回已知 `ShareLink.* / ShareLinkPwdInvalid` 错误时按“分享失效或提取码错误”处理；点击保存会停止在转存前并提示重新搜索。无密码分享不发送空 `share_pwd` 字段，避免把无密码链接误判为授权不完整。
- 公开样例实测表明 `/adrive/v3/file/list`、`/v2/file/get` 和 `get_by_share` 都可能不返回分享文件 SHA1，因此分享列表只校验文件 ID、名称、类型和大小，允许 SHA1 暂缺。转 115 时先把分享文件复制到自己的阿里暂存盘，从拥有者副本元数据读取并核验 SHA1，再提交 115 秒传；不会用分享详情里不存在的哈希猜测文件内容。

## 行为与限制

### 任务记录与恢复

- “阿里云盘 → 转存任务与暂存清理”展示阶段、更新时间、暂存目录、文件和清理数量。停止操作在当前请求完成后阻止下一步，保留副本；退出应用后可从同一记录继续。没有后台保活，继续需要应用前台运行。
- 本机偏好中保存任务清单、分享地址/提取码、阿里/115 账号身份、暂存与目标文件信息，不保存网盘登录凭据、Webhook 或整份配置。任务记录不参与设置同步，包含私有资源信息，应保护本机数据；最多保留 200 条，可经确认移除记录，不会因此删除云端文件。
- 恢复绑定原两端账号和原目标目录，保留原名称修正结果，复用已确认暂存副本，并查询校验目标。目录身份变化、账号不符、暂存身份变化时拒绝继续。后处理读取当前配置；跨盘仍只使用 115 任务与规则，不重复改名。
- 分享树快照允许暂缺 SHA1（含空 `content_hash` 配合 `content_hash_name=sha1` 的旧记录），但拥有者副本快照仍必须有有效 SHA1，并核对暂存父目录、大小及已有源哈希。恢复和仅清理用副本记录中的哈希核验 115；已清理项仍保留哈希回执，不再复制、上传或重复删除。未知上传结果只有目标已出现且内容校验通过才继续，否则停止，不自动重放。
- 复制、上传和清理在请求前写入意图。复制返回不明且无已确认 ID 时停止，不能靠目录名前缀猜测文件；上传返回不明且目标未出现时不重放。删除返回不明时只查询原 ID，确认已不在目录后记录完成，否则保留并提示人工检查。
- “核验并清理副本”需要再次确认，先验证整批 115 目标，再按任务内记录的阿里文件 ID、父目录、名称、大小和 SHA1 复核并移入回收站。不复制、不上传、不重新触发后处理，不递归删除暂存目录或未记录的文件。
- 后处理有操作意图记录，重启后遇到不确定结果不会重复触发 Webhook；提示人工检查。它不是恰好一次投递保证，也不提供自动下载整文件或完整字节上传续传。

- 支持 `alipan.com / aliyundrive.com` 标准分享及 `/s/分享码/folder/目录ID`，提取码优先使用链接中的 `pwd / password`，其次使用搜索结果提取码。
- 递归保留分享内部目录结构，最多 25 层、一万项。源文件必须提供大小；分享缺 SHA1 时从已核验的阿里拥有者副本补齐。已有同名文件只有内容哈希和大小一致才略过；冲突、目录歧义、分页异常时停止，不覆盖。
- 自动转 115 模式在阿里资源盘（缺省回退默认盘）根目录创建独立 `Starflow-transfer-*` 目录，仅将需要转存的文件复制进去。暂存副本平铺在该目录，115 目标保留目录结构。单独阿里保存不调用任何 115 接口，也不触发 115 STRM/媒体库刷新。
- 115 秒传命中后再次读取目标目录，核对名称、大小及 SHA1。115 要求二次证明时，仅读取阿里副本的指定字节区间，每次最多 1 MiB，不下载整文件。
- v4 秒传按参考实现使用毫秒 `t`、同一时间参与 MD5 token、`k_ec` 低 32 位时间及 `topupload=true`。`status=2` 且无错误码时进入目标核验；兼容未返回 `statuscode`、`target` 或 `pickcode` 的成功响应，但显式无效错误码或不一致目标仍拒绝。它不等于已保存或可删除：实际目标名称、大小和 SHA1 核验仍不可省略。
- v4 加密表单同时提交 `userid` 和 `userkey`；`userkey` 不写日志。仅将其用于签名而不放入表单时，当前服务端会返回 `status=4/statuscode=400` 的签名拒绝。
- `115.instant-upload` 记录数值状态码、目标字段是否存在/匹配及证明轮次，不写文件名、SHA1、账号、Cookie、签名、证明密钥、pickcode 或远端原始文案。失败提示区分已知签名/参数/登录错误并保留 `status/statuscode`。2026-09-26 14:26 日志仅能定位到解密后的秒传响应判断，旧日志未保留这些码，不能反推当时的具体服务端原因；本次修正待新包真实账号验证。
- 未命中秒传不会转为普通上传。若任一文件失败、结果不确定或未命中，保留全部本次副本，报告 115 已确认数量及阿里暂存目录，不触发后处理。重试会略过已确认的相同目标，但不会自动清理上次任务的阿里目录。
- 只有全部文件完成，且清理前所有新目标再次核验通过，才逐个检查阿里副本身份并移入回收站。清理失败停止清理并报告警告，不撤销 115 成果，不重复提交删除。HTTP 204 视为已完成，202 异步受理不算删除完成。
- 暂存目录本身保留，可能成为空目录；不会递归删除目录，避免删除用户随后放入的其他文件。
- 单独保存成功后使用阿里 SmartStrm 任务；跨盘完全成功后复用 115 SmartStrm 任务和公共媒体库刷新配置。两种模式都按统一通用名称规则处理本次保存的文件和目录；不遍历重命名目标目录中的无关旧内容。
- 当前执行仍只在应用进程内运行；跨盘任务已有本机持久化恢复记录，没有后台保活或普通上传字节级续传。阿里独立保存不进入跨盘任务记录。Token 失效、容量不足、设备授权及网盘风控都可能导致失败。
- Web 端受到网盘接口 CORS/Cookie 限制，未承诺可用。Android/iOS/桌面扫码与转存仍需真实账号和设备验证。
