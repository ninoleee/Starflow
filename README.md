# Starflow

`Starflow` 是基于 Flutter 的跨平台个人影音入口，仓库包含 `iOS / Android / macOS / Windows / Linux / Web` 工程。不同平台的播放、文件访问和日志能力并不相同，不能把工程存在或主机测试通过等同于设备验收通过。

本文记录用户可见能力和发布规则，包含尚未提交的实现；2026-09-24 整理文档结构，不代表当日重新完成全仓或设备验收。应用版本以 [pubspec.yaml](pubspec.yaml) 为准，各次验证日期见 [主机记录](docs/performance.md)。

十项审查的修复与收尾验证见 [审查收尾记录](docs/reviews/review-closure-2026-09-20.md)。主机回归、原生策略测试和发布预检不替代 Android 6/TV/iOS 真机或真实 NAS/CDN 验收。

凭据安全限制：MPV/iOS 的 NAS/Quark 敏感请求头通过专属安全代理，支持可验证的渐进式媒体及标准 HLS 点播/动态清单（嵌套清单、分片、AES-128 密钥、WebVTT）。低延迟 HLS 兼容为完整分片播放，不承诺低延迟；仅部分分片、增量清单、DRM、DASH、其他播放列表和远程光盘明确报错。普通请求头或无认证清单不强制代理，Android Exo 由自身逐跳数据源保护。详见 [网络边界](docs/development-network.md#网络边界速查)。

## 平台能力

| 平台 | 播放路径 | 主要限制 |
| --- | --- | --- |
| Android / Android TV | 内置 MPV、Media3 ExoPlayer、外部系统播放器 | API 23 起；TV 使用遥控器焦点，原生 TV 播放不启用 PiP |
| iOS / iPadOS | 内置 MPV、AVPlayer 原生容器、系统打开 | 工程最低 iOS 13；AVPlayer 不支持应用双字幕、外挂挂载闭环、字幕偏移和自动跳片头片尾 |
| macOS / Windows / Linux | 内置 MPV、外部系统播放器 | 无 App 内原生容器；macOS 工程最低 10.15；实际格式支持取决于平台依赖和设备 |
| Web | media_kit 的浏览器后端 | 设置枚举沿用 `embeddedMpv`，不是 libmpv；受浏览器编解码和 CORS 限制，无 IO 在线字幕仓库、本地字幕选择或文件日志 |

Android 与 iOS 的本地 `media_kit_libs_*` 覆盖包使用上游 full 二进制；其他桌面平台没有同样的本地覆盖。外部播放器不能稳定回传进度，带受限鉴权头的目标可能改走应用内播放。字幕能力详见专门文档。

## 功能概览

### 性能边界

- 播放启动不再等待后台 NAS 取消收尾；旧播放器释放仍串行。图片下载最多四路，响应头和正文合计 15 秒、32 MiB，隐藏或销毁的未完成图片会释放请求持有权。
- 详情写入按 16ms 窗口合并，评分人数只写受影响分片；NAS 大库分组和本地搜索转到后台 isolate，冷历史/索引读取合并，豆瓣首页不受无关本地索引更新牵连。
- 结构化日志仍启用：普通日志后台/批量写入，关键错误保留可靠 flush；预览后台有界读取。图片磁盘按 30 天与 512 MiB 软上限维护，元数据结果采用 512 项 LRU。
- 上述为工作量与资源边界优化，不是设备速度承诺。逐项实施范围和保留的测量项见 [性能审计与处理状态](docs/reviews/performance-audit-2026-09-20.md)。未降低画质、缓冲或删除播放历史。

### 一致性规则

- 首页、媒体库与详情共用缓存展示规则；海报地址与鉴权头成对选择，公共元数据图片不会继承 NAS 的私有请求头。列表保留已有背景图，详情优先使用缓存补全图；简介保留有效原值，单集详情不继承错误的系列简介。
- 播放进度、跳过设置、字幕偏好与清空记忆串行持久化，清空后不会被旧内存快照恢复。无条目 ID 的资源按保留大小写、标点和路径段的地址识别；读取旧记忆时核对原始目标，避免相近文件名串用进度。
- WebDAV 与夸克共用 NFO 解析和合并，支持 `plot / outline`、分钟 / 秒数时长、首映 / 播出年份及音视频信息。夸克与 115 转存成功后，SmartStrm 失败显示附加警告，不阻断独立的媒体库刷新。
- 删除或修改媒体源时，同时协调夸克、115 的同步删除目录；目录地址对齐包含协议和端口。媒体库主页面与集合页共用删除确认、结果提示和结构化日志。

它把下面几类能力放进同一个应用里：

- 本地媒体源：`Emby`、`飞牛影视`、`WebDAV`、`Quark`
- 内容发现：豆瓣兴趣、推荐、片单、首页轮播
- 聚合搜索：本地资源、`PanSou`、`CloudSaver`
- 搜索页不再显示进入收藏页的图标或按钮；独立收藏页与搜索结果的收藏操作保留
- 添加收藏时会保存匹配到的海报；进入收藏页后，缺失海报的旧收藏会在后台逐条补全并保存，优先复用详情入口已有图片及鉴权头，再使用设置中已启用的元数据源。失败不影响浏览，再次进入可重试；已有海报不会重复匹配或被替换。
- 搜索、收藏和媒体库一级页面不显示左上角返回按钮；详情页进入的搜索页与媒体库二级页面仍保留返回入口
- 内容文字统一为 6 档字号：36（Hero）、24（页面／大标题）、18（区域标题）、16（列表标题）、14（正文）、12（辅助说明）。同一语义在 TV、手机、桌面及 Android 原生选集／播放器控制层使用相同字号；`设置 -> 界面 -> 界面文字大小` 可在 85%–130% 间统一调整全部文字，默认 100%，Android 原生播放器同步应用。布局和焦点仍可按端调整；品牌字标、字幕用户倍率及头像首字母等按尺寸计算的例外不进入通用六档。区域标题到正文为 10dp，上一内容到下一设置标题为 12dp，详情正文模块和设置项之间保持 8dp。不压缩按钮和遥控器焦点区域；搜索结果无标签时不保留标签行空白，字幕排版不变。
- 播放：内置 `MPV`、Android `ExoPlayer（原生）` / iOS `AVPlayer（原生）`、系统播放器
- 入库联动：夸克 / 115 保存、`SmartStrm` Webhook、自动增量刷新索引
- 本地持久化：设置、详情缓存、图片缓存、`WebDAV` 元数据索引
- 诊断运维：结构化本地日志、Android 上次退出信息、日志预览、筛选、清理与跨端导出

## 主导航

路由保留首页、搜索、收藏、媒体库、设置、直播六个一级分支，原有分支索引不变。新配置默认显示五项，已有配置保留菜单选择，可在“设置 -> 界面 -> 菜单栏按钮”启用直播：

- 首页
- 直播
- 搜索
- 媒体库
- 设置

“收藏”可在 `设置 -> 界面 -> 菜单栏按钮` 中启用；菜单可配置可见项和显示顺序，设置入口始终保留且可排序。手机和桌面端支持拖拽或上移 / 下移，TV 使用遥控器操作上移 / 下移按钮；点击保存后统一应用于底部菜单和 TV 侧栏，取消不改变配置。顺序随配置保存、导入和导出，原有配置不强制新增菜单项。搜索页不提供跳转收藏页的按钮，收藏分支复用 `SearchPage(favoritesOnly: true)`。

TV 点击直播菜单是否直接进入播放器，可在“设置 -> 界面 -> 界面效果 -> 导航交互”的“点击直播菜单直接进入播放器”开关中设置，默认开启。开启时恢复上次有效频道，无有效记录时停留频道列表；关闭后只进入频道列表。手机和桌面仍只进入频道列表。选项随应用配置保存、导入和导出。

独立路由页面包括：

- 启动页
- 首页编辑器
  - 手机和桌面端可拖拽调整普通模块顺序；Android TV 使用每个模块的上移 / 下移按钮通过遥控器排序，Hero 固定置顶
- 首页模块完整列表
- 分区内容页
- 详情页
- 人物 / 公司关联影片页
- 元数据索引管理页
- 详情搜索页（带返回入口）
- 独立字幕搜索页（只预填，手动搜索）
- 播放器页

TV 首页编辑的开启／关闭按钮与其他共享文字、图标按钮统一使用低亮度底色和白色焦点描边，开启状态由文字与开关图标表示；手机和桌面端保留原配色。

Hero 自动轮播在 TV 上将焦点交接到新显示的卡片，旧卡片在交接前暂不回收，避免焦点落回下方模块导致轮播停止；用户主动移走焦点仍会暂停轮播。

来源分区新增到首页时统一使用“来源类型 · 分区名”：例如“Emby · 电影”“WebDAV · 电影”“夸克 · 电影”“飞牛 · 电影”。整个来源根只显示来源类型，例如“WebDAV”，不追加“全部内容”。原始来源／分区名称不变，已有和用户自定义的首页标题不自动覆盖。

## 主要能力

### 直播电视

- 独立支持 HTTP/HTTPS M3U/TXT 订阅、本地文件、XMLTV 节目单、频道及分组整理、收藏、多线路与有限重连。手机／电脑使用文件选择，TV 使用同一可信局域网内的手机扫码导入。
- MPV 与 Android 直播 Exo 共用 Flutter 控制层；Exo 使用独立原生视图，不继承点播的 TS/LPCM/PGS、双字幕及自定义音频输出策略。TV 菜单键打开设置，返回先关闭叠层再退出；手机和桌面保留触控入口。
- 首页仅对可见频道做有界首包检测，数值不代表解码可播、持续网速或首帧。单线路开流／无进展等待 5 秒，最多三次自动恢复；后续开流必须等待旧资源取消确认，不承诺原生死锁也能限时释放。
- 直播库、整理偏好和内核选择独立保存，不随应用配置或影视收藏同步；卸载前使用“直播订阅 -> 直播备份与恢复”单独导出。备份未加密，可能含凭据，恢复前需确认。
- 不提供时移、回看、录制、UDP 组播、DRM 或 Emby／飞牛直播库接入。完整功能、界面、存储及兼容限制以 [直播电视](docs/live-tv.md) 为准；真实换台和长播效果需设备验收。

### 媒体源

#### Emby

- 登录并保存会话信息
- 选择分区并读取分区内容
- 本地库缓存按来源与分区分片；读取某个首页或媒体库分区时只加载对应分片
- 不再读取或迁移旧版单文件缓存；升级后如果只有旧缓存，需要重新刷新一次 Emby 媒体库生成当前分片
- 读取媒体详情和播放信息
- 支持电影、剧集、季、集等层级
- 与首页、搜索、详情、播放链路打通

#### 飞牛影视

- 分区新增到首页时，沿用统一的“来源类型 · 分区名”规则，例如“飞牛 · 电影”。
- 在 `设置 -> 内容与来源 -> 媒体源管理 -> 新增媒体源` 中选择“飞牛影视”，填写影视服务地址（例如 `http://192.168.1.100:5666`）、用户名和密码，点击“测试登录”，再读取并选择分区；设置自动保存。
- 直接使用飞牛影视 `/v/api/v1` 接口，不需要 Emby / Jellyfin 转换服务。支持电影、电视剧、季集浏览、同一条目的文件版本选择，以及首页、媒体库、本地搜索和详情资源匹配。
- 媒体库根列表显式限定 `Movie / TV / Directory / Video / LiveChannel` 类型，并开启 `exclude_grouped_video`，避免电视剧的单集绕过剧集层级直接混入媒体库；进入目录浏览时才保留目录内实际条目。
- 复用按来源隔离的媒体服务器分片缓存和后台刷新队列；当前每分区缓存最多 `200` 条，接口按页获取。刷新失败保留上一份缓存；刷新成功后会按飞牛条目 ID 差集清理已删除资源的详情关联、匹配候选、续播记录和剧集播放偏好。媒体库选择“飞牛影视”后可手动点击“更新”。刷新飞牛前会先对当前选中的媒体库根目录调用服务端刷新接口，再读取并保存本地分片；通知失败只记录日志，后续本地读取仍继续。
- 播放开始前重新解析文件与播放地址，本地文件通过飞牛 Range 接口原流播放；服务端返回的 STRM 外链使用独立请求头，不携带 NAS 登录凭据。续播、选集、字幕和音轨沿用应用已有播放器能力。
- 飞牛返回的音轨、内置字幕会按标题、语言、编码和流索引映射到播放器现有“音轨 / 字幕”入口；外挂字幕按 GUID 下载后接入同一字幕选择器。播放器启动时按飞牛 `play/info` 的 `audio_guid / subtitle_guid` 恢复默认轨道，用户已保存的剧集字幕偏好优先。
- 原画音轨菜单保留飞牛已返回但当前流无法匹配或设备不支持的音轨，标为“需服务端转码”；点选后由用户选择服务端实际提供的转码画质，无可用档位则保留当前播放并提示原因。Exo 回写音轨使用包含不支持轨道的完整列表，数量不一致时不按序号猜测 GUID；明确选中的音轨在重新解析时消失会报错，不静默改选其他音轨。
- 媒体流协商携带当前会话摘要和播放器 User-Agent，播放请求沿用协商的 User-Agent（外链优先采用服务端返回的请求头）；业务错误会区分“读取播放信息”和“解析媒体流”，便于从导出日志定位，不记录会话摘要或服务端正文。
- 修改地址、用户名或密码会清除旧会话和分区选择，需要重新测试登录。飞牛登录会话与配置导出均属于敏感信息，应妥善保管配置文件。
- 支持 HTTP / HTTPS 服务器地址直连；尚未接入 FN ID 中继发现、双重验证或直播库。播放器“播放设置 -> 画质”同时读取飞牛 `direct_link_qualities` 直链档位和 `qualities` 服务端转码档位。默认原画直连；主菜单按“原画 / 4K / 1080P / 720P”等分辨率合并，只展示服务端实际返回的档位，保留“流畅”等直链名称。同分辨率默认使用飞牛返回的第一档码率，当前已选的码率优先保留；有重复分辨率时可进入“自定义”选择具体码率，菜单不展示 HLS / 编码等技术标签。选择服务端档位后由 NAS 生成 H264 / AAC 双声道 HLS，能否成功转码取决于 NAS 的权限、硬件和源文件支持。
- MPV 与 Android Exo 均接入上述画质选择、进度回写和外挂字幕解码；画质单档或未返回时仍保留入口和状态提示。切换先解析新地址，解析失败保留当前播放；打开失败尝试恢复旧会话，保留进度、暂停状态和倍速。转码模式从原文件完整列表选择音轨 / 字幕，服务端内置字幕随转码会话选择，关闭字幕会明确传空值；外挂文本字幕继续在客户端下载加载，支持 ZIP 及 UTF-8 / UTF-16 / GBK，位图外挂不作为文本加载。
- 飞牛进度按约 `10s` 节流回写，MPV / Exo 串行发送，暂停、退出、换集及完成时补写；失败不阻断本地续播。新画质就绪后释放旧转码会话，失败、换集、退出及迟到响应也清理对应会话；观看历史不保存活动转码会话，下次打开恢复原画后续播。能力日志只记录画质 / 轨道数量及是否转码，不记录地址、凭据或响应正文。本机验证覆盖 mock HTTP、Flutter 组件和 Android JVM 测试，真实 NAS 转码、长距离拖动及不同设备解码效果仍需联调。

#### WebDAV

- 选择根目录并读取目录结构
- 以“本地索引优先”的方式服务首页、媒体库和详情页
- WebDAV 请求通过共享 HTTP 客户端记录脱敏后的结构化失败日志；不会写入 Cookie、Token、密码或完整查询参数
- 扫描时支持：
  - 目录结构推断
  - 本地 `NFO / poster / fanart / banner / clearlogo / extrafanart`
  - `streamdetails`
  - 文件名和目录名里的 `IMDb ID`
  - 会从标题里的 `{tmdbid-95903}`、`{tvdbid-...}`、`{imdbid-...}`、`{doubanid-...}` 等嵌入式外部 ID 标签中剥离展示标题与搜索词，避免目录标签进入系列名或分组名
  - 会忽略 `分段版 / 特效中字 / 会员版 / 导演剪辑版 / 清晰度 / 音轨 / 字幕` 这类包装目录或版本说明，避免把它们误识别成剧名
  - 同一影片目录下如果同时存在至少两个 `1080P / 4K / 国英双语 / 英语 / 日语 / 韩语 / 高码 / 字幕` 等技术版本目录，且文件没有季集信号，会合并为一个电影卡片；版本目录下再套 `Disc / CD / Remux` 等组织层时，其下所有可播放文件也会归入同一组，详情页仍保留所有可播放版本，不再把技术目录建成剧集
  - 电影根目录下只有一个类似“片名 + 年份 / 语言 / 字幕”的发布包装目录且没有季集信号时，仍使用外层电影目录作为名称，例如 `濑户内海/濑户内海（2016）日语中字` 会索引为电影“濑户内海”
  - 一级影片目录下只有一个视频文件、且没有明确季集信号时，直接按电影入库并使用一级目录名作为卡片标题；公共的 `strm / quark / WebDAV` 目录下其他剧集不会影响这个判断，但如果同一片名目录的祖先存在明确季目录、集号或剧集 NFO，则以上级剧集结构为准，不会把单集误判为电影
  - 媒体目录下的子目录和子文件不会各自创建独立片名；无法识别为版本或季集的子目录，会作为父剧集下的隐式一季
  - 即使子目录自身还包含更深层文件夹，也不会升级为新的剧集根；结构分组会自动剥离来源地址和所选分区对应的根目录，并默认跳过 `movies / strm / quark / WebDAV / NAS` 等常见媒体库或传输层，再使用其后的第一个有效媒体目录作为剧名，不要求用户额外填写过滤关键字。例如 `我的事说来话长/剧版/01.strm` 只生成“我的事说来话长”一个系列，`剧版`作为隐式第 1 季，根目录特别篇归入第 0 季
  - 扫描分类、索引标题、在线搜刮查询和系列分组统一使用同一套路径解析结果；公共根、作品标题和结构分组键不会再由不同阶段分别猜测
  - 最高优先级：开启目录结构推断后，跳过来源/分区根及公共包装层，每个一级媒体目录最多生成一个剧集或电影入口。子目录、局部 NFO 或版本名称不能拆出新的顶层条目；电影资源统一保留在播放版本中，不同实际目录保持独立
  - `movies`、`strm`、`quark`、`WebDAV` 等传输/媒体库目录不会被创建为剧集候选根，公共目录下的剧集证据也不会串到旁边的单文件电影；当前作用域版本为 `webdav-v17`，变化会触发重新索引。《重启人生》这类 `全10集` 发行目录不再误判电影，`重启人生01` 形式的集号归入第 1 季，同集多个版本合并展示，番外仍在同一剧集内
  - 目录结构暂时无法确认是版本或季集时，仍优先使用媒体源下的一级媒体目录作为影片/剧集名称；只有文件直接位于媒体源根目录且没有可用目录名时，才退回文件名。电影目录标题会保留目录中有意义的括号内容（例如年份），但不会因为发布文件名包含目录标题就改用冗长文件名；例如 `两杆大烟枪/Top026.两杆大烟枪...strm` 始终显示为“两杆大烟枪”
  - 索引已经明确为 `movie` 的条目会强制按电影候选匹配在线元数据；目录识别阶段的“偏向剧集”提示不能再把电影误配为同名电视剧。完整增量扫描会更新未手动锁定记录的本地结构，已有海报、评分和在线元数据继续复用；重新搜刮仍需重建索引或显式元数据操作
  - 目录归属、资源角色和季集证据随索引保存，局部刷新不另起作品身份；明确的 episode NFO 季集号优先于文件名与推断值。已知音频及音频 STRM 不进入视频结构推断；花絮不决定主体类型，也不优先成为电影代表资源；同目录平铺的画质版本不自动变成多集
  - 电影多版本详情页会在 Hero 下方直接提供“播放版本”选择控件；“本地资源”只负责来源切换，两者独立显示和保存；版本辅助信息只显示来源、分辨率、首个格式和文件大小；`.strm` 不会误用自身的小文件大小，只有当前选中的版本才会解析真实视频地址、格式和大小，未选版本不发起解析请求；NAS / WebDAV 即使只索引了选中的目录，详情页也会按来源、分区和条目读取该目录范围内已经保存的全部版本；在线匹配统一使用影片根目录名，文件名只用于播放版本展示，明确命中的 NFO / sidecar 标题仍优先
  - 支持单独配置“顶层推断目录”：来源根目录、所选分区根目录和内置常见包装层会自动过滤，无需填写；该设置只用于补充一级媒体目录之前的非标准包装目录。确定一级媒体目录后，更深处同名目录不能重置归属边界；没有有效目录时退回文件名
  - 支持单独配置“剧集只按剧名层级搜刮”：仅在目录结构推断开启时生效；开启后，在线搜刮只使用目录推导出的剧名，不再把季名或集名拼进查询，也不再按单集继续请求剧照
  - 综艺/节目文件名会额外识别 `第X期`，以及 `01 会员版` 这类“集号 + 版本说明”形式
  - 已确定属于同一剧集分组、且同组文件都使用 `1.标题 / 2.标题 / 10.标题` 这类数字前缀时，会保留前缀作为真实集号并按数值排序；缺号不会被压缩重排，普通电影文件名不进入这条规则
  - 父目录的 `E01-16 / EP01-16 / S01E01-E16` 表示多集范围，不作为子文件的统一集号；同组文件按各自编号识别，支持 `16(1080x264).(mp4).strm` 这类集号紧接括号说明的文件名。结构规则升级后，旧索引会在后续刷新时重新识别。
  - 支持 `01-4K.国&粤` 这类“集号 + 清晰度/语言描述”形式，不会把版本描述误识别成标题
  - 文件名轻量媒体信息兜底
- 支持把多集文件聚合为 `剧 -> 季 -> 集`
- 目录名里如果能识别出明确季号，例如 `Season 1`、`S02`、`SE08`、`第2季`、`Stranger.Things.S02.2160p.BluRay.REMUX`、`我的天才女友S3 蓝光版`，会直接把这一层当作季目录
- STRM 穿透后的大小只显示源文件的完整长度，支持直链重定向；获取失败、分片响应未提供总长度或目标为播放列表时不显示大小，不再回退为 STRM 文本、单个分片或播放列表的大小。跨域大小探测不转发 NAS 登录凭据。
- 支持 `SE08.06` 这类“季.集”文件名；母目录一旦被结构推断确定为剧集根，母目录名就是唯一剧名，子目录和文件名只决定季集号与单集标题。`陈鲁豫/陈鲁豫 · 慢谈 #19 .../video.strm`、`罗永浩的十字路口/#004 长标题/同名视频.mp4`，以及名称修正后的 `罗永浩的十字路口/004 长标题/同名视频.mp4` 都会归入母目录的第 1 季并识别对应集号；子目录不会再单独成为剧名或季
- 已确定为剧集母目录后，没有明确季标记且直接只包含一个视频的子目录按单集包装目录处理，多个这类目录统一归入第 1 季；`Season 1 / S01 / 第1季` 等明确季目录不受影响，包含多个视频的未知子目录仍可作为隐式季
- 对 `2.巴以 / 5.美国 / 9.韩国` 这类“数字 + 标题”的专题目录，会额外要求同级里存在多个同类兄弟目录，避免把普通数字目录误判成季
- 对明确剧名下的 `2025 / 2026（4K）` 这类可识别年份分组，会继承上级剧名并保留原目录名作为季名，不再各自生成新的剧集；`4K 12集` 这类只表达画质、版本或总集数而看不出季名的目录只作为包装层，文件自带季号时仍按季号归组，否则进入默认季，不会显示成单独一季；位于媒体源顶层的纯年份目录仍可作为真正剧名
- 一旦当前层被识别为季目录，上一级目录就会作为剧名；像 `怪奇物语/Season 1/Season 2`、`怪奇物语/Stranger.Things.S02.2160p.BluRay.REMUX`、`我的天才女友/我的天才女友S1/S2/S3 蓝光版` 都会合并到同一个剧名下
- 如果路径里已经确认存在显式季目录，即使当前只有一季，也会继续保留“季”这一层，不再直接拍平成集列表
- 支持排除目录关键字
- 媒体库保留“增量更新”和“重建索引”两个入口，不增加刷新模式按钮或常驻扫描统计
- 媒体库手动增量更新先清除所选 WebDAV 来源的持久化目录快照，再按原扫描上限遍历当前所选分区；新文件建立索引，完整扫描同时重算已有条目的本地结构，不重复在线搜刮。不使用活跃目录优先、定时轮换或分批补扫
- 保存后的自动刷新沿用原方式，按选中的媒体源执行一次增量刷新。OpenList / AList 中的 STRM 仍通过其暴露的 WebDAV `/dav/...` 地址读取，不调用管理 API；手动增量更新和重建索引行为保持不变
- 增量更新只对新发现的文件补 sidecar / 在线元数据；已有条目即使元数据缺失也不会在增量阶段重试。命中条数或递归深度上限等不完整扫描会保留未见旧记录及已有分类，包括强制重建；只有完整扫描才据缺失判定删除
- NAS 索引当前使用 v2 数据库，旧索引不读取；重新建立当前索引后按现行电影版本目录规则处理
- 仅在“当前作用域索引为空”时，才会在后台调度一次自动全量重建；读链路本身不再同步等待这次重建
- 支持从媒体库直接删除 `WebDAV` 文件或目录；文件使用真实资源 `URI`，整剧使用结构识别得到的剧名根目录，单季仍使用季目录。只有一季或一个视频子目录时，也不会把整剧删除错误缩小到内部目录；删除目录包含其中的图片、字幕、NFO 等全部内容。WebDAV 删除后重新读取父目录确认目标已消失，读取失败或目标仍存在不视为成功
- 删除成功后，本地只会精确移除当前资源或当前目录作用域相关的索引、详情缓存和匹配关系，不再整源清空
- 网盘与转存里开启“同步删除夸克目录”并选中监听的 `WebDAV` 目录后，只要删除命中了这些目录下的文件或文件夹，就会到当前夸克保存目录里同步删除匹配到的影片或剧集目录
- 支持从详情页进入 `建立/管理索引`，手动修正搜索词、年份和匹配结果
- 目录结构索引会保存根目录、标题、类型、资源角色及季集号的判断依据和规则编号，并区分明确、推断、未知。季集号合并采用明确优先级：人工 > NFO > 文件名 > 目录编号 > 推断 > 未知；同级使用新观察值。NFO 与文件名等编号冲突保留双方值及依据，重复冲突去重，每条资源最多保留 32 条。证据供索引诊断使用，尚无新增可视化面板；不改变一级目录归属、不新增自动改名或网络请求。旧记录兼容读取，完整增量扫描逐步补齐本地结构证据，历史 NFO 原始依据缺失时不会凭空还原。

#### Quark

- 复用 `设置 -> 内容与来源 -> 网盘与转存 -> 夸克云盘` 中保存的全局 `Cookie`
- 选择夸克目录后，可直接把该目录作为本地媒体源接入首页、媒体库、搜索和详情页匹配
- 可继续选择该目录下的子目录作为分区范围
- 索引与在线搜刮链路复用 `WebDAV` 同一套外部存储规则，支持目录结构推断、本地刮削/NFO 和顶层推断目录；结构推断出的剧集会先按剧名匹配并在同剧各集间复用在线结果，可选跳过单集剧照请求
- 开启“剧集复用系列级图片”后，系列匹配年份优先取系列目录，目录没有年份时使用同一个无年份缓存键，不会再因每集上映年份不同重复搜索同一系列；同目录的季/系列 NFO 与通用图片上下文也只解析一次
- 在线元数据查询会在已经单独识别出年份时去掉标题末尾重复年份，例如把 `披荆斩棘2026 + 2026` 规范成查询 `披荆斩棘 + 2026`，避免 WMDB / TMDB 收到重复年份标题
- 详情缓存由 `DetailCacheStore` 按 `16ms` Timer 收集批次后串行落盘，编码后内容未变化时跳过写入；清理会先排完已接受更新，释放时冲刷批次并停止通知。
- 详情页会在真正播放前按需解析夸克直链，并补齐对应请求头

#### 已选分区作用域

- 现有“全部”媒体库和首页“最近新增”按作品聚合，不新增聚合入口：同一电影或整剧只显示一张卡片，分页按作品计数。详情页沿用来源与播放版本切换，各来源自己的季集、画质与剪辑版本仍独立保留；指定来源／分区的列表不混入其他来源。
- 作品优先按同类型的整剧／电影 TMDB 或 IMDb ID 识别；缺少 ID 时要求规范化标题与有效年份一致。ID 冲突、缺年份、类型未知或同名歧义不自动合并，季／单集 ID 不作为整剧 ID。聚合只改变展示，不合并底层文件记录、地址、凭据或删除范围。

`Emby`、`飞牛影视`、`WebDAV` 与 `Quark` 都围绕“已选分区”工作：

- 媒体库只显示已选分区
- 首页编辑器可添加已选分区；NAS / WebDAV 还可直接添加“全部内容”，用同一媒体源根索引展示整个来源
- 本地搜索只搜索已选范围
- 手动匹配与刷新也只在已选范围内执行
- 打开 NAS / WebDAV 子分区只把它作为索引记录过滤条件，不会把子目录临时改成新的索引作用域；因此按来源根建立的索引可正常读取 `quark` 等子树

### 首页与豆瓣

- 首页是模块化装配，不是固定版式
- 支持添加、启用、删除、排序首页模块
- 普通首页模块可独立选择 `竖版海报 / 横版卡片`：竖版保持原有海报流，横版使用 `16:9` 卡片并优先显示背景图，缺失时回退横幅和海报；默认竖版
- Hero 只引用模块内容，不再把被选中的来源模块从下方列表移除；“最近播放”即使排在 Hero 后第一位也会稳定保留
- 支持 `Hero` 模块：
  - 开关
  - 数据来源选择
  - `normal / borderless` 展示方式
  - 高度按首页实际可用空间自适应，普通模式最高 `440dp`、无边框模式最高 `500dp`，为下一模块标题和部分卡片预留空间；加载占位和内容共用高度，简介最多两行，矮窗口或大字体下优先保留片名
  - 是否启用全屏背景图
  - 可切换使用 Logo 形态标题
  - 会根据当前屏幕横竖方向和可用素材自动优先选择横版或竖版图片；横屏优先横版，竖屏优先竖版，只有单张图可用时会直接按海报布局展示
  - `Hero` 当前项、翻页按钮和指示状态都已经改成局部监听，切换时不再带动首页整页重建
  - 首次进入首页时，如果 `Hero` 条目信息不全且还没有已刷新成功或失败的标记，会在后台 best-effort 补一次信息
  - 全屏背景可单独关闭；静态 Hero 与精简 Hero 视觉合并为“简化首页 Hero”开关
  - “设置 → 界面 → 首页设置”提供独立的“Hero 自动轮播”开关，默认关闭，TV 同样支持；开启后每 `6` 秒切换一次并循环，少于两项时不轮播。离开首页、进入后台、滚离顶部、鼠标悬停或触摸按住时暂停；TV 焦点离开当前 Hero 卡（包括进入翻页按钮或菜单）时暂停，返回后重新计时。自动翻页仅在原焦点未改变时将 TV 焦点跟随到可见卡片，不抢走用户移开的焦点
  - 自动轮播与“简化首页 Hero”独立保存；简化开启时直接切图，关闭时使用翻页动画，末项回首项直接切换
  - 无边框轮播卸载旧卡片时，若没有其他可操作焦点，会将焦点补到新卡片；不会覆盖用户已移到菜单或下方内容的焦点
- 除 `Hero` 外，首页普通横向内容流在桌面端也会显示统一的左右切换按钮，便于鼠标快速翻到下一屏。普通海报流的 `12dp` 左右留白放在横向滚动视口外层，焦点回到首张海报时保持 `minScrollExtent = 0`，不会因方向定位把左侧空隙滚掉；详情页横排原本就是这种结构。
- 首页、媒体库、豆瓣模块列表、演员/导演作品等海报统一使用公共组件 `MediaPosterTile`，TV 焦点样式由组件默认值提供：海报图片 `1.6dp` 白色描边、`1.06` 缩放；白边常驻并在未聚焦时透明，不随焦点变化重建或做额外淡入淡出，标题、年份等图片下方文字不参与描边。
- 支持的模块类型：
  - 最近新增
  - 最近播放
  - 指定媒体源分区
  - 豆瓣 `我想看 / 我在看 / 我看过 / 随机想看`
  - 豆瓣个性化推荐
  - 豆瓣片单
  - 豆瓣首页轮播
- 最近播放模块直接读取本地播放记忆：
  - 展示最近播放内容和续播进度
  - 海报右上角以 19 号加粗、无边框、无背景的文字显示记录对应的来源媒体库，并增加双层黑色文字阴影，提升亮色封面上的可读性，便于区分同名内容
  - 电影会显示电影名；剧集会优先显示剧集总名，单集信息继续放在副标题和续播进度里，不再把具体集名当主标题
  - 会优先尝试从本地详情缓存补海报
- 首页会优先合并本地详情缓存，减少重复补元数据
- 首页模块装配当前分成“seed section 构建 + 批量详情缓存合并”两段；普通海报流、最近播放、豆瓣列表和轮播都会复用同一条缓存合并链路；详情缓存更新时只会重做这一层装饰合并，不会让首页整轮重新抓取
- 可配置是否启用首页 `Hero / item` 的运行时局部 overlay 更新；关闭后首页会保持当前静态快照，只在应用启动、保存设置或手动刷新后再重新合并缓存
- 首页 presentation 当前也已经拆层：`home_page.dart` 主要保留 retained async、Hero 选择同步、预取和页面级焦点编排；`home_page_hero.dart` 负责 Hero 视觉/分页/焦点；`home_page_sections.dart` 负责 section slot、背景 shell、carousel、loading/empty 和 view-all 这组通用展示块
- 首页 `Hero`、背景图和海报图会按实际显示尺寸传递 decode 尺寸，移动端 `PageController` 也做了边界稳定化，降低首屏切换和大图解码抖动
- 如果条目已经刮削过或已经关联到本地详情缓存，首页 `Hero` 和各类海报卡片会优先显示刮削/关联后的标题；没有时才回退到原始标题或来源标题

### 详情与元数据

剧照可全屏预览、双指缩放、双击切换 2.5 倍缩放，放大后可拖动；未放大时向下滑动或点击图片外空白关闭。各端支持系统返回，TV 确认键也可关闭预览；预览不设右上角缩放／关闭按钮，加载失败保留重试。桌面横向海报、剧集和剧照列表提供左右翻页按钮。

- 详情页顶部以背景图为主，不再重复展示海报；Logo、标题、评分、导演、演员、技术信息等在同一视觉区域内组织
- 详情页在手机和桌面端使用标准 Hero；TV 固定使用精简详情 Hero
- 详情页首屏优先使用已缓存的海报、背景图和 Logo；本地缓存尚未读好时先显示图片占位，命中后立即展示，不等待 TV 延迟启动或联网补全。缓存未命中或读取失败时回退入口图片，避免先闪旧图再切换缓存图。
- 元数据补全或缓存回写只更新 Hero 图片候选时，详情页会保留上一张已解码背景图直到新图就绪；同一系列来源的元数据刷新也会保留已加载季，不再闪回剧集 loading。
- 详情页会展示背景图、剧照、分集截图、人物头像、公司 Logo 等素材；公司 Logo 位于页面底部，以柔和高对比度背景的单行横向列表展示，可左右滑动浏览，TV 端支持焦点逐项移动与轻微放大提示
- 剧集支持选季、横向浏览集列表和直接播放
- 详情页简介、剧集、剧照、演职员、资源信息与公司等模块的外间距统一为 8dp；剧集横排另保留底部 10dp 焦点空间，因此卡片边界到下一区域为 18dp。模块标题到正文为 10dp，卡片内部间距不受影响。
- 资源信息的来源、链接、时长和状态等单行项统一标签与值的字形起点；链接保留可点击高度，长地址等多行值仍与标签顶部对齐。
- 详情“演职员”中的“导演 / 演员”改用 16dp 分组标题，形成 18（区域）→16（分组）→14（人物姓名）的字号层级；资源字段标签仍保持 12dp。
- 剧集横排顶部留白为 14dp；“继续播放 / 从头播放”按钮到 Hero 底边统一为 8dp。两处间距在 TV、手机和桌面一致，无独立设置。
- 电影和单集详情在 Hero 后直接显示标题时保留 8dp 顶部留白；剧集详情继续使用卡片区块的 14dp，不叠加该间距。
- 剧集卡片简介最多显示三行，图片与简介间距为 8dp、底部内边距为 14dp，卡片高度按三行文字和内边距计算并随字体缩放，不再额外预留一行空白；详情页简介默认六行，长内容可“展开全文 / 收起”，支持 TV 遥控器。清理后没有正文时，卡片回退到集数、时长等信息，详情页显示“暂无简介”。
- 简介中的 HTML 来源链接和对应来源标签不混入正文，正文原有段落、标点保留；没有明确分隔或无法确认是来源标签时保留文字，避免误删剧情。来源链接收纳到简介右侧“更多 → 视频来源”，选择后通过系统打开，失败时显示提示。
- 简介保留原始元数据，仅在展示时清理；来源列表按 URL 去重，只接受合法 HTTP/HTTPS 地址，不自动访问链接。缓存没有来源 URL 时无法直接恢复来源，需要重新读取或手动更新信息。
- 单集卡片的图片区继续直接播放；图片下方的简介区域可进入单集详情页，并查看该集关联资源与详情信息
- 季与单集详情缓存按季号、集号隔离，同剧共用的外部 ID、标题和搜索词不会让不同季集互相覆盖；季集号缺失时仅按具体资源读取，同一集已选播放版本仍可恢复。
- 详情页里的剧集横排和剧照横排在桌面端会显示统一的左右切换按钮，和首页 Hero 的翻页方式保持一致
- `WebDAV` 条目默认优先使用索引期结果，不在详情页重复做在线刮削
- 详情页是否自动匹配本地资源由 `设置 -> 元数据 -> 元数据匹配 -> 自动匹配本地资源` 控制，默认关闭；关闭后只会在手动点击“重新匹配资源”时开始匹配
- 详情页本地资源匹配还可通过 `设置 -> 内容与来源 -> 媒体源管理 -> 详情页匹配来源` 限制到指定来源；未单独勾选时默认使用全部已启用的 `Emby / 飞牛影视 / WebDAV / Quark` 来源，已保存来源失效时也会自动回退到全部已启用来源
- 详情页“匹配本地资源”命中 `WebDAV / NAS` 后，会优先采用匹配到的本地资源信息与图片，再用当前详情页已有元数据做补充
- 如果详情页是从媒体库卡片或指定来源模块点进来的，并且入口本身已经带了来源上下文，资源匹配会先优先看这个入口来源；同来源里已经有命中时，不会先跳去别的来源
- 对非剧集聚合页，如果入口卡片本身就是该来源的已解析资源，详情页会先直接把它当作首选候选；手动重新匹配时也不会先回头重扫这个同来源入口资源
- 剧集海报带有明确来源和条目 ID 时，首屏与季集读取优先使用入口资源，不会先显示其他来源的详情缓存；仍可在“本地资源”中手动切换。剧集重新匹配继续查询入口来源，不因补入候选而跳过。
- 手动匹配过程中会按搜索源并发执行；只要某个源先命中，详情页就会立即展示结果，但不会打断其他源继续搜索
- 手动匹配命中多个本地资源时，会把整组候选资源和当前选中项一起缓存；再次进入详情页时会恢复资源选择器，不再只剩下一个候选
- 如果入口来源当前还没有命中，但入口带了明确来源或分区上下文，详情页会先按这个来源和分区优先搜索，只有同来源未命中时才回退到其他来源
- 如果剧集详情页恢复到的是某个已匹配单集或文件资源，页面仍会保留剧集结构目标并继续显示“剧集”浏览区，不会因为资源已就绪就整页降成单集详情
- 如果候选来自多个来源，资源信息区会显示“本地资源”并只列来源；如果当前来源内存在多个可播放文件，Hero 下方会独立显示“播放版本”。`movie` 和单集等可播放叶子项都使用这套两级选择
- 如果后续删除了其中某个已匹配本地资源，详情缓存只会剔除这一个候选；其他候选会继续保留
- 如果删除的是当前唯一命中的本地资源，详情页会回退到“无/未匹配”的本地资源状态，但保留影片本身的标题、简介、图片和外部 ID 等详情信息
- 退出详情页时，当前页本地资源匹配会话会立即失效；还没启动的后续来源任务不会继续执行，已经返回的结果也不会再回写当前页面
- 详情页、人物作品页和媒体库页在页面失活时，现在会优先取消当前任务，但不再顺手把成功缓存一起失效；返回页面时会优先复用最近一次结果
- 豆瓣等在线详情页如果已经缓存过本地资源匹配结果，再次进入时会优先复用已缓存的资源状态、来源、播放信息和多候选选择状态，不再退回显示“无”或丢失候选列表
- 详情页、首页和媒体库当前都会优先显示已刮削或已关联后的标题；如果缓存或关联结果里已经有更准确的片名/剧名，就不再继续展示原始文件名、目录名或 seed 标题
- 外部 ID 匹配只要任一可用 ID 命中即可成立；详情页文案会按实际命中的 ID 展示，例如 `IMDb ID / TMDB ID`，不再暗示必须双 ID 同时命中
- 详情页资源信息区已删除“刷新字幕 / 外挂字幕选择”；在线字幕搜索统一收口到播放器页与独立字幕搜索页，详情页不再持有字幕搜索状态，也不再把字幕选择写入详情缓存
- 详情页资源信息区可直接切换播放器，使用和设置页一致的选择列表；修改后会同步写回全局默认播放器
- `WMDB / TMDB` 用于补全标题、简介、评分、外部 ID 和 artwork；详情页不主动请求 IMDb。NAS 索引仍支持配置中的 `imdbRatingMatchEnabled`（默认关闭），开启后才查询 IMDb 建议接口与评分数据集
- 详情页评分人数跟随豆瓣评分从条目接口的 `rating.count` 获取，直接显示为“☆31.6万”并写入详情缓存；豆瓣接口失败时保留已有缓存人数，无缓存则隐藏，不使用其他来源回退
- 评分人数会同步写回对应的媒体库条目；NAS / WebDAV / Quark 索引在条目、剧集、季和特殊集合并时保留该字段，Emby / 飞牛分片缓存也会更新。之后从媒体库进入详情时，人数会随 `MediaItem` 直接恢复，不再先显示为空再等豆瓣接口。
- 评分人数与豆瓣评分共用加载时机：缺豆瓣评分或新匹配到豆瓣 ID 时一起获取，手动更新影片信息时一起刷新；已有评分但缺人数不会单独触发预取或反复请求。豆瓣列表响应中的人数直接带入详情；首页、轮播、媒体库缓存回填、资源匹配和剧集变体合并均保留人数，人数变化也会发送评分缓存通知。
- 详情页评分标签会按来源归一去重；`豆瓣 / IMDb / TMDB` 各最多保留一条，避免 seed target、本地详情缓存、手动更新信息或自动补全合并后出现两个同来源评分。评分人数单独保存，不参与同来源评分标签去重
- `TMDB` 当前已接入 `poster / backdrop / still / profile / logo` 等图片字段；人物头像来自 `profile`，详情页公司 Logo 来自 `production_companies.logo_path`，并展示 `TMDB x.x` 评分；`IMDb` 标签来自上游资料或显式启用的 NAS 评分补全。评分数据集共享一次下载和后台索引构建，后续按 ID 二分查询，不逐影片重复解压
- 媒体库或 NAS 索引只有导演、演员姓名而没有头像时，详情页会在已启用 TMDB 且配置 token 的前提下按需补一次人物 `profile`；同名人物会保留现有名单顺序并升级头像，已有详情缓存中的头像也不会再被无头像的姓名占位覆盖
- 本地 sidecar 信息优先级高于在线补全
- 详情页“手动更新信息”会直接重新搜索在线元数据，并用命中结果覆盖当前详情缓存
- 手动索引管理会直接写回本地索引和详情缓存，不只是一次性页面状态；手动点击搜索并应用结果时，不管本地当前是否已有信息，都会强制搜索并直接替换已命中的字段
- 手动索引管理在 `TV` 模式下打开时，会把初始焦点明确放到首屏可见的“自动更新”，避免离屏搜索按钮尚未构建时丢失 autofocus
- 手动索引管理的标题和年份输入框不会再把 TV 软键盘删除键当作返回；删除字符后继续保持输入焦点，遥控器返回键仍可退出键盘
- 点击导演或演员头像可打开人物关联影片页，点击公司 Logo 可打开公司作品页，两者都用与首页一致的海报卡片样式继续浏览；`TV` 焦点白框只套在圆形头像上，不包裹下方姓名，并获得 `1.06` 放大效果。作品卡片右上角会显示题材/类型标签，左下角会按 `豆瓣 -> IMDb -> TMDB` 优先级显示已有评分
- 公司作品页按 `TMDB` 页提供上一页 / 下一页，每次读取电影与剧集的同一页并合并展示；导演 / 演员作品一次获取后在本地排序筛选，并按每页 40 条切页，翻页不重复请求。`TV` 上方分页向下进入作品首行，下方分页向上回到作品末行
- 人物 / 公司关联影片页支持按年份新到旧 / 旧到新排序，也可以按类别筛选，并统一采用上一页 / 下一页；公司作品排序通过 `TMDB sort_by` 从第 1 页重新读取，导演 / 演员作品在本地排序后回到第 1 页
- 图片加载支持候选图回退；`poster / banner / backdrop / extraBackdrop` 其中一张返回 `404` 时会自动尝试下一张，全部候选失败后仍会进行有限重试，不再把首次失败状态保留到应用重启
- 详情页 `TV` 模式会优先把焦点落到主操作按钮；演职员、剧集卡片等横向区域由当前屏幕位置自然寻焦
- 详情页 `TV` 模式下，`Hero` 主操作按钮左右切换会默认留在顶部操作区；剧集浏览区则拆成“季标签一排 / 卡片上半播放区一排 / 卡片下半简介区一排”，左右默认只在当前这一排里移动，不再轻易掉到下方

### 搜索、保存与刷新

- 支持同时搜索：
  - 本地媒体源
  - `PanSou`
  - `CloudSaver`
- 支持多来源并发搜索；每个来源返回后会先批量展示无需验证的结果，夸克与 115 链接则在后台验证完成后逐步补入
- PanSou 同时配置 Token 与完整用户名/密码时，会优先登录取得当前 JWT 再搜索，避免已过期的手动 Token 阻断仍然有效的账号；仅在账号信息不完整时直接使用 Token
- PanSou 聚合查询允许等待最多 `60s`，避免“金色”这类命中较多、服务端聚合较慢的搜索被共享 `20s` 网络上限提前中断；连接测试和登录仍保持 `20s` 快速失败
- 搜索执行范围可通过 `设置 -> 内容与来源 -> 搜索服务管理 -> 搜索来源` 控制；可分别选择本地媒体源和在线搜索服务，未单独勾选时默认使用全部已启用来源，已保存来源失效时会自动回退到全部已启用来源
- 搜索页顶部的来源按钮、最近搜索按钮与媒体库筛选按钮现在统一复用同一套 `chip` 按钮规格；普通端与 `TV` 端都不会再出现底部被裁掉或高度不一致
- 空关键词会直接短路，不再启动整轮搜索
- 多来源结果会先在页面内聚合，再按短节流批量提交 UI；不会再每个来源一返回就触发一次全量排序和整页刷新
- 支持：
  - 同分享去重，未知链接按原链接规则去重
  - 按网盘类型过滤
  - 过滤词
  - 强匹配
  - 标题长度上限

### 播放

- 播放器基于 `media_kit`
- 播放器内核当前支持：
  - 内置 `MPV`
  - Android `ExoPlayer（原生）` / iOS `AVPlayer（原生）`
  - 系统播放器
- 详情页资源信息区也可直接切换播放器内核，这个选择会和设置页里的全局默认播放器保持同步
- `App 内原生播放器` 现已支持 Android / iOS：
  - Android 使用 App 内 `ExoPlayer` 容器页承载播放，设置页和详情页统一显示为 `ExoPlayer（原生）`
  - Android 原生容器使用兼容 `Media3 / AppCompat` 的全屏黑色主题，打开音轨或字幕轨选择弹窗时不会再因主题不兼容而退出
  - `ExoPlayer 音频输出` 在设置 -> 播放中提供 `自动（推荐） / PCM 兼容 / 设备直通`；播放中的“更多操作”也有同样的当前会话选项，点选后会保留进度、暂停状态、倍速、音量，并按轨道身份恢复已选音轨
  - Android TV 在“自动”下遇到 `DDP / E-AC-3` 会启用随 App 打包的 Media3 FFmpeg 音频扩展，本地解码为 PCM；只处理音频，4K / Dolby Vision 视频仍保持原流直放，不要求 Emby 转码
  - FFmpeg 音频扩展始终作为备选注册，按实际音轨 MIME 决定兼容输出，不依赖启动元数据是否完整；已补齐 MPEG Layer I/II/III 所需的 `mp3` decoder。系统音频解码失败时，对库支持的非 DRM 音频最多自动重建一次并切到 FFmpeg，不对网络、视频或已使用 FFmpeg 的解码失败重复尝试。AudioTrack 输出失败另按实际 sink 格式决定是否单次回退 PCM16，不直接强制软解，也不消耗解码回退次数
  - Android 原生播放日志会记录音轨 MIME、编码标记、声道数、采样率、支持状态与选中状态，并标记音频输出模式、PCM 兼容路径和 FFmpeg 解码器状态；字幕轨同样记录 MIME、编码标记、语言、角色、支持状态与选中状态
  - Android 原生播放器会记录视频轨的 MIME、编码、尺寸、色彩信息与支持状态；如果设备不能支持当前视频编码，会自动保留进度并改用 Emby 转码流重新连接，而不是只播放音轨
- Android 原生播放器只对 `/smartstrm_fid/` 中的 MP4/未知格式地址预读最多 `64` 字节：发现标准 MP4 `ftyp` 时直接按 MP4 打开，发现 `#EXTM3U` 时直接按 HLS 打开；已明确为 MKV 等其他容器时不再额外探测。其他 SmartStrm 文件名含 `#` 时仍使用同一轻量探测；标准 `/smartstrm/` 与 `/smartstrm_*/` 路径在首次容器解析错误后都会保留进度并按 HLS 自动重试一次，内置 MPV 和外部播放器不受影响
- Android Exo 的原生 HTTP 数据源不再用固定的 `Starflow` 覆盖播放目标携带的 `User-Agent`，飞牛返回的 115 等直链会保留服务端要求的浏览器 UA；没有目标 UA 时才使用 `Starflow`。
- Android Exo 对 URL 安全校验拒绝立即停止加载重试；原生日志区分地址格式、协议、主机、嵌入凭据、端口及 HTTPS 降级原因，不再统一记为 `Invalid live request`。不放宽跨源凭据或 HTTPS 保护；排障边界见 [开发网络](docs/development-network.md#原生播放请求拒绝诊断2026-09-24)。
- Android 原生媒体请求兼容路径／查询中未转义的空格、竖线、花括号等字符，校验与实际请求使用同一规范化地址；保留已有百分号编码、查询顺序及重复参数，不重编码整条签名链接。主机、嵌入凭据、HTTPS 降级和控制字符仍严格拒绝。
- Android Exo 仅在目标音频编码明确为 `pcm_bluray`（忽略大小写及首尾空白），或对应 TS 流带有效的音轨级 HDMV 注册描述符时，将 stream type `0x80` 按 Blu-ray LPCM 处理；描述符截断或注册信息冲突时不接管。无证据的 `0x80` 保留 Media3 默认 `DC2/H.262` 映射，不根据 `.ts`、`pcm` 或 `lpcm` 猜测。支持单声道、双声道、5.1/7.1（HDMV 布局 1/3/9/11）的 48/96/192 kHz、16/20/24-bit LPCM：读取层完整保留采样，16-bit 输出 PCM16，20/24-bit 输出 PCM24，只转换大小端、移除声道填充并重排声道。其他布局明确失败，不静默卡在准备阶段。无编码元数据且无音轨级 HDMV 描述符的 NAS/STRM 不保证 LPCM 播放，内置 MPV 路径不变。
- Exo 自动/设备直通模式在正常速度与音调下优先使用 Media3 高精度浮点 PCM 输出；LPCM 不属于 Dolby/DTS 压缩直通。PCM 兼容模式、非正常倍速/音调或输出故障回退使用 PCM16 兼容路径；非正常倍速/音调在所有模式下禁用压缩直通。普通 PCM16（如系统解码后的 AAC）倍速原地更新；实际高精度 PCM 或已启用直通需要更换输出路径时，才从当前进度重建并保留音轨、暂停和音量。恢复正常速度后按当前模式恢复高精度及此前因倍速关闭的直通资格，已触发设备故障回退的当前媒体除外。高精度/直通的 AudioTrack 初始化或写入错误最多回退一次，不强制更换解码器策略、不新增服务器转码。日志分别记录 LPCM 源位深、reader 编码、输入格式、AudioTrack 输出格式及倍速是否重建，以 PCM16/PCM24/Float32 等标签辅助阅读；不保证 Android 混音器或最终设备 bit-perfect。
  - 倍速临时降精度按源音轨身份记录，系统解码器返回 1x 时可恢复先前高精度路径，不把普通 PCM16 当成待恢复输出；恢复尝试后清除记录，设备回退与新媒体也清除。FFmpeg AC-3 固定 PCM16，不为启用 float 做无收益重建。输出状态区分待配置输入和仍在活动的 AudioTrack，复用时保留实际输出，释放时清理。
- Android Exo 将 TS 中的 Blu-ray `HDMV/PGS` 位图字幕注册为 Media3 文本轨；reader 跨 PES 聚合显示集，以 `PCS` 的呈现时间为准，不再被后续调色板、对象或 `END` 的时间戳覆盖。新 `PCS` 会丢弃未结束的旧显示集，单个显示集缓存上限为 `4 MiB`，seek 丢弃残片。日志除轨道选择外，还限频记录实际输出的字幕 cue 数、位图数和时间，不记录字幕正文；实际 TV 字幕显示仍需设备验证。
- Android 字幕输出不再让主线程逐条补播已过时的显示消息：每个字幕 renderer 只保留一个待交付的最新状态（包括清屏）。PGS/VobSub/DVB 积压时每轮最多追赶 32 条，resolver 最多读入一条未来样本；未追完不显示中途旧字幕，仍持续推进呈现/清屏时钟。普通文本不启用额外追赶，快进、换轨与停用清理旧状态。PGS 支持有界对象/调色板复用、多对象和裁剪；位图解析增加像素、缓存、解压和循环前进检查，异常字幕清屏而不拖住解复用。详见 [字幕链路](docs/subtitles.md)，实际延迟和显示仍需设备复测。
- Android Exo 的 progressive TS 解析启用 Media3 非 IDR I 帧识别，处理 Blu-ray 开放 GOP 缺少 TS 随机访问标记时续播 / 快进后找不到起播帧的问题；普通 P / B 帧不会被当作关键帧，HLS 与内置 MPV 不变。
- progressive TS 的 PCR 时间戳搜索窗口由默认 `112,800` 字节扩大到 `1,128,000` 字节（约 `1.08 MiB`），用于高码率文件的时长读取和续播 / 快进定位，降低窗口内无 PCR 时直接落到错误估算位置的风险。仍使用 Media3 定位器；既有首尾及定位读取可能增加流量，单次搜索缓冲有上限，不新增独立测速、预检或重试。实际 TV 出帧和连续快进仍需复测。
- 飞牛 STRM 使用服务端解析出的直链和对应请求头，不再因 `pcm_bluray + MPEG-TS` 强制改走 `media/range`。该绕行在此次日志中返回 HTTP 400，不能作为续播兼容方案；本地文件及原本需要 NAS 代理的云盘来源仍按既有规则使用 Range 端点。
  - LPCM 音轨在读取媒体数据前注册；TS 分包末尾不足一个采样帧的字节会缓存到下一片，每个 PES 包重新读取音频头，seek 后丢弃旧残片。复用固定缓冲，按最多 10 ms 或 PES 边界提交 PCM16/PCM24，按累计采样帧推进时间戳；不按每个 TS 分片分配输入/输出数组。
  - Android 原生播放器的选集列表保留当前季全部剧集和真实当前索引，不再裁掉当前集之前的内容；进入原生页或打开选集列表都不会提前解析整季，只有确认选择某一集、上一集、下一集或自动续播时才通过 Flutter 解析该集的播放地址、请求头、格式和文件大小。解析期间当前视频保持播放，成功后才释放旧播放器并切集，失败则提示并停留在当前视频，避免集数多或网络慢时把首次打开拖到十秒以上
  - Android TV 在原生播放器内切换远程剧集时会完整释放旧 Exo、Surface、带宽监听和看门狗，再为新地址创建独立会话；低内存 TV 的新集使用 `48 MB` 目标缓存，并分别积累约 `6s / 12s` 后开始或恢复播放，避免冷连接只缓冲两三秒便进入“播放几秒、停顿十几秒”的循环。首次从详情页打开仍保持 `32 MB / 1.5s / 4s` 快启档

- 下载后的字幕写入 `starflow/online_subtitles/download-*`，不复用过期下载链接。下载上限 `16 MiB / 30s`，ZIP 最多 `256` 项、声明解压总量最多 `64 MiB`、单文件实际输出最多 `16 MiB`，解压校验在后台 isolate 执行。设置中的“单次最多结果数”仅限制搜索结果，不触发预下载
- 字幕缓存统计和清理只覆盖当前 `starflow/online_subtitles/download-*`，下载时回收超过 7 天的条目。MPV 挂载已解码文本，Android 使用独立播放副本，清理下载缓存不影响已经加载的字幕；Android 正常退出时删除播放副本
- MPV 文本字幕沿用 Flutter 字幕层，ASS 特效不会完整保留；PGS/DVD/DVB 等内封位图字幕交给 MPV 原生渲染，双字幕仅接受两条内封文本轨。原生 `sid` 和迟到轨道元数据共同校正渲染类型，`auto` 不直接当作文本轨；渲染、偏好与外挂拒绝共用 codec/image 判断。Android 本地外挂在后台统一处理 UTF-8 / UTF-16 / GBK，零偏移也先解码，迟到任务不会覆盖新播放会话
- 能力边界：在线搜索与外挂加载闭环支持非 Web MPV 和 Android Exo；iOS AVPlayer 当前仅支持系统字幕选轨与记忆，未完成在线外挂挂载闭环；Web 仓库和 Emby 外挂下载接口尚未实现。详见 [字幕链路](docs/subtitles.md)
- `TV` 模式下，外部字幕选择、在线字幕搜索和部分外部跳转都会优先做失败兜底，避免定制系统或无浏览器环境下直接闪退
- Android `TV` 从 `App 内原生播放器` 进入独立字幕搜索页时，会保留当前搜索词、标题和输入框初值，不再空白打开；页面只做预填，不会自动发起搜索
- 内置播放器支持按剧绑定的自动跳过：
  - 自动跳过片头
  - 自动跳过片尾
  - 规则只作用于当前剧，其他剧不受影响
- 内置 `MPV` 按续播点或片头规则直接开流定位，不再从零缓冲再跳转；远程片源因此少一次被丢弃的首段缓冲和重复 Range 请求。片头长度超过本集时长时，取得真实时长后回到开头
- 内置 `MPV` 与 Android ExoPlayer 到达片尾跳过点后直接切下一集，不再先跳到文件尾等待结束事件；最后一集则暂停并记为已看完。自动切入下一集时忽略那一集的旧续播位置，按本剧片头规则从正文开始；显式“从头播放”从零开始，“继续播放”保留续播点（含续播点落在片头内的情况），音频切换和故障恢复保留当前进度。手动拖回片头不会立刻被再次跳走，手动拖入片尾可继续观看片尾。
- 两种播放器都在片尾跳过点（未启用片尾规则时为自然结束点）前 `30s` 内，最多提前解析紧邻下一集一次，只缓存地址和请求头，不创建第二个播放器、不预缓冲视频。结果最多保留 `60s`；命中缓存的切集不再重复解析，暂停期间不发起预解析，手动选集优先。解析 `30s` 超时或失败后保留当前集，可手动重试，不随轮询重复请求；预解析地址在新一集打开时遇到鉴权失效、链接过期这类永久错误，会用原目标重新解析一次。
- MPV 与 Exo 切集接管尚未超时的后台解析时，复用同一个请求，并从首次接管起给予一次完整的 `30s` 前台等待；反复结束事件、暂停/恢复不会延长该请求的期限。超过期限的回调仍会丢弃，失败后不自动循环重试；手动选集可明确重试。
- MPV 自动切集解析期间，暂停、手动跳转、修改跳过规则或进入字幕搜索会取消自动切集意图；迟到的地址只缓存，手动选集可取代尚未提交的自动请求。手机 / 桌面 Adaptive 进度条、滑动、双击、键盘与 TV / 系统媒体 seek 统一在定位前设置手动保护，自动片头和故障恢复定位不清除该保护。切集提交后按原顺序保存并释放旧播放器。
- MPV 在启动阶段首次取得有效时长时校验片头越界，回到零后重新确认播放进展，不等待原无效起点启动超时，也不会再次采用被拒绝的起点。跳过片尾的完成状态独立保存，历史保留真实 position / progress；暂停和退出不撤销完成，手动 seek 或开始新一轮媒体播放才清除，同媒体故障恢复与音频 / 画质重开保留。
- 内置 `MPV` 切集和故障恢复直接复用内存中的剧集队列，不再重新解析整季；冷启动时队列在后台解析，不挡住开播，解析完成后补上选集与上一集/下一集入口
- 内置播放器支持本地续播记忆：
  - 电视剧记忆“播到哪一集 + 当前进度”
  - 电影记忆当前进度
  - 最近播放保留 `20` 条
  - 内置 `MPV`、Android `ExoPlayer（原生）` 与 iOS `AVPlayer（原生）` 在正常播放时约每 `10` 秒保存一次；暂停、返回、切集和关闭时仍立即保存
- Android / iOS 播放记忆统一保存在原生播放器与 Flutter 都能访问的 shared preferences；从原生播放器返回前台后立即刷新“继续播放”和“最近播放”
  - 播放记忆快照在进程内缓存，播放中的定期保存不再每次重读并解码整份历史；应用回到前台时缓存失效，重新读取原生播放器写入的记录
- 首页模块现在也可以直接添加“最近播放”
- 详情页只要已有匹配资源就显示“从头播放”，不要求有播放历史、已加载剧集或已解析播放地址。电影从影片开头、剧集从现有列表最前面一季的最前面可播放剧集开头播放，忽略历史进度和片头跳过，不要求季集编号为 1。“继续播放”仅在有可续播记录时显示，使用记录中的影片 / 剧集和进度。两个入口共用启动锁，解析中保留按钮，失败提示后可重试。续播标记贯穿 `MPV`、Android `ExoPlayer（原生）` 与 iOS `AVPlayer（原生）`
- 详情页存在续播记录时，“继续播放”排在“从头播放”前并作为 TV 默认主焦点，并在操作区上方显示“上次播放：第 X 季 · 第 Y 集 · mm:ss”；单集详情页继续复用已有“播放版本”选择，系列总详情页不额外增加版本选择器
- 详情页已有匹配资源时立即提供“从头播放”；播放历史读取完成后补充“继续播放”与上次进度，历史 readiness 只控制默认首焦点，不阻塞从头播放按钮。两个入口共用启动锁，元数据变化不重建按钮子树。切换资源时采用新目标，不沿用旧资源的播放字段；初始化先恢复缓存与版本选择，再按需刷新和补全详情。
- 系列详情优先加载上次播放所在季，并把对应剧集滚动到可见位置（包含已看完的历史），但 TV 焦点继续留在“继续播放”按钮；无历史或找不到对应季集时保留默认选择。元数据更新不清空季列表，已加载的季在本次页面内复用，手动切季或移开焦点后不会反复自动定位。
- 所有详情页播放入口共用启动锁，连续确认不会重复打开播放器；从播放器返回后保留当前季、剧集横向位置和焦点，只更新播放进度。
- 播放、界面和性能后台不再经过统一中转页；相同用途的界面选项在“界面效果”页合并为“简化界面特效”“减少界面动画”“简化首页 Hero”三个开关
- 内置 `MPV` 不再执行旧式启动测速或 `4s` Range 预检拦截；NAS/Quark 敏感凭据安全代理会额外验证有界媒体前缀，其他路径直接开流。实际打开失败仍按原有总超时和有限重试策略处理，启动与重试决定写入结构化本地日志；Android ExoPlayer 的 SmartStrm 格式探测保持不变
- TV 固定启用轻量焦点、精简详情 Hero 与精简播放界面，并固定关闭自动更新卡片信息；这些平台保护不会在 TV 设置页显示开关
- 内置 `MPV` 当前还额外做了跨平台统一的启动期性能调优：
  - 按本地 / 远程 / 重码率片源动态调整前向缓冲与回看缓冲
  - Android TV 会读取应用内存等级并限制 MPV 缓冲预算；`<=256 MB` 的低内存设备即使播放夸克或开启激进调优，前向缓冲最多 `96 MB`、回看缓冲最多 `16 MB`，避免 `192–256 MB` 缓冲挤压 Flutter 与硬件解码器
  - 默认开启 `demuxer thread`，并关闭 `interpolation / deband / audio-display` 这类非必要处理
  - 远程流会按 `http/https/ftp` 与 `rtsp/rtmp` 两类场景分别调节 `network-timeout`、`cache-on-disk`、`cache-secs` 与预读参数，降低刚进播放时的抖动
  - 已缓存的同主机实测速率达到片源码率 `2.5` 倍且容器风险较低时使用快启档；速度在进程内保留 `10` 分钟，缓存缺失或过期时按片源元数据使用标准/高风险缓冲档，不等待测速。后续速度来自播放中的本地 `cache-speed` 属性，首次播放与切集均不额外发送 Range 检查
  - 实测网速低于片源码率时会提示可能持续缓冲，并停止无意义的硬重建循环，继续让当前连接积累缓冲
  - 只对超时、连接重置、`408 / 425 / 429 / 5xx` 等临时网络错误重建重试；文件不存在、权限、格式/协议不支持与 `400 / 401 / 403 / 404` 会立即返回错误
  - 质量预设保持用户选择，不再因窗口状态、远程流或重片源自动降档
  - 可单独启用更激进的 `MPV fast profile`；重片源 / 高压力场景仍会按运行时策略自动调节
  - `TV` 固定使用精简播放叠层与字幕渲染，降低叠加压力
  - 软解优先且片源较重时，会适度降低解码压力，尽量换取更稳的播放
  - Windows 非全屏轻量叠层已关闭 hover 唤醒，只允许点击显示，并在全屏切换时重置悬浮状态，减少无控件状态下的闪烁
- Android（含 TV）与 iOS 的内置 `MPV` 使用 media-kit 的完整 FFmpeg 解码构建，补齐精简构建缺失的 `MLP / TrueHD` 解码器；TrueHD 在设备本地解码，不依赖系统 codec 初始化，也不改变 ExoPlayer 或外部播放器路径
- `ISO` 片源当前对所有内置 `MPV` 打开路径统一生效：本地 `ISO` 优先走设备模式，远程 `ISO` 自动回退直开，避免错误残留 `dvd-device / bluray-device` 选项
- 重型视频不再自动切换播放器或进入回退路径；仍使用用户选择的播放器，并由 MPV 的片源自适应调优处理缓冲与解码压力
- `App 内原生播放器` 目前专注于性能和稳定播放：
  - Android 支持跟随设置选择 `自动 / 硬解优先 / 软解优先`
  - MPV / Exo 的应用层可靠性规则来自 `config/playback_policy.json`：共享 HTTP 分类、预解析地址刷新范围、缓冲累计进展阈值、状态优先级和自动重建预算；Dart / Kotlin 生成结果由测试校验，不升级播放器依赖。
  - 同一轮播放最多自动重建两次，重建实例不会清空该预算；手动重试或切集重新计数。Exo 启动采用“连续 `30s` 无实际进展失败、总计最多 `60s`”：实际收到网络字节或已缓冲媒体时长累计增长才更新进展时间，单纯正在加载、连接重试、缓存网速及片头/续播起点不算进展。计时每秒检查，首帧前由启动控制器管理，运行期卡顿恢复不同时 seek 或重建；MPV 保留用户设置及片源自适应启动期限，仍以上限 `120s` 封顶。
  - 重试分为地址解析、内核 HTTP 加载、格式回退和开播后的卡顿恢复。Exo 首次开流后的 HTTP 重试、HLS/转码回退、预解析地址失效刷新及播放器重建共用剩余的启动预算，不是每层重新等 `60s`；地址刷新不会暂停计时，超时后忽略迟到结果。首次下一集地址解析仍单独限时，预解析命中则不等待解析；只有用户手动重试或切换到另一集才开启新的启动预算。
  - ExoPlayer 的加载重试按错误分类：鉴权、文件不存在和永久 HTTP 状态立即失败，超时、连接中断、`429` 与 `5xx` 使用最多 `6` 次、`0.5–8s` 的有限退避
  - ExoPlayer 会在同一原生播放会话内保留 `10` 分钟主机带宽样本；下一集若网速达到码率 `2.5` 倍会缩短启动/二次缓冲阈值，低于 `1.25` 倍则提高二次缓冲阈值，目标缓存字节仍受设备内存档位限制
  - ExoPlayer 实测网速低于片源码率时同样保留当前连接继续缓冲，不反复释放重建；两种播放器的主机速度都使用平滑值，避免单次采样抖动触发误判
  - ExoPlayer 与 MPV 都会写入 `playback.performance` 会话摘要，包括地址解析/首帧耗时、缓冲次数/时长、恢复次数、平均/最低/最高速度、码率比、解码器、掉帧以及实际缓冲预算；只在启动关键边界和会话结束记录，不做高频日志
  - iOS 走系统原生解码链路，当前不提供软硬解切换
  - 两端都不提供完整的应用内高级控制项
- 进入播放页后，会额外做一层“后台工作让路”：
  - 路由层会冻结隐藏分支的动画、Hero 和命中测试
  - 首页与详情页优先只消费已有缓存，不再继续发起这一轮补全任务
  - 隐藏页中的网络图片会停止继续解析和拉取
  - 播放页切到后台后，内置 `MPV` 仍保存进度并更新系统播放会话，但会跳过 TV 播放视觉状态刷新，回到前台再按播放器当前状态补齐
- 动画、导航显隐、磨砂效果和轻量播放 UI 由各自设置及 `effective*` 平台规则决定，不再推导或切换隐藏的统一性能档位
- `内置 MPV` 支持跟随设置切换解码模式；`系统播放器` 属于外部应用，解码方式由系统或目标播放器自行决定
- 系统播放器属于外部应用，不能稳定回传播放状态，因此续播记忆仅对内置 `MPV` 和 `App 内原生播放器` 生效
- 自动跳过片头片尾支持内置 `MPV` 与 Android `ExoPlayer（原生）`，上述切集与提前解析规则在两者上保持一致；iOS `AVPlayer（原生）` 与系统播放器不参与。
- 字幕偏移当前支持：
  - 内置 `MPV`
  - Android `App 内原生播放器` 的外挂字幕
  - iOS `App 内原生播放器` 暂不支持
- `TV` 模式下不再常驻显示右上角遥控器操作文案，菜单键仍可直接打开播放设置

### 网络同步

- `设置 -> 数据与维护 -> 网络同步` 支持 WebDAV 手动同步应用配置和现有收藏列表：服务器地址、相对同步目录（默认 `Starflow`）、用户名、密码及开关自动保存到本机，不再单独显示“保存同步设置”按钮；返回前补存最后修改，测试、上传、下载和设置页立即同步会等待本地保存完成。保存配置本身不触发网络同步。
- 同步文件为目录内的 `starflow-sync.json`；上传自动创建同步子目录，服务器地址对应的基础目录需已存在。测试连接保持只读：指定目录返回 404 时进一步检查 WebDAV 基础地址，基础地址可访问则提示“连接成功，同步目录尚未创建”，首次上传或实际写入收藏时才尝试创建；基础地址也返回 404 则明确提示检查 WebDAV 接口地址。测试成功仅代表访问成功，不验证写入权限。
- 每级子目录的创建请求后都会重新验证目标是否为可访问的 WebDAV 目录；`MKCOL` 返回成功或 405 都不能直接跳过验证。目录仍不存在、同名路径是文件或响应无效时停止上传，并区分创建、验证和文件上传阶段及 HTTP 状态。网络同步日志记录各次响应的方法、路径及状态码，不记录认证头或配置正文。
- 配置仍只手动同步。手动上传保留未勾选的远端内容，手动下载仅覆盖勾选的本机内容，两个方向均先确认。
- 新增“收藏自动同步”开关（默认关闭，确认后自动保存生效）：只双向合并收藏，不上传或应用配置。每台设备在相同 WebDAV 目录中维护自己的 `starflow-favorites-<设备ID>.json`，不会互相覆盖，也不按同步次数累积快照。设备 ID 自动保存在本机，不随配置导出。不会自动导入手动备份 `starflow-sync.json`，需要其中的收藏时可在开启自动同步前手动下载。
- 收藏设备文件只同步标题、资源链接与提取码、收藏文件夹、来源及媒体标识、必要的详情／播放入口和增删版本记录；不传输海报地址、图片请求头、图片列表、简介、评分和演职员等展示缓存，播放鉴权头及影响播放／字幕匹配的容器、编码和数值参数仍保留。本机已有展示数据不会因同步丢失，新设备缺图沿用原有后台补图流程，缺失简介和标签不渲染空白控件；仅补图不改变同步版本，也不会在下次同步重复上传。手动配置备份格式不变。
- App 启动不进行收藏同步。开启自动同步后，每次 App 运行中只有第一次进入收藏页会自动同步；离开再进入、页面重建、切回前台或保存连接设置都不会重置这次机会，首次未开启或同步失败也不因重新进入而补发。新增或删除收藏（含清空）仍触发自动同步，右上角手动同步不受首次限制。不做定时巡检、延迟防抖或失败定时重试；海报补全及远端合并不会额外触发。失败保留本地修改，等待增删事件或手动同步。后台不发起新任务。
- 收藏页右上角始终显示手动同步图标，同步中禁用重复点击，完成后显示结果；TV 模式下忙碌时仍可聚焦，避免确认后焦点丢失，方向键可继续移动到收藏列表，完成或失败不抢回已移开的焦点。自动同步关闭时仍可使用已保存的 WebDAV 连接手动合并收藏，未配置会提示先保存地址和账号。设置页保留同步状态和本次运行上次成功时间。
- 收藏增删记录与列表一起持久化，取消收藏及清空收藏保留删除记录，避免离线设备或海报补全恢复旧收藏；明确重新收藏可以恢复。多端并发元数据修改按版本确定性选取，同一收藏成员版本冲突时删除优先。活跃收藏最多 200 条，合并超限会停止并提示，不截断条目；删除记录暂不自动清理。
- 自动同步开启时，在本地存储页清理包含收藏的数据会先确认“清空收藏并同步删除”，确认后删除将传播到其他设备，不是仅释放本机缓存。
- 自动模式下手动上传／下载不操作收藏。收藏同步列出各设备文件，读取并合并全部收藏和删除记录；本设备文件需要更新时才上传，随后按关键字段和版本记录读回验证，通过后才显示成功。关键内容没有变化时不重复写入；失败保留本地修改，不安排定时重试。
- 收藏同步不依赖 ETag、不伪造版本、不删除远端文件，也不新增兼容开关。通过不同设备写不同路径避免跨设备文件覆盖，本机请求串行执行；服务器仍需可靠保存文件并最终提供正确的目录列表及正文。其他设备的变更在下次有效同步触发时合并，不是实时推送。清空收藏保留本机设备 ID，卸载或清除应用数据后可能生成新 ID；旧设备文件及删除记录暂不自动清理，避免离线收藏复活。不要把整份应用私有数据克隆给另一台同时使用的设备。日志记录触发来源、设备数量、设备文件写入及实际验证结果。
- 网络同步地址、目录、用户名、密码及同步开关以 `webDavSync` 保存到应用配置，包含在 JSON 导出、文件／Web／TV 导入导出和手动配置备份中。导入按当前完整配置直接替换；收藏自动同步文件仍不包含应用配置。配置 JSON 含明文同步密码，请作为私密备份保管，使用 HTTPS 和可信私有目录；当前不使用系统钥匙串。

## TV 模式

当前 `TV` 模式已经单独做了适配，不只是把触屏页面直接搬到电视上：

- 返回、确认和菜单键按配对松开执行一次，消费长按重复；焦点移走或切后台取消待执行动作。原生播放／暂停保持即时响应，方向导航和长按快进不受影响。普通禁用控件退出寻焦，忙碌操作及边界分页可显式保焦；详细页面规则统一见 [TV 焦点清单](docs/tv-focus.md)。
- 应用内弹窗主按钮使用低亮度底色和白色焦点框，取消／关闭弱化，危险操作保留警示色；重建索引确认默认聚焦取消。此规则不改变普通页面、非 TV 或 Android 原生系统弹窗。
- 左侧主导航为垂直居中的低存在感窄栏图标菜单。关闭自动隐藏时使用 `Row` 并排布局，菜单常驻并占用左侧 `48dp`，面板颜色跟随主题 `surface`，与使用 `AppPageBackground` 的内容页背景一致；开启自动隐藏时使用 `Stack` 覆盖层，内容区保持全宽，侧栏只做滑入/淡出，不会在显示或隐藏时重新排版首页与媒体库网格。自动隐藏面板在启用透明磨砂时使用 `BackdropFilter`，关闭特效时使用半透明纯色。栏宽 `48dp`、按钮 `44×44dp`、图标 `24dp`，四周外边距为 `0`（不含系统安全区）。按钮统一 `18dp` 圆角；常驻 `Row` 面板保持直角，自动隐藏 `Stack` 面板使用 `28dp` 圆角。未选中项更弱化、聚焦描边更细，避免在内容页抢视线。支持菜单键随时把焦点拉回侧栏；可按设置决定是否在焦点离开后自动隐藏，隐藏动画不会继续保留不可见的焦点候选
- TV 菜单聚焦标签显示在按钮右侧 `12dp`，文字置于半透明强调色胶囊背景内，文字使用对应强调色的对比色，不带描边，不增加 `48dp` 菜单栏占位；浮层按标签尺寸布局，避免标签错位或旧版标签背景被撑成全屏胶囊。移开焦点后标签消失
- 一级页面到达左侧焦点边界后，按一次左键即可回到当前页面对应的菜单项；菜单常驻或自动隐藏时都不需要再按上下键触发。菜单聚焦请求会主动安排更新帧，页面静止时也能完成切换。
- 应用失活时立即执行页面失活处理，不等待后台可能停止的绘制帧；恢复前台后再按页面可见性激活。首页与设置页缺失焦点恢复会主动安排更新帧，不抢已有可操作焦点；首页寻焦滚动到边界后也能结束等待并执行原有回退，不依赖额外按键。
- 设置页在 TV 识别结果延迟返回后会补做首焦点检查，只在页面可见且没有可操作焦点时聚焦页头。信息管理页的“自动更新”在忙碌时保留 TV 焦点但不接受重复确认，方向键仍可离开，更新成功或失败后不抢回焦点；非 TV 触摸禁用行为不变。
- 日志页在设置保存期间保留遥控器焦点并忽略重复确认；预览刷新按日志身份保焦，首条上移回“刷新”、末条下移及左右键停留；电视导出页首焦点落导出入口，二维码弹窗首焦点落“关闭服务”，关闭后回导出入口；清理确认默认取消。
- 页面内常用操作统一支持遥控器焦点高亮
- 季标签按文字、勾选图标和对称内边距自然排宽，季选择区域高度保持不变。仅在打开详情页、季标签首次显示时，按实际位置将当前季尽量居中一次，首尾标签保持在滚动边界内完整显示；之后切换季、手动滚动、横竖屏变化或从播放器返回都不再自动居中，不移动整页也不抢焦点。
- 详情页已显示的剧集区域在进入播放页后保持挂载，返回时不再因路由动画开关而移除、重建；后台抓取仍受页面可见状态限制。
- 详情页播放按钮直接复用共享播放记录快照，资源信息补全时不再重复等待续播查询；“剧集”标题在列表首次加载、成功和失败之间保持同一组件层级。
- “从头播放”只由匹配资源状态决定显示，历史加载中、为空或读取失败都不隐藏按钮；点击后才解析播放起点。历史就绪后补充“继续播放”和上次播放位置，操作行使用稳定 key 保留按钮实例。自动首焦点仍等待记录就绪后确定。
- 剧集浏览在本地来源恢复后即可加载，不等待在线评分和简介刷新；播放记录与季列表并行读取。单季不保留季选择条空位，多季才显示季选择条，错误提示按内容高度显示；列表完成只更新剧集区域，播放进度变化只更新对应角标。
- 长页面的普通方向寻焦使用 Flutter 默认可见性滚动；首页恢复与选集等显式路径可居中，其他控件不统一强制居中
- 顶部主入口、横向列表和底部内容区之间已经补齐统一的上下方向焦点边界；往上可回到页头，往下可继续进入下一个模块
- 首页存在 Hero 时，从首个普通模块按上会明确回到 Hero 当前海报；不会落到 Hero 内部的中间焦点节点，也不会误聚焦不可用的左右翻页按钮
- 首页、搜索结果、媒体库网格、详情页人物 / 剧集卡片的普通方向键使用 Flutter 默认寻焦
- TV 页面会通过统一的安全方向寻焦策略忽略动态刷新期间尚未完成布局的候选节点，避免首页模块异步插入、缓存合并或滚动时把 `RenderBox was not laid out` 写入全局错误日志
- 应用默认方向键 Action 同样只捕获 `RenderBox was not laid out`：异步控件尚未布局时忽略当前按键并保留焦点，不重试、不改顺序，也不主动切换目标；对应 `warning` 每 `5` 秒最多记录一次
- 页面边界、嵌套焦点组与侧栏横向移动共用上述异常保护；未布局导致的寻焦中断视为本次按键已处理，不会误判为左侧边界而跳回菜单。TV 文本弹窗退出输入状态时直接聚焦已挂载且可用的操作按钮，再次返回才关闭弹窗
- 来源多选、播放器字幕/音轨/倍速/循环选项、字幕偏移和片头片尾弹窗均提供明确首焦点；多选为空时落到取消，删除媒体源/搜索服务/夸克目录及覆盖配置确认框默认聚焦取消。夸克目录选择页将首焦点放在始终可用的“选择”，加载中、空目录和失败时也可确认当前目录或返回
- 首页 Hero 只有一项、处在翻页边界或刷新后翻页按钮变为不可用时，不再把焦点留给未挂载或禁用按钮；按左仍可正常回到侧栏，列表重排也会保留当前资源
- TV 返回首页以及首页模块从加载中变为完成时各检查一次当前焦点；如果没有可操作焦点就恢复到当前侧栏首页入口，已有页面或侧栏焦点时不抢焦点
- 从首页编辑器返回或模块顺序变化时，旧编辑器焦点不会再被误判为首页有效焦点；Hero 已可用时优先恢复到当前 Hero 卡，普通内容尚未就绪时才回侧栏
- 首页首焦点优先选择已经可见的 Hero；Hero 来源仍在加载时不会先用“最近播放”等普通模块垫底，而是在 Hero 到齐后落到当前 Hero 卡。单击侧栏首页触发的导航重置也只把用户焦点拉回 Hero，不额外抢普通模块焦点。Hero 未启用或为空时继续按首个实际有卡片的模块定位，跳过连续空模块；普通模块晚加载不会抢走用户当前焦点
- 首页按来源和资源 ID 为每张海报、轮播卡及“查看全部”入口保留稳定焦点节点；资源重排、标题补全不会换焦点，刷新移除当前目标时才恢复到仍存在的内容
- 首页编辑器为模块开关和来源保留稳定焦点；重排、删除、移动按钮到达边界以及关闭底部菜单或编辑对话框后，焦点会回到同一模块或先前操作位置
- TV 主界面按返回会先清理当前焦点作用域历史，并把焦点放到当前页面对应的侧栏入口；只有焦点已经在该入口时再次返回，才显示退出确认
- Android / TV 确认退出后会先释放播放器、媒体通知和画中画状态；原生层等待确认键释放并吞掉尾部按键，再移除本应用全部 task，未收到按键抬起事件时也有超时兜底。退出后的短保护窗口还会拒绝电视启动器因按键穿透发起的重复启动
- 焦点日志只记录首页确实执行缺焦恢复、返回键确实清理并移动焦点，以及方向键因未布局候选被忽略；不记录普通按键或每次焦点变化
- NAS / WebDAV 的 STRM 直链会把文件路径中的裸 `#` 编码为 `%23`，避免 SmartStrm 等服务把 `#01 / #23` 误当 URL fragment 而截断真实媒体路径
- 媒体库首页只保留顶部筛选项作为首焦点，异步出现的合集和首张海报不再同时申请 `autofocus`
- 首页和媒体库选择 NAS / WebDAV 根目录下的子分区时，会在原来源索引作用域内按资源 URI 的完整目录段读取该子树；例如 `quark` 不会因记录归属扫描根而显示为空，也不会混入 `quark-old / 115` 等相邻目录。首页编辑器还可选择“全部内容”直接展示整个 NAS / WebDAV 根
- 单击导航栏“首页”会执行安全的软恢复：回到页面顶部、取消页面级预取与媒体库后台刷新，并解除首页/元数据调度器自己的批次等待；已开始的任务和并发计数不会被强制清零，双击首页仍执行刷新
- `TV` 退出确认框显示期间只暂停新的后台元数据预取；取消退出后立即恢复，不会把一次误按返回当成清理或重置任务
- 应用进入后台时会暂停首页加载与全部元数据任务的新准入；回到前台后先等待首帧，再经过 `400ms` 静默期逐步恢复，已经开始的请求不会被中断
- 系统报告低内存时会写入 `app.memory-pressure`，暂停新后台任务 `2s` 并取消媒体库后台刷新；Flutter 自身负责清理内存图片缓存，Starflow 不会清空持久化图片、详情缓存或播放器状态
- 豆瓣、WMDB、TMDB 等主机熔断后，双击首页、下拉刷新、详情手动更新、信息管理搜索和媒体库手动刷新会各允许一次半开探测；同一主机不会并行放行多个探测，失败后继续熔断，成功后恢复正常
- 首页和元数据调度队列等待超过 `5s`、TV 图片请求等待超过 `4s` 时会分别记录活动数、排队数、并发上限及最老等待时间；这些只是诊断日志，不新增设置，也不会因为等待超时强制释放有效任务
- TV 仅在应用恢复、主导航切换或弹窗关闭后的边界检查空焦点；如果首帧后仍只有路由焦点域而没有可操作控件，才回到当前导航项，已有页面首焦点不会被覆盖
- 文本编辑弹窗是唯一的输入局部例外：上下键会离开输入框并进入前后操作按钮，避免方向键被光标编辑吞掉后无法退出
- 页面不再叠加空的焦点记忆作用域、额外固定顺序或反向候选拦截；焦点视觉态使用轻量的局部高亮，海报卡的 `outline only` 模式不会再叠加浮动效果
- 详情页 `Hero` 主操作和剧集浏览区额外补了显式方向链：左右优先留在同一水平带里，剧集卡左右切换默认走上半播放区，按下才进入下半详情区
- 详情页信息管理页进入后会主动接管旧页面遗留焦点，并将焦点落到首屏“自动更新”按钮
- 搜索页支持最近搜索词和来源 tab 多选记忆；设置只决定搜索页展示哪些来源 tab，实际请求以搜索页当前选中的 tab 为准，“全部”会搜索所有当前可见来源；从详情页进入时会先恢复该选择，再用预填片名自动搜索
- 媒体库分页按钮支持 `TV` 焦点操作，列表返回后尽量回到上次停留位置
- `TV` 端会强制关闭首页 `Hero`、首页卡片和媒体库当前页卡片的运行时局部 overlay 更新，避免后台缓存变更在滚动或焦点移动时继续唤醒局部重算
- 详情页的大季集数保持横向惰性构建；单集图片共用 `TV` 图片并发保护。播放器覆盖详情页时保留已挂载剧集区和滚动位置，暂停 provider 监听与隐藏图片排队；详情路由销毁时再释放组件
- `TV` 全局图片加载门的四个 permit 改为由 gate 自身持有并带 `8s` 自恢复租约；即使隐藏组件没有及时完成 rebuild，也不会永久占住所有名额导致 Hero 和整排海报同时空白
- TV 图片所在页面关闭 `TickerMode` 时，未完成的加载立即释放名额并取消排队，重新显示后再申请；已经解码的图片保持挂载。主图切换备用图时隔离旧 Future 的错误和结果，避免豆瓣返回 `418` 后误跳过仍在加载的备用图；租约只作为兜底，已发出的网络请求仍按原超时收尾。
- 飞牛季集读取失败现在区分“读取父条目 / 读取季列表 / 读取剧集列表”。读取条目的 `-6 / Not Found` 提示更新媒体库后重新打开，并只清除对应条目的详情关联；不自动重试或判定为登录过期。删除后重新入库的同名剧集不会通过详情缓存恢复成旧 GUID，刷新通知失败仍继续本地缓存刷新。空标题的季 / 集按文件名或季集编号显示，未分季使用“未分季”，不再直接丢弃。
- 播放器保留菜单键直达播放设置等 `TV` 快捷操作，但不再依赖常驻文字提示
- `TV` 播放器可按上临时呼出片名 / 进度叠层，按下或菜单键直达更多播放设置
- 设置编辑页里的文本输入会改走“选择条目 -> 弹窗编辑”流程；弹窗输入框支持上下键退出，避免遥控器焦点被软键盘困住
- 配置管理使用应用内局域网传输，不再依赖系统目录 / 文件选择器
- 配置和日志的 TV 手机传输页都会显示完整地址及二维码；手机与电视处于同一局域网时可直接扫码打开
- 多数设置编辑页现在共用同一种标题栏、自动保存、危险操作按钮和选择条目样式，遥控器在不同设置页之间切换时的学习成本更低

## 本地数据

设置、播放记忆、搜索偏好和详情缓存使用本地偏好存储；WebDAV／Quark 索引和直播库使用独立 Sembast 数据库，图片使用持久化缓存，下载字幕使用受生命周期管理的临时目录。清理入口在“设置 -> 数据与维护 -> 本地存储”，清理收藏可能传播同步删除，操作前需确认。

具体存储键、分片、缓存身份和释放规则统一见 [架构的本地持久化](docs/architecture.md#12-本地持久化) 与 [字幕链路](docs/subtitles.md)。结构化本地日志、Android 原生退出捕获、预览、筛选、清理和导出保持启用；旧 trace 静音不表示应用关闭日志。

## 环境要求

- TV 发布固定 Flutter `3.38.10`，由 `.fvmrc` 与 `config/android_release.json` 记录；其他平台也需可解析当前锁定依赖的 SDK。`pubspec.yaml` 的宽泛 Dart 下限不表示任意 Dart 3.4 环境都能构建，当前锁定依赖至少需要 Dart 3.10.3 / Flutter 3.38.4
- TV 脚本优先使用 `STARFLOW_FLUTTER_SDK`，其次项目 `.fvm/flutter_sdk`，最后 PATH；Flutter 与 Dart 必须来自同一 SDK。预检核对 framework/engine revision、既有签名私钥和检查工具，失败发生在版本递增前；PowerShell 同样通过该环境变量选择 SDK。
- 日常依赖解析、测试和分析也统一使用项目 `.fvm/flutter_sdk`，VS Code 已配置该路径。切换 SDK 后先用同一 SDK 执行 `flutter pub get`，不要在同一工作目录并发运行不同版本 Flutter；否则 `.dart_tool/package_config.json` 的 framework 与执行引擎可能混用。macOS 本机终端配置及检查步骤见 [开发环境](docs/development-network.md#flutter-sdk-一致性)。
- Android：JDK 17、Android SDK（`compileSdk 36 / targetSdk 35 / minSdk 23`），NDK 版本由 Flutter 提供
- iOS / macOS：macOS 上的 Xcode 与 CocoaPods
- Windows：Flutter Windows 工具链；安装器另需 Inno Setup 6
- Linux：Flutter Linux 桌面工具链；PowerShell 脚本不能直接作为 Bash 脚本执行

当前 TV 打包规则：

- 默认输出到桌面
- 默认只生成单个 APK
- Windows 与 macOS TV 发布脚本均固定使用 `--target-platform android-arm,android-arm64`，单个 APK 仅包含 ARM 32 位（`armeabi-v7a`）与 ARM64（`arm64-v8a`），不再构建或打包 `x86_64`
- 不传 `SettingsJsonPath` 时不会嵌入配置
- Bash 预设只在显式提供第一个设置 JSON 路径参数时嵌入配置；不得自行搜集用户配置打入包
- 传入 `SettingsJsonPath` 时会临时写入 `assets/bootstrap/embedded_settings.json`；成功或失败后均清理临时配置，并恢复构建前已有的文件。普通包构建期间排除该文件，不因工作区残留而嵌入配置
- 内部构建命令会默认附带 `--android-skip-build-dependency-validation`，继续保留 `Android 6.0 / API 23` 的老电视兼容目标
- 文件名为：
  - `starflow-tv-主版本.月份.序号.apk`
  - `starflow-tv-config-主版本.月份.序号.apk`
- 内部版本号会自动递增：
  - 第一段主版本号保留手动控制
  - 第二段是月份
  - 第三段是当月递增序号
  - 每个月第一次打包时第三段自动归 `0`
- 当前显示版本号只保留标准三段式 `主版本.月份.序号`
- Android 数字 `versionCode` 由 `config/release_version.json` 的基值、纪元和进位范围计算，Gradle 与 Dart 版本工具共用该策略；它与显示版本不同。超出策略范围会失败，不静默回退到版本码 1
- Android TV 保留 `Android 6.0 / API 23` 目标；发布预检拒绝非锁定 SDK，产物检查拒绝原生库高于 API 23 的构建标记或较新系统强符号依赖。2026-09-20 主机核验 Flutter 3.38.10 官方 ARM32 / ARM64 引擎的构建 API 分别为 21 / 22；这不是 Android 6 真机启动或完整依赖兼容性验收
- Release APK 当前启用了 `v1 + v2` 签名，兼容老一些的电视安装器
- Release 必须显式配置忽略提交的 `android/key.properties`，格式见 `android/key.properties.example`，不再自动回退新生成的 debug key。当前安装基线历史上使用 Android Debug 证书，必须沿用并备份这把旧 key；`config/android_release.json` 固定其 SHA-256 指纹，换机需要恢复同一签名。不能随意换证书后宣称可覆盖升级
- `-SkipBuild` 在版本递增和配置处理之前直接拒绝。两个 TV 发布脚本交付前均校验 APK 内部版本、包名、minSdk、双 ARM ABI、签名、原生库和内嵌配置字节，不会把旧配置包误命名为普通新包
- 发布脚本会修改 `pubspec.yaml`；失败不会自动回滚版本。TV 与 iOS 共用工作区时串行构建，默认保留 Flutter、Android 和 iOS 的增量构建缓存并跳过依赖解析；组合脚本让 TV 复用本次 iOS 版本，不重复递增。设置 `STARFLOW_CLEAN_BUILD=1` 才会在对应平台构建前执行 `flutter clean`，设置 `STARFLOW_FORCE_PUB_GET=1` 才会让构建重新解析依赖

当前 iOS 打包规则：

- 默认输出到 iCloud Drive 的 `Installers` 文件夹；只有显式选择相同目录时才与 TV APK 放在一起，普通 TV 交付默认仍是桌面
- 内部版本号沿用三段式 `主版本.月份.序号` 自动递增规则
- 内部构建命令固定使用 `flutter build ios --release --no-codesign`
- 不再尝试生成签名版；输出文件名为 `starflow_v主版本.月份.序号_unsigned.ipa`
- 未签名 IPA 不能直接作为已签名安装包安装，后续签名与设备部署由相应工具链完成
- 构建前清理误缓存的 simulator Native Assets，打包前验证 framework 不含 simulator / x86_64 切片；入口为 `prepare_ios_device_build.sh` 与 `verify_ios_device_frameworks.sh`
- 明确需要固定本批版本时可使用 `STARFLOW_RELEASE_VERSION=主版本.月份.序号`，其他发布预设通过共享工具使用同一变量

当前 Windows 安装器打包规则：

- 默认输出到桌面
- 默认只生成单个安装器 `.exe`
- 内部会先执行 `flutter build windows`
- 然后调用 Inno Setup 生成安装器
- 当前会优先在这些位置查找 `ISCC.exe`：
  - `E:\Program Files (x86)\Inno Setup 6\ISCC.exe`
  - `E:\Program Files\Inno Setup 6\ISCC.exe`
  - `C:\Program Files (x86)\Inno Setup 6\ISCC.exe`
  - `C:\Program Files\Inno Setup 6\ISCC.exe`
- 当前安装器文件名为：
  - `starflow-windows-版本号-setup.exe`
- Windows 脚本通过共享 Dart 工具按月递增，也支持显式固定批次版本；PowerShell 预设现在要求 `dart` 可从 PATH 调用

## 品牌资源

Flutter 启动页会等待全部已启用首页模块的首次数据加载结束（含缓存内容整理）再进入首页，最多等待 5 秒。单模块失败不阻塞其他模块；超时后进入首页并继续后台加载。海报图片解码、完整片库扫描不属于此等待范围，启动自动刷新和临时崩溃恢复策略保持不变。

从 Flutter `BootstrapController.start()` 开始计时，整个启动准备流程另有 `10 秒` 总时长兜底，覆盖配置读取、媒体源缓存协调和首页等待；配置读取仍保留 `3 秒`、首页模块等待仍保留 `5 秒` 的阶段上限，阶段切换不会重置总计时。提前完成立即进入首页，总超时也会放行；已经开始的操作允许后台收尾，迟到结果不回写启动状态、不继续触发后续启动阶段。此计时不包含 Flutter 启动流程开始前的原生初始化，且无法打断主线程同步阻塞。

安装后的应用显示名称及窗口标题统一为 `Starflow`（首字母大写）；应用 ID、包名及 TV APK 文件命名规则保持不变。

Android（含 Android 12+ 系统启动屏）、iOS 原生启动页与 Flutter 启动首屏统一使用 `#121212` 中性深灰背景，不使用彩色渐变或光晕。启动首屏 Logo 保持原色且无额外底板、阴影，字标使用白色与浅灰色。

原生启动阶段仅显示纯色背景，不展示 Logo；Android 12+ 使用透明启动图标，iOS 启动 storyboard 不加载图片。Logo 和字标只在 Flutter `BootstrapPage` 静态展示，初始化流程保持不变。导出脚本仍保留原生启动图片资源，但当前原生布局不引用它们。

Flutter 启动 Logo 和字标始终静态显示，保持固定大小、位置与不透明度，不执行淡入、缩放、位移或循环动画，也不随初始化进度或“减少动画”设置变化。初始化完成后主动请求一帧执行首页跳转，不依赖动画或用户操作触发刷新。
